אתם משתמשים ב-API כל היום בלי לשים לב. כשאפליקציית מזג אוויר מציגה את התחזית למחר, היא לא המציאה את המספרים: היא שאלה שרת (server) איפשהו, השרת ענה, והאפליקציה הציגה את התשובה. בקורס הזה תלמדו להיות האפליקציה: לשלוח בקשות, לקרוא תגובות ולטפל במצבים שבהם משהו משתבש.

## מהו API?

**API** (ראשי תיבות של Application Programming Interface) הוא דלת שתוכנה מציעה לתוכנות אחרות. **API של רשת** (web API) הוא דלת שמגיעים אליה דרך האינטרנט בעזרת **HTTP**, אותה שפה שהדפדפן שלכם מדבר כשאתם פותחים דף אינטרנט. ההבדל הוא ש-API של רשת מחזיר בדרך כלל נתונים פשוטים (לרוב **JSON**) ולא דף יפה.

הכול הוא שיחה של שתי הודעות:

1. ה**לקוח** (client), כלומר הקוד שלכם, שולח **בקשה** (request).
2. ה**שרת** שולח בחזרה **תגובה** (response).

זה הכול. השרת אף פעם לא מדבר ראשון.

## האנטומיה של בקשה

הנה בקשת HTTP אמיתית כטקסט, בדיוק כפי שהיא עוברת בחוט:

```
GET /users/3 HTTP/1.1
Host: api.academy.test
Accept: application/json

```

- **שיטה** (method) (`GET`): מה אתם רוצים לעשות. `GET` קורא, `POST` יוצר, `PUT` ו-`PATCH` מעדכנים, `DELETE` מוחק.
- **נתיב** (path) (`/users/3`): לאיזה דבר אתם מתכוונים. כאן, המשתמש עם המזהה 3.
- **כותרות** (headers) (`Host`, `Accept`): מידע נוסף, `Name: value` אחד בכל שורה.
- **גוף** (body): נתונים אופציונליים שאתם שולחים יחד עם הבקשה (לא בשימוש ב-`GET`). הכותרות והגוף מופרדים בשורה ריקה.

כתובת מלאה כמו `https://api.academy.test/users/3` היא **URL**. היא מתפרקת לחלקים:

```
https://api.academy.test/users/3?role=admin
|       |                |       |
scheme  host             path    query string
```

## האנטומיה של תגובה

```
HTTP/1.1 200 OK
Content-Type: application/json

{"id":3,"name":"Alan Turing","role":"viewer"}
```

השורה הראשונה מכילה את **קוד הסטטוס** (`200`) וטקסט קצר (`OK`). אחר כך באות כותרות, שורה ריקה, וה**גוף**.

קוד הסטטוס הוא מספר בן שלוש ספרות, והספרה הראשונה אומרת לכם מהי המשפחה:

| קוד | משפחה | משמעות |
| --- | --- | --- |
| 2xx | הצלחה | זה עבד (`200 OK`, `201 Created`, `204 No Content`) |
| 3xx | הפניה / לא השתנה | חפשו במקום אחר, או השתמשו בעותק השמור אצלכם (`304`) |
| 4xx | שגיאת לקוח | הבקשה שלכם שגויה (`401`, `403`, `404`, `422`) |
| 5xx | שגיאת שרת | השרת נכשל, זו לא אשמתכם (`500`, `503`) |

## הקריאה הראשונה שלכם

JavaScript שולחת בקשות בעזרת `fetch`. תלמדו אותה כמו שצריך בשיעור הבא; כרגע, קראו את זה:

```js
const res = await fetch('https://api.academy.test/');
const info = await res.json();
console.log(res.status); // prints: 200
```

- `fetch(url)` שולחת בקשת `GET` ומחזירה אובייקט **תגובה** (response), אבל רק אחרי שהשרת עונה. `await` משהה את הקוד שלכם עד שזה קורה.
- `res.status` הוא המספר מהשורה הראשונה של התגובה.
- `res.json()` קוראת את הגוף ומפענחת את טקסט ה-JSON לאובייקט רגיל. גם זה לוקח זמן, ולכן גם כאן צריך `await`.

שרת התרגול בכתובת `https://api.academy.test` חי בתוך הדף הזה, ולכן הוא עובד גם בלי חיבור לאינטרנט, תמיד עונה באותה צורה, ומתחיל מאפס בכל פעם שאתם לוחצים על הרצה. אי אפשר לשבור שום דבר.

> **שימו לב:**
> - שכחתם `await`: `const res = fetch(...)` שומר *הבטחה* (promise), לא תגובה. הדפסת `res.status` נותנת `undefined`, ו-`res.json()` נכשלת עם `TypeError: res.json is not a function`.
> - שימוש ב-`http://` במקום ב-`https://` עבור שרת התרגול: הבקשה נכשלת עם `TypeError: Failed to fetch: use https:// for api.academy.test`.
> - קריאה ל-`res.json()` פעמיים: אפשר לקרוא גוף רק פעם אחת. שמרו את התוצאה במשתנה והשתמשו בו שוב.
> - בלבול בין טקסט הסטטוס למספר: השוו `res.status === 200`, ולא את המילה `"OK"`.

## להמשיך הלאה

פתחו את `https://api.academy.test/` כנתונים: התשובה מפרטת כל כתובת שתשתמשו בה בקורס הזה. נסו `await fetch('https://api.academy.test/users')` והדפיסו `(await res.json()).length`.

> **תורכם:** שורת ה-`fetch` כבר כתובה. קראו את הגוף עם `res.json()`, ואז הדפיסו את שם ה-API, את הסטטוס, ואת מספר נקודות הקצה (endpoints) של REST ושל SOAP שהשרת מפרט, בפורמט של ארבע השורות מהערות קוד ההתחלה.
