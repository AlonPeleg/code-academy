מחיקה היא הכתיבה הפשוטה ביותר: מצביעים על משהו ואומרים "הסירו אותו". זה גם המקום המושלם ללמוד שני רעיונות חשובים על שיטות HTTP: **בטוחה** (safe) ו**אידמפוטנטית** (idempotent). הם אומרים לכם אילו בקשות מותר לחזור עליהן בלי חשש.

## DELETE בפועל

```
DELETE /todos/1 HTTP/1.1
Host: api.academy.test
Authorization: Bearer token-ada
```

```
HTTP/1.1 204 No Content

```

אין גוף בקשה, ואחרי הצלחה אין גוף תשובה: `204 No Content` פירושו "בוצע, ואין מה להראות לכם". בקוד:

```js
const res = await fetch(BASE + '/todos/1', {
  method: 'DELETE',
  headers: { Authorization: 'Bearer ' + token },
});
console.log(res.status); // prints: 204
console.log(res.ok);     // prints: true
```

**אל** תקראו ל-`res.json()` על `204`: אין JSON ותקבלו `SyntaxError: Unexpected end of JSON input`. אם רוצים לוודא שהוא ריק, `await res.text()` מחזירה `""`.

בלי token מקבלים `401`, ועבור id שלא קיים מקבלים `404`. לכן מחיקה של אותו פריט **פעמיים** נותנת `204` ואז `404`.

## שיטות בטוחות

שיטה היא **בטוחה** אם היא רק *קוראת*; קריאה לה לא משנה דבר בשרת. זה הבטחה בינכם לבין כל הרשת: דפדפנים טוענים קישורים מראש, מנועי חיפוש סורקים אותם, מטמונים שומרים את התשובות, ואף אחד מהם לא מבקש רשות.

| שיטה | בטוחה? | אידמפוטנטית? | יוצרת או משנה נתונים? |
| --- | --- | --- | --- |
| `GET` | כן | כן | לא (קריאה בלבד) |
| `HEAD`, `OPTIONS` | כן | כן | לא |
| `PUT` | לא | כן | מחליפה |
| `DELETE` | לא | כן | מסירה |
| `PATCH` | לא | לא מובטח | משנה חלקית |
| `POST` | לא | **לא** | יוצרת |

אם אי פעם תשימו מחיקה מאחורי קישור `GET`, רובוט סריקה ימחק בשמחה הכול. לעולם אל תעשו את זה.

## אידמפוטנטית: חזרה עליה לא מזיקה

שיטה היא **אידמפוטנטית** אם ביצוע שלה הרבה פעמים משפיע על השרת כמו ביצוע פעם אחת.

- `PUT /todos/2` עם אותו גוף פעמיים משאיר את todo 2 באותו מצב. בסדר לחזור על זה.
- `DELETE /todos/1` פעמיים: אחרי הקריאה הראשונה ה-todo נעלם, ואחרי השנייה הוא עדיין נעלם. ה*מצב הסופי* זהה, גם אם ה**תשובה** השנייה היא `404` ולא `204`.
- `POST /todos` פעמיים יוצר **שני** todos עם שני id שונים.

```
POST /todos {"title":"Same","userId":1}  ->  201  id 11
POST /todos {"title":"Same","userId":1}  ->  201  id 12   (a duplicate!)
```

למה זה חשוב? רשתות לא אמינות. אם בקשה חרגה מהזמן, אתם לא יודעים אם השרת קיבל אותה. עבור `PUT` או `DELETE` אפשר פשוט **לנסות שוב**. עבור `POST` ניסיון חוזר עיוור עלול ליצור כפילויות, ולכן API רציניים של תשלומים מוסיפים כותרת מפתח אידמפוטנטיות. תשתמשו בחשיבה הזאת שוב בשיעור 11.

## קריאת המצב הסופי

אחרי מחיקה, הוכיחו שהיא עבדה: `GET /todos/1` נותן עכשיו `404`, ו-`GET /todos` מדווח `X-Total-Count: 9`. בדיקת המצב האמיתי היא הרגל טוב בבדיקות ובסקריפטים.

> **שימו לב:**
> - **קריאה ל-`res.json()` על `204`.** היא זורקת `SyntaxError: Unexpected end of JSON input`. בדקו `res.status === 204` או השתמשו ב-`res.text()`.
> - **שכחתם את ה-id.** `DELETE /todos` (האוסף) עונה `405 Method DELETE is not allowed here`; אי אפשר למחוק את הרשימה כולה.
> - **שכחתם את הכותרת `Authorization`.** כל כתיבה עונה `401` בלעדיה.
> - **התייחסתם ל-`404` השני ככישלון של התוכנית שלכם.** במחיקה, "כבר לא קיים" הוא בדרך כלל מה שרציתם. החליטו במכוון אם `404` הוא שגיאה מבחינתכם.
> - **ניסיון חוזר עיוור של POST** אחרי חריגת זמן. ייתכן שעכשיו יש לכם כפילות.
> - **מחיקה עם `GET`.** לעולם אל תשנו נתונים עם שיטה בטוחה.

## להמשיך הלאה

מחקו את todo 2 ואז הביאו את `/users/1/todos`. אילו todos נשארו ל-Ada? אחר כך נסו `DELETE /users/99` וקראו את הודעת השגיאה.

> **תורכם:** מחקו todo בלי token, עם token, ושוב, ואז בדקו את הספירה. אחר כך צרו את אותו todo פעמיים עם `POST` כדי לראות שני id, ובצעו `PUT` של אותה החלפה פעמיים כדי להוכיח שהתוצאות זהות.
