מודל שאף אחד לא יכול להשתמש בו הוא רק ניסוי. בשלב האחרון הזה הופכים את המודל שהוערך למשהו שאפשר לשים מאחורי טופס אינטרנט, בודקים את הגבולות שלו וכותבים מה הוא יכול ומה הוא לא יכול.

## איפה אנחנו עומדים

כל החלקים קיימים: נתונים נקיים, מתכון לעיבוד מקדים, שלושה מועמדים שהושוו בהגינות, מנצח (רגרסיה לינארית) ושגיאת בדיקה ישרה של כ-20 אלף. קוד ההתחלה שומר את כל קוד הפרויקט עד שלב 7 ויש בו את הייבואים המצטברים.

## מה נוסיף

1. **אימון מחדש על כל הנתונים.** הבחינה נגמרה, ולכן 60 בתי הבדיקה יכולים עכשיו לעזור באימון. אחרי זה אי אפשר להעריך עוד, ולכן אנחנו סומכים על המספרים משלב 7.
2. פונקציה `predict_price(...)` שמתמחרת בית חדש ו**מזהירה** כשהוא מחוץ למה שהמודל מכיר.
3. הדגמה של בעיות **אקסטרפולציה** (extrapolation).
4. **כרטיס מודל** (model card) קצר.

## מדריך צעד אחר צעד

**1. אימון מחדש.** ערמו את חלקי האימון והבדיקה ובנו מחדש את ה-pipeline עם המודל המנצח:

```python
X_all = pd.concat([X_train, X_test])
y_all = pd.concat([y_train, y_test])
final = Pipeline([("prep", prep), ("model", LinearRegression())])
final.fit(X_all, y_all)
```

שמרו גם את `area_low` ו-`area_high`, השטח הקטן והגדול ביותר שנראו באימון: הם מגדירים את הטווח שבו יש למודל ראיות.

**2. פונקציית חיזוי.** בית חדש מגיע כערכים פשוטים. המודל מצפה לטבלה עם **אותן עמודות** כמו באימון, כולל המאפיין שהונדס, ולכן עטפו את הערכים ב-`DataFrame` של שורה אחת (כל ערך ברשימה) והשתמשו שוב ב-`add_features` משלב 5. זה הרווח מכתיבתה כפונקציה:

```python
def predict_price(area_m2, bedrooms, age_years, distance_to_center_km, neighbourhood):
    house = pd.DataFrame({"area_m2": [area_m2], ...})   # one row, one list per column
    house = add_features(house)
    price = float(final.predict(house)[0])               # predict returns an array, take element 0
    ...
    return round(price), warning
```

החזירו שני דברים, את המחיר ואזהרה (הודעה, או `None` כשהכול בסדר). הקוד שקורא לפונקציה יכול להציג את האזהרה למשתמש. פייתון מאפשרת לפרק את שניהם בבת אחת: `price, warning = predict_price(...)`, ו-`warning or "ok"` מדפיסה "ok" כשהאזהרה היא `None`.

**3. אקסטרפולציה.** אמנו יער אקראי על אותם נתונים ושאלו את שני המודלים על וילה של 400 מ"ר, הרבה מעבר לכל מה שיש בנתונים. המודל הלינארי ממשיך את הקו הישר שלו (בערך 1295 אלף); היער יכול רק לחזור על מה שראה, ולכן עונה בערך 562 אלף. אף אחד מהם לא אמין! מחירים אמיתיים של אחוזות כפופים לכללים אחרים. הלקח: **תחזיות מחוץ לטווח האימון הן ניחושים**, ומערכת טובה אומרת את זה.

**4. הטיה וגבולות.** מודל לומד כל דפוס שיש בנתונים שלו, כולל דפוסים לא הוגנים. אם בחיים האמיתיים מחירים היסטוריים בשכונה מסוימת הורדו בגלל אפליה, מודל שהתאמן עליהם יעתיק את זה ויקרא לזה "אובייקטיבי". בגלל זה שלב 7 פרס את השגיאות לפי קבוצה. הנתונים שלנו גם מומצאים, מכסים שלוש שכונות ואין בהם מושג של זמן, ולכן אינפלציה, כבישים חדשים או התרסקות שוק בלתי נראים לו.

**5. כרטיס מודל** הוא סיכום קצר וישר שמוצמד למודל: מה הוא, על מה הוא אומן, עד כמה הוא עובד, איפה הוא נכשל. הדפסה שלו מאותם משתנים שחישבתם (`len(X_all)`, `test_mae`, `area_low`) שומרת אותו מסונכרן עם הקוד.

> **שימו לב:**
> - העברת בית בלי העמודה `area_per_bedroom` זורקת `ValueError: columns are missing`. תמיד העבירו נתונים חדשים דרך `add_features`.
> - DataFrame שנבנה עם מספרים רגילים במקום רשימות נכשל עם `ValueError: If using all scalar values, you must pass an index`. כתבו `[area_m2]`.
> - אימון מחדש על כל הנתונים בסדר רק כי העריכו קודם. לעולם אל תדווחו ציון של מודל שאומן על השורות שעליהן קיבל ציון.
> - `round(price)` מעגל לאלף השלם הקרוב: אל תציגו מספר מדויק כזה כוודאי, כי השגיאה הטיפוסית היא כ-20.

> **תורכם:** אמנו מחדש את `final` על כל השורות וחשבו את `area_low`/`area_high`; כתבו את `predict_price` והדפיסו שורה לכל בית (`neighbourhood area m2: price k, warning-or-ok`) עבור `(80, 2, 10, 3.5, "Riverside")`, `(120, 4, 35, 8.0, "Hilltop")` ו-`(400, 5, 3, 2.0, "Riverside")`; אמנו את היער והדפיסו `linear for 400 m2:`, `forest for 400 m2:` ו-`forest stays below the most expensive house seen:`; לבסוף הדפיסו את כרטיס המודל (`MODEL CARD`, `model:`, `trained on:`, `features:`, `typical error:`, `valid area range:`, `known limits:`).

## מה לבנות הלאה

* החליפו את הטבלה המומצאת במערך נתונים אמיתי, למשל CSV של מכירות, וחזרו על אותם שמונה שלבים.
* הוסיפו מאפיין `area_m2 ** 2` (או נסו `GradientBoostingRegressor`) ובדקו אם שגיאת ה-cross-validation יורדת, ואז אמתו שוב על קבוצת בדיקה שלא נגעתם בה.
* נבאו טווח, לא רק מספר, למשל עם השגיאה הטיפוסית או עם מודלי קוונטילים.
* שמרו את ה-pipeline עם `joblib.dump(final, "model.joblib")` וטענו אותו בתוך אפליקציית אינטרנט קטנה.
* עקבו אחרי המודל אחרי ההשקה: השוו תחזיות למחירי מכירה אמיתיים בכל חודש, ואמנו מחדש כשהשגיאה גדלה.
