ה-API שלכם עובד, אבל הוא שוכח הכול כשהוא מופעל מחדש, ההגדרות שלו קבורות בקוד, ודפדפנים באתרים אחרים לא יכולים לדבר איתו. השיעור האחרון הזה מתקן את שלושתם ונותן לכם את רשימת הבדיקה להעלאת שרת לאינטרנט.

## שמירת נתונים עם קובץ JSON

עד עכשיו הנתונים חיו במערך רגיל, ולכן נעלמו בכל פעם שהתוכנית נעצרה. התיקון הפשוט ביותר הוא קובץ: טוענים אותו כשהשרת מתחיל, ושומרים אחרי כל שינוי. אתם כבר מכירים את החלקים משיעור ה-`fs`:

```js
function load() {
  if (!fs.existsSync(file)) return [];                 // first run: no file yet
  return JSON.parse(fs.readFileSync(file, 'utf8'));    // text -> array
}
function save(items) {
  fs.mkdirSync(path.dirname(file), { recursive: true }); // create the folder if needed
  fs.writeFileSync(file, JSON.stringify(items, null, 2)); // array -> text
}
```

`JSON.stringify(items, null, 2)` מזיז את תחילת השורות בקובץ בשני רווחים כדי שאדם יוכל לקרוא אותו. שמרו את הקוד הזה במודול משלו (`store.js`) כך שהנתיבים רק קוראים ל-`store.load()` ול-`store.save(notes)`; בהמשך אפשר להחליף את הקובץ במסד נתונים אמיתי בלי לגעת בנתיבים. בהדגמה שלהלן התוכנית מפעילה אפליקציה שנייה אחרי שעצרה את הראשונה: היא מוצאת את הפתקים שוב כי הם נקראו מהקובץ.

קובץ JSON מושלם לאב-טיפוס (prototype) ולכלים קטנים. הוא קורס כשהרבה משתמשים כותבים בבת אחת (כל כתיבה מחליפה את הקובץ כולו) או כשהנתונים גדולים. אז משתמשים במסד נתונים כמו SQLite, PostgreSQL או MongoDB. זכרו גם שהרבה אחסוני ענן נותנים לאפליקציה שלכם דיסק זמני שנמחק בכל פריסה (deploy), ולכן אחסון בקובץ שם צריך "persistent volume" או מסד נתונים.

## הגדרות עם משתני סביבה

הגדרות שמשתנות בין המחשב הנייד שלכם לשרת (הפורט, קובץ הנתונים, סודות) אסור לקבוע בקוד. הסטנדרט הוא **משתני סביבה** (environment variables), הזמינים ב-`process.env`:

```js
const PORT = Number(process.env.PORT) || 3000;
const SECRET = process.env.SECRET; // set on the server, never in Git
```

שלושה כללים: הערכים הם תמיד **מחרוזות** (ממירים עם `Number`), משתנה חסר הוא `undefined` (נותנים ברירת מחדל עם `||` להגדרות לא מזיקות, אבל נכשלים בקול רם עבור סודות), וסודות לעולם לא נכנסים למאגר (repository) שלכם. במחשב שלכם אפשר לשים אותם בקובץ `.env` (שרשום ב-`.gitignore`) ולהפעיל את Node עם `node --env-file=.env server.js`, או להשתמש בחבילה `dotenv`. פלטפורמות אירוח מאפשרות להקליד את המשתנים בדף הגדרות, והן בדרך כלל אומרות לאפליקציה שלכם באיזה פורט להשתמש דרך `PORT`, ולכן חובה לקרוא אותו. `NODE_ENV=production` היא עוד מוסכמה: ספריות (ו-Express) עוברות להתנהגות מהירה ושקטה יותר.

## CORS: לתת לדפדפנים לקרוא ל-API שלכם

לדפדפנים יש כלל בטיחות: JavaScript ב-`https://myapp.com` לא רשאי לקרוא תשובות מ-`https://api.other.com` אלא אם השרת הזה מסכים במפורש. זו **מדיניות same-origin**; ההסכמה נקראת **CORS** (Cross-Origin Resource Sharing). השרת מסכים על ידי שליחת כותרת:

```
Access-Control-Allow-Origin: *
```

עבור בקשות שיכולות לשנות נתונים, הדפדפן שולח קודם בקשת `OPTIONS` של **preflight** ששואלת "מותר לי?", וצופה ל-`204` עם השיטות המותרות. החבילה `cors` עושה את כל זה כ-middleware:

```js
app.use(cors());                                   // any website may call us
app.use(cors({ origin: 'https://myapp.com' }));   // only this one (better for production)
```

רשמו אותה לפני הנתיבים שלכם. זכרו: CORS נאכף על ידי הדפדפן בלבד. `curl` ותוכניות שרת מתעלמים ממנו, ולכן הוא לא תחליף לאימות.

## רשימת הבדיקה לעלייה לאוויר

- ב-`package.json` יש סקריפט התחלה: `"start": "node server.js"`, והאפליקציה מאזינה ל-`process.env.PORT`.
- סודות ו-`NODE_ENV=production` מוגדרים כמשתני סביבה במארח, ולעולם לא נכנסים ל-commit.
- האתר מוגש ב-**HTTPS** (Render, Railway, Fly.io ופלטפורמות דומות מספקות זאת בחינם).
- ה-error handler שלכם מסתיר פנימיות; הקלט מאומת; הסיסמאות מגובבות.
- הוסיפו `helmet` (כותרות ברירת מחדל בטוחות יותר) ו-`express-rate-limit` (עוצר הצפות של בקשות), הריצו `npm audit` מדי פעם, ושמרו על התלויות מעודכנות.
- השתמשו באחסון נתונים אמיתי ששורד פריסות, ושמרו גיבויים.

סביבת התרגול כאן היא חיקוי בטוח: מערכת הקבצים שלה בזיכרון והרשת שלה מדומה. Node.js אמיתי עובד באותה דרך עם דיסק ורשת אמיתיים; השתמשו בכפתור "הגדרה" (Setup) כדי לראות איך מריצים את התוכניות האלה במחשב שלכם.

> **שימו לב:**
> - **`process.env.PORT` הוא מחרוזת.** `'4000' + 1` הוא `'40001'`. השתמשו ב-`Number(...)`.
> - **כתיבת הקובץ לפני שהתיקייה קיימת.** `fs.writeFileSync` נכשל עם `ENOENT: no such file or directory`. צרו את התיקייה עם `mkdirSync(..., { recursive: true })`.
> - **`JSON.parse` על קובץ ריק או שבור** זורק `SyntaxError: Unexpected end of JSON input`. טפלו במקרה של ההרצה הראשונה עם `existsSync`.
> - **commit של `.env`.** ברגע שסוד נמצא בהיסטוריית Git, התייחסו אליו כאל דלף והחליפו אותו.
> - **שימוש ב-`cors()` כאבטחה.** `*` פירושו כולם; הגנו על נתונים עם התחברות, לא עם CORS.

> **תורכם:** כתבו את `load` ו-`save` ב-`store.js`, קראו את `PORT` ו-`DATA_FILE` מ-`process.env` עם ברירות מחדל, ורשמו את `cors()` ב-`main.js`. ההדגמה שומרת שני פתקים, מפעילה את השרת מחדש ומראה שהם עדיין שם.
