יש לכם עכשיו את כל המרכיבים של משחק אמיתי: לולאה, קלט מהמקלדת, מחלקה (class) של שחקן ורשימה של אובייקטים. החלק האחרון שחסר הוא **זיהוי התנגשות** (collision detection): לגלות מתי שני דברים נוגעים זה בזה. בעזרתו אפשר לאסוף מטבעות, לפגוע באויבים, להיתקל בקירות ולשמור **ניקוד** (score). בשיעור הזה תסיימו משחק קטן ושלם.

## מבנה המשחק

- מחלקה `Player` שזזה עם מקשי החיצים ונשארת על המסך.
- מחלקה `Coin`: רק מיקום ומתודה `Draw()`.
- `List<Coin>` ב-`Main` שמחזיקה את כל המטבעות שעל הלוח.
- `int score` שגדל ב-10 על כל מטבע שנאסף.

שימו לב כמה `Main` קצרה: כל מחלקה מכירה את הנתונים והציור של עצמה, ו-`Main` רק אומרת להן *מתי* לפעול.

## התנגשות מלבנים (AABB)

רוב משחקי ה-2D משתמשים במלבנים כ"קופסאות פגיעה" בלתי נראות. שני מלבנים שלא מסובבים (אומרים **מיושרים לצירים**, axis-aligned) חופפים רק כשהם חופפים **גם** אופקית **וגם** אנכית. הבדיקה היא ארבע השוואות:

```csharp
bool overlap =
    aLeft  < bRight  &&   // A starts before B ends
    aRight > bLeft   &&   // A ends after B starts
    aTop   < bBottom &&
    aBottom > bTop;
```

כשיש מיקום `(X, Y)` וגודל, "שמאל" הוא `X`, "ימין" הוא `X + Size`, "למעלה" הוא `Y` ו"למטה" הוא `Y + Size`. שימו את הבדיקה במתודה של `Player`, כדי שקריאת לולאת המשחק תרגיש טבעית:

```csharp
public bool Touches(Coin c)
{
    return X < c.X + Coin.Size && X + Size > c.X
        && Y < c.Y + Coin.Size && Y + Size > c.Y;
}
```

המתודה מחזירה `bool`. הסימן `&&` פירושו "וגם": כל ארבעת החלקים חייבים להתקיים. ה-`Size` של המטבע הוא `const`, ולכן ניגשים אליו דרך שם המחלקה: `Coin.Size`.

נסו את זה על מספרים. שחקן ב-x = 100 (כלומר הוא מכסה 100 עד 120) ומטבע ב-x = 125 (מכסה 125 עד 137): האם `100 < 137` נכון? כן. האם `120 > 125` נכון? לא. לכן כל הבדיקה שקרית (false): יש רווח.

## איסוף עם RemoveAll

בשיעור הקודם `RemoveAll` קיבלה lambda ומחקה את הפריטים שמתאימים. עכשיו ה-lambda שואלת את השחקן:

```csharp
int collected = coins.RemoveAll(coin => player.Touches(coin));
score += collected * 10;
```

`RemoveAll` מחזירה את **מספר הפריטים שהיא הסירה**, ולכן שורה אחת יכולה גם למחוק את המטבעות וגם לתת את הנקודות. המשתנה `score` מוגדר **לפני** הלולאה, ולכן הוא שומר על הערך שלו מפריים לפריים.

## ניקוד והצגתו

הציגו את הניקוד עם `Engine.Text(8, 8, 14, Color.White, "Score: " + score);`. חיבור מחרוזת ומספר עם `+` הופך את המספר לטקסט באופן אוטומטי. בסוף המשחק מדפיסים את התוצאה עם `Console.WriteLine`: זו השורה ש-**בדיקת תשובה** (Check answer) קוראת.

> **שימו לב:**
> - שימוש ב-`||` במקום `&&` בבדיקת ההתנגשות גורם לשחקן "לגעת" במטבעות מהצד השני של המסך.
> - בלבול בין הקצוות, כמו `X + Size < c.X`: זה בודק אם הם *רחוקים*, ההפך מחפיפה.
> - הגדרת `int score = 0;` בתוך הלולאה מאפסת אותו בכל פריים, ולכן הוא תמיד מסתיים ב-0.
> - ב-`Touches(Coin c)` שוכחים `return`: `error CS0161: 'Player.Touches(Coin)': not all code paths return a value`.
> - ה-`(X, Y)` של מלבן הוא הפינה השמאלית העליונה שלו. עבור עיגולים, `Engine.Circle` מקבלת את המרכז, ולכן `Coin.Draw` מוסיפה `Size / 2`.

## להמשיך הלאה

הזיזו את התסריט בלשונית Player input כך שהשחקן יחטיא או יאסוף מטבעות אחרים, וראו איך הניקוד משתנה. אחר כך הוסיפו ספירה לאחור: סיימו את המשחק אחרי פחות פריימים עם `Engine.Frames(...)`, או תנו לכל מטבע שדה `Value` כדי שמטבעות נדירים יהיו שווים יותר.

> **תורכם:** השלימו את `Touches` עם בדיקת החפיפה בת ארבעת החלקים, ואז ממש אחרי `player.Update();` השתמשו ב-`coins.RemoveAll(...)` כדי להסיר מטבעות שנגעו בהם ולהוסיף 10 נקודות על כל אחד. הסיור אוסף 5 מתוך 6 המטבעות: `score: 50` ו-`coins left: 1`.
