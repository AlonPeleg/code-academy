סנייק נראה פשוט, אבל מסתתר בו רעיון שימושי מאוד: המשחק לא זז בכל פריים. הוא זז ב**צעדים**, על רשת, בזמן שהמסך ממשיך להיות מצויר מחדש 30 פריימים בשנייה. תשתמשו גם ב-`List<T>` כגוף של הנחש.

## רשת וטיימר צעדים

המסך הוא 320 על 240 פיקסלים. אנחנו חותכים אותו לתאים של 16 פיקסלים, וכך מתקבלת רשת של 20 עמודות ו-15 שורות. לוגיקת המשחק משתמשת ב**קואורדינטות של תאים** (עמודה 9, שורה 7), ורק הציור מכפיל ב-16:

```csharp
Engine.Rect(s.X * CellPx + 1, s.Y * CellPx + 1, 14, 14, Color.Green);
```

הנחש צריך לזוז פעם בכל 6 פריימים (5 צעדים בשנייה). אופרטור השארית `%` נותן "כל N פריימים":

```csharp
if (Engine.Frame % 6 == 5)    // true on frames 5, 11, 17, 23 ...
{
    snake.Step(food);
}
```

להאט או להאיץ את הצעד זה מחוון הקושי של סנייק: משנים מספר אחד.

## הגוף הוא List של תאים

הראש הוא `Segments[0]` והזנב הוא האיבר האחרון. כדי לזוז לא מזיזים כל מקטע. מוסיפים ראש חדש מלפנים וזורקים את הזנב:

```csharp
Segments.Insert(0, new Cell(nx, ny));            // new head
Segments.RemoveAt(Segments.Count - 1);           // forget the old tail
```

`Insert(index, item)` מכניסה את הפריט במקום הזה ודוחפת את האחרים אחורה. `RemoveAt(index)` מוחקת לפי מיקום (בניגוד ל-`Remove`, שמקבלת את הפריט עצמו).

## לגדול זה "לא למחוק את הזנב"

זה כל הטריק של הצמיחה. כשהראש החדש נוחת על האוכל, פשוט מדלגים על `RemoveAt`. הנחש עכשיו ארוך בתא אחד, כי הוא קיבל ראש ולא איבד כלום:

```csharp
bool ate = food != null && food.Same(nx, ny);
if (!ate) Segments.RemoveAt(Segments.Count - 1);
return ate;
```

המתודה `Step` מחזירה אם אוכל נאכל, כך ש-`Main` יכולה לעבור למיקום האוכל הבא. אנחנו משתמשים במערך קבוע של מיקומי אוכל ולא באקראיים, כי הקלטה חייבת להיות דטרמיניסטית: אותם מקשים חייבים תמיד לתת את אותו משחק.

## פונים בלי פניות פרסה

הכיוון הוא זוג `(DX, DY)`: ימינה הוא `(1, 0)`, למעלה הוא `(0, -1)`. נחש לא יכול להסתובב לאחור אל תוך הצוואר של עצמו, ולכן `Turn` מסרבת לכיוון ההפוך:

```csharp
if (dx == -DX && dy == -DY) return;
```

השתמשו ב-`KeyPressed`, לא ב-`KeyDown`. פנייה צריכה לקרות פעם אחת לכל הקשה, והנחש זז רק כל פריים שישי, ולכן הקשה קצרה בין שני צעדים חייבת עדיין להיזכר.

## מוות

לפני שהוא זז, `Step` מחשבת את מיקום הראש החדש ובודקת שני דברים: האם הוא מחוץ לרשת, והאם מקטע כלשהו כבר יושב שם? הבדיקה השנייה משתמשת ב-lambda עם `Exists`:

```csharp
Segments.Exists(s => s.Same(nx, ny))
```

`Exists` דומה ל-`RemoveAll` אבל רק שואלת "האם יש לפחות התאמה אחת?". אם אחת הבדיקות נכונה, `Alive` הופך ל-false והצעדים נעצרים.

> **שימו לב:**
> - עדכון הנחש בכל פריים במקום בכל פריים שישי: הנחש עף על הלוח מהר פי 6. השתמשו בטיימר הצעדים.
> - שימוש ב-`Remove(Segments.Count - 1)` במקום `RemoveAt`: `Remove` רוצה *פריט*, ולכן מקבלים `error CS1503: Argument 1: cannot convert from 'int' to 'Cell'`.
> - חישובי פיקסלים בלוגיקת המשחק: השוו תאים לתאים, לא פיקסלים לתאים, אחרת שום דבר לא מתנגש.
> - נחש שהסתובב לאחור: לחיצה על שני חיצים בתוך צעד אחד (ימינה, למעלה, שמאלה) עדיין יכולה להפוך אותו. משחקים אמיתיים זוכרים רק פנייה אחת בתור לכל צעד.

## מה ההקלטה עושה

לשונית הקלט (input) מפנה את הנחש ימינה אחרי כל ארוחה: למעלה בפריים 24, ימינה בפריים 48, למטה בפריים 78. הוא אוכל ארבע חתיכות אוכל, ולבסוף נוסע לתוך הקיר התחתון ונעצר, ולכן התוכנית מדפיסה `alive: False`. הזיזו לחיצת מקש בכמה פריימים והנחש יחטיא אוכל או יתרסק מוקדם יותר.

## להמשיך הלאה

הוסיפו האצה: בכל פעם שאוכל נאכל, הקטינו את מרווח הצעדים. שמרו אותו במשתנה במקום במספר 6.

> **תורכם:** (1) ב-`Main`, קראו ל-`snake.Turn(...)` עבור כל מקש חץ עם `KeyPressed`; (2) ב-`Step`, שמרו את הזנב כשהראש החדש נמצא על האוכל והחזירו `true`. הנחש צריך להסתיים עם `length: 7` ו-`alive: False`.
