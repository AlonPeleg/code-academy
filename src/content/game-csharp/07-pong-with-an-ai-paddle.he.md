בפונג יש שני מחבטים, אבל רק בן אדם אחד. בשיעור הזה תתנו למחבט השני מוח, ותעשו את זה כמו שמפתחי Unity עושים: עם **ממשק** (interface), כך שלמחבט לא אכפת אם ההוראות שלו מגיעות ממקלדת או מאלגוריתם.

## מחלקה אחת של מחבט, שני סוגי נהגים

המשחק צריך שני מחבטים שנעים באותה דרך (למעלה, למטה, ונשארים בתוך המסך) אבל מחליטים *מתי* לזוז בצורה שונה. במקום להעתיק את כל המחלקה `Paddle`, מוציאים החוצה את הדבר היחיד ששונה. ממשק הוא חוזה: הוא מונה מתודות שמחלקה מתחייבת שיהיו לה, ולא אומר דבר על איך הן עובדות.

```csharp
interface IController
{
    int Direction(Paddle paddle, Ball ball);   // -1 = up, 0 = stay, +1 = down
}
```

כל מחלקה שכותבת `: IController` אחרי שמה חייבת לספק את `Direction`. שתי מחלקות עושות זאת:

```csharp
class KeyboardController : IController
{
    public int Direction(Paddle paddle, Ball ball)
    {
        int dir = 0;
        if (Engine.KeyDown(Key.Up)) dir -= 1;
        if (Engine.KeyDown(Key.Down)) dir += 1;
        return dir;
    }
}
```

`Paddle` שומר `IController` בשדה ושואל אותו בכל פריים: `Y += Controller.Direction(this, ball) * Speed;`. למחבט אין מושג איזה סוג בקר הוא מחזיק. זה נקרא **פולימורפיזם** (polymorphism): "צורות רבות", קריאה אחת. כך גם מחליפים ב-Unity רכיבים כמו מטפלי קלט ומוחות AI. בהמשך תוכלו להוסיף `NetworkController` בלי לגעת ב-`Paddle`.

## חושבים כמו AI פשוט

AI טוב במשחק אינו מושלם, הוא *ניתן לניצחון*. הכלל של המחשב קטן מאוד: משווים את אמצע הכדור לאמצע המחבט וזזים לכיוון הכדור.

```csharp
int paddleMid = paddle.Y + Paddle.Height / 2;
int ballMid = ball.Y + Ball.Size / 2;
if (ballMid < paddleMid - 4) return -1;   // ball is above: go up
if (ballMid > paddleMid + 4) return 1;    // ball is below: go down
return 0;                                 // close enough: stay
```

האזור המת של 4 פיקסלים מונע מהמחבט לרעוד קדימה ואחורה בכל פריים. גם המחבט של המחשב *איטי* יותר משלכם (3 פיקסלים לפריים לעומת 5). כשאתם פוגעים בכדור ליד קצה המחבט שלכם הוא יוצא בזווית חדה, וה-AI האיטי לא תמיד מצליח להדביק אותו. הפרש המהירות הוא הגדרת הקושי.

## הכדור והקפיצה

`Ball.Hits(paddle)` היא אותה בדיקת חפיפה בין מלבנים שפגשתם בשיעור המטבעות. `Bounce` הופכת את המהירות האופקית וקובעת את המהירות האנכית לפי *המקום* שבו נפגע המחבט:

```csharp
VX = -VX;
VY = (Y + Size / 2 - (p.Y + Paddle.Height / 2)) / 5;
```

חילוק שלמים מתאים כאן. פוגעים באמצע והכדור ממשיך ישר, פוגעים בקצה והוא עף בזווית חדה. הבדיקות `ball.VX < 0 && ...` ב-`Main` בודקות רק את המחבט ש*אליו* הכדור נע; בלי זה הכדור היה יכול לקפוץ פעמיים בתוך המחבט ולהיתקע.

## ניקוד

כשהכדור עבר לגמרי צד של המסך, מישהו קלע והכדור נשלח מחדש. `Serve(direction)` מחזירה את הכדור לאמצע ושולחת אותו שמאלה (`-1`) או ימינה (`1`).

> **שימו לב:**
> - אם שוכחים `: IController` במחלקה שיש לה מתודה `Direction`, מקבלים `error CS1503: Argument 3: cannot convert from 'AiController' to 'IController'` כשמעבירים אותה ל-`Paddle`.
> - מתודה של ממשק חייבת להיות `public` במחלקה, אחרת: `error CS0737: 'AiController' does not implement interface member 'IController.Direction(Paddle, Ball)' ... is not public`.
> - השוואה בין **החלק העליון** של הכדור (`ball.Y`) ל**חלק העליון** של המחבט גורמת ל-AI לכוון למקום הלא נכון. השוו בין האמצעים.
> - חילוק שלמים: `Height / 2` בסדר, אבל `3 / 2` הוא 1 ולא 1.5, ולכן מהירויות קטנות יכולות להתעגל לאפס.

## איך ההקלטה הזאת עובדת

לשונית הקלט (input) מחזיקה את השחקן ה"אנושי": היא לוחצת Down בפריים 28, משחררת בפריים 44, וכן הלאה. התוכנית שלכם מקליטה 600 פריימים (20 שניות). שנו את המקשים האלה והמחבט יחסום זריקות אחרות, ולכן גם התוצאה הסופית תשתנה.

## להמשיך הלאה

הפכו את ה-AI לגרוע יותר: עדכנו את ההחלטה שלו רק כל פריים שלישי, או תנו לו `Speed` של 2. או הוסיפו בקר שלישי, `TwoPlayerController`, שמשתמש במקשים `W` ו-`S`.

> **תורכם:** השלימו את `AiController.Direction` כך שהמחשב יעקוב אחרי הכדור (אמצע לאמצע, אזור מת של 4 פיקסלים), ואז תנו נקודות ב-`Main`: כשהכדור יוצא מימין השחקן קולע ו-`Serve(-1)`, וכשהוא יוצא משמאל המחשב קולע ו-`Serve(1)`. התוכנית צריכה להדפיס `player 1 - computer 4`.
