ברייקאאוט הוא קיר של לבנים, כדור קופץ ומחבט. הוא משלב את כל מה שלמדנו עד כה: `List<T>` של אובייקטים, התנגשויות בין מלבנים והסרת פריטים מהרשימה בזמן שהמשחק רץ. הרעיון החדש הוא **תגובה להתנגשות** על ידי שינוי המהירות של הכדור.

## בונים קיר עם לולאות מקוננות

יש 32 לבנים, ב-4 שורות של 8. להקליד 32 שורות `new Brick(...)` יהיה מגוחך, ולכן לולאה בתוך לולאה יוצרת אותן. הלולאה החיצונית סופרת שורות, הפנימית סופרת עמודות, והמיקום הוא סתם חשבון:

```csharp
for (int row = 0; row < 4; row++)
{
    for (int col = 0; col < 8; col++)
    {
        bricks.Add(new Brick(8 + col * 38, 40 + row * 16, rowColors[row]));
    }
}
```

כל לבנה רחבה 36 פיקסלים, ולכן צעד של 38 פיקסלים משאיר רווח של 2 פיקסלים. `rowColors` הוא מערך (array) של ארבעה ערכי `Color`, ו-`rowColors[row]` בוחר אחד לכל שורה. התבנית הזאת, "עוברים על רשת, יוצרים אובייקט לכל תא", היא הדרך שבה מתחילים רוב מחוללי האריחים והשלבים.

## מהירות וקפיצה

לכדור יש מהירות, `(VX, VY)` פיקסלים לפריים, ובכל פריים הוא מוסיף אותה למיקום שלו. קפיצה היא לא יותר מהיפוך הסימן של רכיב אחד:

```csharp
if (X < 0 || X + Size > Engine.Width) VX = -VX;   // left and right walls
if (Y < 0) VY = -VY;                              // the ceiling
```

הרצפה שונה: אין קיר בתחתית. אם הכדור יורד מתחת למסך, השחקן מאבד חיים ומתחיל כדור חדש.

המחבט שולח את הכדור בחזרה למעלה (`VY = -Math.Abs(VY)` מוודא שהוא עולה גם אם הוא כבר היה שלילי) ומכוון אותו לפי המקום שפגעתם בו: `VX = (ballCenter - paddleCenter) / 10`. פוגעים בקצה השמאלי של המחבט והכדור עף שמאלה.

## פוגעים בלבנה

שני מלבנים חופפים כשהם חופפים בשני הצירים. במשחקים הקודמים כתבתם את זה כביטוי ארוך. עכשיו זה נמצא במתודה של האובייקט שמכיר את הגודל של עצמו, `Brick.Hits(Ball b)`:

```csharp
return b.X < X + Width && b.X + Ball.Size > X
    && b.Y < Y + Height && b.Y + Ball.Size > Y;
```

קראו את זה כארבע שאלות של נכון/לא נכון: האם הקצה השמאלי של הכדור משמאל לקצה הימני שלי, הקצה הימני שלו מימין לקצה השמאלי שלי, ואותו דבר למעלה ולמטה. כל הארבע חייבות להיות נכונות.

אחר כך שורה אחת עושה את הנזק:

```csharp
int broken = bricks.RemoveAll(b => b.Hits(ball));
if (broken > 0) ball.VY = -ball.VY;
```

`RemoveAll` מוחקת כל לבנה שה-lambda עונה עבורה `true` ומחזירה כמה כאלה היו. אם לפחות לבנה אחת נשברה, הכדור קופץ. זה פשוט בכוונה: משחק אמיתי היה בודק אם הפגיעה הייתה מהצד או מלמטה והופך את `VX` או `VY` בהתאם, אבל היפוך של `VY` כבר מרגיש נכון בגרסה ראשונה.

## חברים סטטיים וחברי מופע

שימו לב ל-`Brick.Width`, ‏`Ball.Size` ו-`Paddle.Y` שנכתבים עם **שם המחלקה**. אלה ערכי `const`: הם שייכים למחלקה ולא לאובייקט אחד, ולכן ניגשים אליהם דרך המחלקה. לעומת זאת `Y` ו-`X` שונים לכל לבנה, ולכן משתמשים בהם דרך מופע (`b.X`). בתוך המחלקה עצמה אפשר לכתוב רק `Width`.

> **שימו לב:**
> - שינוי הרשימה בזמן מעבר עליה עם `foreach` זורק `InvalidOperationException: Collection was modified`. השתמשו ב-`RemoveAll` אחרי הלולאה, כמו כאן.
> - חיבור ארבע ההשוואות עם `||` במקום `&&`: כמעט כל לבנה תדווח על פגיעה, וכל הקיר ייעלם בפריים אחד.
> - היפוך של `VY` לכל לבנה חופפת היה מקפיץ את הכדור פעמיים ומבטל את הקפיצה. הפכו **פעם אחת** (`if (broken > 0)`), לא בתוך לולאה.
> - כדור מהיר יכול לקפוץ מעל אובייקט דק בין שני פריימים. זה נקרא **tunnelling** (מנהור). עם מהירות של 5 פיקסלים ולבנים בגובה 12 פיקסלים זה לא יכול לקרות כאן.

## ההקלטה

ה"שחקן" בלשונית הקלט (input) מזיז את המחבט רק ארבע פעמים: ימינה פעמיים, ואז שמאלה פעמיים, בדיוק מספיק כדי לפגוש את הכדור בכל פעם שהוא יורד. הכדור שובר אחת עשרה לבנים ב-300 פריימים (10 שניות) ולא נופל אף פעם. נסו למחוק שורת מקש: המחבט מחטיא, מאבדים חיים וכדור חדש מתחיל מהאמצע. כש-`lives` מגיע ל-0 הלולאה נעצרת.

## להמשיך הלאה

תנו לשורה התחתונה של הלבנים ניקוד גבוה יותר, או הפכו את צבע הלבנה לאינדיקציה לכמה פגיעות היא צריכה (מונה `Hits` ב-`Brick` שיורד). האיצו את הכדור אחרי כל עשר לבנים.

> **תורכם:** כתבו את `Brick.Hits(Ball b)` עם ארבע ההשוואות, ואז ב-`Main` הסירו כל לבנה שנפגעה עם `bricks.RemoveAll(...)` והפכו את `ball.VY` כשלפחות לבנה אחת הוסרה. התוכנית צריכה להדפיס `bricks left: 21` ו-`lives: 3`.
