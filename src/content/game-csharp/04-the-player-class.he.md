עד עכשיו כל המצב של המשחק שלכם חי במשתנים רופפים בתוך `Main`. זה עובד עבור ריבוע אחד, אבל במשחק אמיתי יש שחקן, אויבים, כדורים ומטבעות. בשיעור הזה תכירו את הכלי שכל מפתח Unity משתמש בו כל היום: **המחלקה** (class).

## מהי מחלקה?

**מחלקה** היא תבנית לסוג של דבר. היא מתארת אילו נתונים יש לדבר (**שדות**, fields) ומה הוא יכול לעשות (**מתודות**, methods). **אובייקט** (object) הוא דבר אחד ממשי שנוצר מהתבנית. מחלקה אחת, `Player`, יכולה ליצור כמה שחקנים שתרצו, לכל אחד מיקום משלו.

```csharp
class Player
{
    public int x;          // field: data stored inside the object
    public int speed;

    public void Update()   // method: something the object can do
    {
        x += speed;
    }
}
```

יוצרים אובייקט עם `new`, ופונים לפנימיות שלו עם נקודה:

```csharp
Player p = new Player();
p.speed = 3;
p.Update();
Console.WriteLine(p.x);   // prints: 3
```

## שדות וגישה

- `public` פירושו שקוד מחוץ למחלקה (כמו `Main`) רשאי להשתמש בו. בלי מציין גישה, חבר הוא `private`, ולכן רק המחלקה עצמה יכולה לגעת בו. בתרגיל, `x` הוא public (כדי ש-`Main` תוכל להדפיס אותו) ואילו `tint` הוא private.
- `const int Size = 20;` הוא קבוע שמשותף לכל השחקנים.
- שדות מחזיקים את **המצב** של האובייקט. מתודות משתמשות בשדות ישירות, כמו ב-`x += speed;`.

## הבנאי

כשכותבים `new Player(50, 60, 3, ...)` המחלקה צריכה לדעת את ערכי ההתחלה. **בנאי** (constructor) הוא מתודה מיוחדת עם **אותו שם כמו המחלקה** וללא טיפוס החזרה. הוא רץ פעם אחת, בדיוק כשהאובייקט נוצר:

```csharp
public Player(int x, int y, int speed)
{
    this.x = x;
    this.y = y;
    this.speed = speed;
}
```

כאן לפרמטרים ולשדות יש אותו שם. בתוך הבנאי `x` רגיל פירושו הפרמטר (הקרוב ביותר), ולכן `this.x` הוא הדרך לומר "השדה `x` של האובייקט הזה עצמו". `this` פירושו "האובייקט שעליו אני רץ".

## Update ו-Draw

ב-Unity לכל אובייקט משחק יש מתודת `Update()` שהמנוע קורא לה פעם בפריים; אנחנו מעתיקים את הרעיון ומוסיפים מתודת `Draw()`. לולאת המשחק נהיית אז קצרה להפליא, כי כל אובייקט דואג לעצמו:

```csharp
while (Engine.Running())
{
    p1.Update();
    p2.Update();

    Engine.Clear(Color.Dark);
    p1.Draw();
    p2.Draw();
    Engine.Present();
}
```

שני שחקנים עם `speed` שונה ומקשים שונים, שנבנו ממחלקה אחת. לחצו על המקשים בלשונית הקלט: כל ריבוע מקשיב למקשים שלו וזז במהירות שלו.

## ערכים שאפשר להעביר הלאה

שדות לא חייבים להיות מספרים. בתרגיל `Color tint` ו-`Key leftKey` הם גם שדות, ולכן כל שחקן זוכר באיזה צבע הוא ואיזה מקש מזיז אותו.

> **שימו לב:**
> - אם שוכחים `new`: `Player p; p.Update();` נותן `error CS0165: Use of unassigned local variable 'p'`.
> - אם שוכחים `this.` בבנאי, כשלפרמטר ולשדה יש אותו שם: `x = x;` פשוט מבצעת השמה של הפרמטר לעצמו (המהדר מזהיר CS1717) והשדה נשאר 0.
> - קריאה לשדה פרטי מבחוץ: `p1.tint` נותן `error CS0122: 'Player.tint' is inaccessible due to its protection level`.
> - אם נותנים לבנאי טיפוס החזרה (`public void Player(...)`) הוא הופך למתודה רגילה, ו-`new Player(...)` נכשלת עם `error CS1729: 'Player' does not contain a constructor that takes 6 arguments`.

## להמשיך הלאה

הוסיפו שחקן שלישי שמשתמש ב-`Key.Z` וב-`Key.X`. אתם צריכים רק שורה חדשה אחת ב-`Main` בשבילו, ועוד קריאות ל-`Update()` ול-`Draw()` שלו.

> **תורכם:** השלימו את הבנאי (העתיקו כל פרמטר לשדה שלו עם `this.`), גרמו ל-`Update()` לזוז שמאלה כשמחזיקים את `leftKey`, ועשו clamp ל-`x` בין 0 ל-`Engine.Width - Size`. שני השחקנים אמורים להסתיים ב-`p1 x: 140` וב-`p2 x: 100`.
