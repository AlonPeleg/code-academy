הגיע הזמן לחבר הכול. בפרויקט הגמר הזה תבנו **משחק בריחה מבלוקים נופלים** קטן: בלוקים אדומים נופלים, אתם מחליקים שמאלה וימינה כדי להתחמק מהם, כוכבים צהובים נותנים נקודות בונוס, ויש לכם שלושה חיים. הרעיונות החדשים הם **ירושה** (inheritance) ו**פולימורפיזם** (polymorphism), עמוד השדרה של `GameObject` ו-`MonoBehaviour` ב-Unity.

## מחלקת בסיס אחת, הרבה סוגי אובייקטים

לשחקן, לבלוקים ולכוכבים יש מיקום, גודל, דרך להתעדכן ודרך להיצייר. לכתוב את זה שלוש פעמים זה הדרך שבה באגים מתרבים. לכן כותבים את זה פעם אחת במחלקת בסיס ונותנים לאחרים **לרשת** אותה:

```csharp
abstract class GameObject
{
    public int X, Y, Width, Height;
    public bool Dead;

    public abstract void Update(GameState state);
    public abstract void Draw();
    public virtual void OnTouch(GameState state) { }

    public bool Overlaps(GameObject o) { /* rectangle test */ }
}
```

שלוש מילות מפתח חשובות:

* `abstract class` פירושו "אי אפשר ליצור GameObject רגיל, זו רק תבנית למחלקות יורשות".
* למתודות `abstract` אין גוף: כל מחלקה יורשת **חייבת** לספק אחד (`override`). שוכחים אחת ומקבלים `error CS0534: 'Star' does not implement inherited abstract member 'GameObject.Update(GameState)'`.
* למתודות `virtual` יש גוף ברירת מחדל שמחלקות יורשות **יכולות** להחליף. `OnTouch` לא עושה כלום כברירת מחדל, ולכן `Player` לא צריכה להזכיר אותה.

מחלקה יורשת נכתבת `class Block : GameObject` וכל מתודה שהיא מחליפה אומרת `override`:

```csharp
class Star : GameObject
{
    public override void Update(GameState state) { Y += 3; }
    public override void OnTouch(GameState state) { state.Score += 5; Dead = true; }
}
```

`Star` מקבלת בחינם את `X`, ‏`Y`, ‏`Dead` ו-`Overlaps`.

## פולימורפיזם: רשימה אחת, לולאה אחת

מכיוון ש-`Block` *היא* `GameObject`, אפשר לשמור כל סוג ב-`List<GameObject>` אחת ולהתייחס לכולם אותו דבר:

```csharp
foreach (GameObject o in objects)
{
    o.Update(state);
    if (!o.Dead && o.Overlaps(player)) o.OnTouch(state);
}
```

הלולאה לא יודעת אם `o` הוא בלוק או כוכב. בזמן ריצה C# קוראת ל-`Update` הנכון ול-`OnTouch` הנכון: בלוק עולה בחיים, כוכב מוסיף חמש נקודות. זה פולימורפיזם, והוא אומר שהוספת סוג אובייקט חדש (למשל בונוס מגן) דורשת מחלקה חדשה ושורת `Add` אחת, אבל **אפס שינויים בלולאה**.

## מצב משותף, דגלי מוות וניקוי

החיים והניקוד נמצאים באובייקט קטן בשם `GameState` שמועבר ל-`Update` ול-`OnTouch`, כך שאובייקטים יכולים לשנות את הניקוד בלי משתנים גלובליים. אובייקטים אף פעם לא מסירים את עצמם מהרשימה. הם קובעים `Dead = true`, ואחרי הלולאה קריאה אחת עושה את הניקוי:

```csharp
objects.RemoveAll(o => o.Dead);
```

זה אותו כלל "קודם מסמנים, אחר כך מסירים" כמו בשיעור הכדורים: שינוי רשימה בתוך ה-`foreach` שלה זורק חריגה (exception).

## "אקראיות" דטרמיניסטית

הקלטה חייבת להיות ניתנת לחזרה, ולכן שום דבר אינו באמת אקראי. כל 20 פריימים מופיע אובייקט חדש ב-`x = (spawned * 97 + 30) % 290`. המספרים קופצים על המסך בצורה לא סדירה, ובכל זאת אותו משחק תמיד מייצר אותה תבנית. כל אובייקט רביעי הוא כוכב, והשאר הם בלוקים שנופלים במהירויות 4, 5 או 6 פיקסלים לפריים. בלוק שנופל מהתחתית "נעקף" ושווה נקודה אחת.

> **שימו לב:**
> - אם שוכחים `override` על `OnTouch`: מקבלים רק `warning CS0114: ... hides inherited member`, והגרסה הריקה של הבסיס רצה, ולכן נגיעה בכוכב לא עושה כלום. תמיד כתבו `public override`.
> - קריאה ל-`new GameObject()` על מחלקה מופשטת: `error CS0144: Cannot create an instance of the abstract class`.
> - בדיקת התנגשויות עם אובייקטים מתים: בלוק שכבר פגע בכם היה עולה בחיים שניים באותו פריים. בגלל זה הלולאה בודקת `!o.Dead`.
> - הסרה מ-`objects` בתוך ה-`foreach`: `InvalidOperationException: Collection was modified`.

## מה ההקלטה עושה

לשונית הקלט (input) מחליקה את הספינה שמאלה, אחר כך ימינה, ושוב שמאלה. הריצו קודם את קוד ההתחלה: הספינה פשוט צפה דרך הכול, ולכן היא שומרת על 3 חיים ומקבלת נקודות רק על בלוקים שנעקפו. במשחק המוגמר היא צריכה לאבד שני חיים ולקבל 28 נקודות. אם `Lives` מגיע ל-0, הלולאה מסתיימת מוקדם בזכות `while (Engine.Running() && state.Lives > 0)`.

## להמשיך הלאה

הוסיפו מחלקה יורשת שלישית, `Shield : GameObject`, שמחזירה חיים. הגבירו את מהירות הבלוקים לפי הניקוד. או הוסיפו מחלקה `Bullet` והפכו את זה למשחק יריות בחלל: אותה רשימה ואותה לולאה יספיקו.

> **תורכם:** גרמו לאובייקטים להגיב לשחקן. מלאו את `Block.OnTouch` (חיים אחד אובד, הבלוק מת), את `Star.OnTouch` (חמש נקודות, הכוכב מת), ואת בדיקת ההתנגשות בלולאה הראשית (`o.OnTouch(state)` עבור אובייקט חי שחופף לשחקן). התוכנית צריכה להדפיס `score: 28` ו-`lives: 2`.
