השורות של שאילתה חוזרות בלי סדר מובטח. כשהסדר חשוב, למשל בטבלת מובילים או ברשימה של "החדש ביותר קודם", צריך לבקש אותו. השיעור הזה עוסק במיון עם `ORDER BY` ובהשארת הראשונות בלבד עם `LIMIT`.

## ORDER BY

```sql
SELECT name, age
FROM students
ORDER BY age;
```

כיוון ברירת המחדל הוא `ASC` (עולה, ascending): מהקטן לגדול עבור מספרים, מ-A עד Z עבור טקסט. הוסיפו `DESC` (יורד, descending) לקבלת ההפך:

```sql
SELECT name, age
FROM students
ORDER BY age DESC;
```

## מיון לפי כמה עמודות

כששתי שורות בעלות אותו ערך, העמודה הבאה שוברת את השוויון. רשמו את העמודות מופרדות בפסיקים, לכל אחת הכיוון שלה:

```sql
SELECT name, city, age
FROM students
ORDER BY city ASC, age DESC;
```

השורות ממוינות קודם לפי עיר; סטודנטים באותה עיר ממוינים אחר כך מהמבוגר לצעיר.

## LIMIT

`LIMIT n` משאיר רק את *n* השורות הראשונות של התוצאה. בשילוב עם `ORDER BY` הוא עונה על שאלות "N הראשונים":

```sql
SELECT title, credits
FROM courses
ORDER BY credits DESC
LIMIT 2;
```

בלי `ORDER BY`, ל"ראשונות" אין משמעות אמיתית, ולכן תמיד מיינו לפני שאתם מגבילים.

`OFFSET` מדלג קודם על שורות. `LIMIT 3 OFFSET 3` נותן את שורות ארבע עד שש, וכך בונים עמוד 2, 3 וכן הלאה ברשימות באתרים.

הסעיפים חייבים להופיע בסדר הזה, אף על פי שהם מעובדים אחרת בתוך מסד הנתונים:

1. `SELECT`
2. `FROM`

## לאן הולכים ערכי NULL?

ב-SQLite הערך `NULL` נחשב לערך הקטן ביותר, ולכן הוא ממוין ראשון בסדר `ASC` ואחרון בסדר `DESC`. זכרו זאת כשממיינים לפי עמודה עם חורים, כמו `city`.

> **שימו לב:**
> - הצבת `LIMIT` לפני `ORDER BY` גורמת ל-`near "ORDER": syntax error`.
> - פסיק בטעות אחרי `DESC` ב-`ORDER BY` (`ORDER BY age DESC,`) גורם לשגיאת תחביר.
> - `LIMIT 3` לבדו מחזיר שלוש שורות כלשהן שבאות ראשונות, וזה לא "שלושת הראשונים" אמינים.
> - `DESC` חל רק על העמודה שלפניו ישירות: `ORDER BY city, age DESC` ממיין את city בסדר עולה.

> **תורכם:** הציגו את `name` ו-`age` של שלושת הסטודנטים המבוגרים ביותר, המבוגר ביותר ראשון.
