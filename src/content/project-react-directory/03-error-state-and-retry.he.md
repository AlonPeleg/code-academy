שרתים נכשלים: פריסה משתבשת, ה-Wi-Fi נופל, באג מחזיר 500. אפליקציה מקצועית לא משאירה את המשתמשים בוהים ב-"Loading..." לנצח. בשלב הזה תוסיפו מסך שגיאה וכפתור **Retry**, ותלמדו איך לבדוק את המסלול הלא מוצלח בלי לשבור שרת אמיתי.

## איפה אנחנו עומדים

הספרייה טוענת חמישה אנשים מה-API ומציגה הודעת טעינה. אם השרת היה עונה בשגיאה, הקוד היה קורס כשהוא מנסה להתייחס לגוף השגיאה כאל רשימה.

## מה נוסיף, ולמה זה חשוב

מתחילים בודקים רק את המסלול המוצלח. אנשי מקצוע שואלים "מה אם זה ייכשל?" על כל בקשה, כי במוקדם או במאוחר היא תיכשל. נבנה שלושה דברים:

1. **סטטוס** (status) עם שלושה שלבים: `loading`, `error`, `ready`.
2. **מסך שגיאה** שמסביר מה קרה ומציע Retry.
3. **מתג בדיקה**, `FAIL_FIRST_TRY`, שגורם לבקשה הראשונה ללכת אל `/error/500` (שרת התרגול עונה על כל קוד סטטוס לפי דרישה). זה טריק שמפתחים אמיתיים משתמשים בו כל הזמן: שוברים בכוונה בקשה כדי לראות איך המסך מגיב.

## מדריך צעד אחר צעד

**1. מחליפים את `loading` בסטטוס.** שני ערכים בוליאניים כמו `loading` ו-`failed` יכולים לסתור זה את זה ("בטעינה וגם נכשל בו זמנית?"). מחרוזת אחת לא יכולה:

```jsx
const [status, setStatus] = useState('loading'); // 'loading' | 'error' | 'ready'
const [error, setError] = useState('');
const [attempt, setAttempt] = useState(0);
```

**2. בודקים את `res.ok`.** `res.ok` הוא `true` עבור סטטוס 200 עד 299. בכל מקרה אחר זורקים שגיאה, שמדלגת ישר אל `.catch`:

```jsx
fetch(url)
  .then((res) => {
    if (!res.ok) throw new Error('HTTP ' + res.status);
    return res.json();
  })
  .then((data) => { setPeople(data); setStatus('ready'); })
  .catch((err) => { setError(err.message); setStatus('error'); });
```

`.catch` מטפלת גם בכשלי רשת אמיתיים, ולכן מקום אחד מכסה את שני סוגי הבעיות. ההודעה `HTTP 500` היא מה שהמשתמש (ואתם, בדיווח על באג) יקראו.

**3. בוחרים את הכתובת.** המתג בוחר את הכתובת השבורה רק בניסיון הראשון:

```jsx
const url = FAIL_FIRST_TRY && attempt === 0 ? API + '/error/500' : API + '/users';
```

**4. גורמים ל-Retry להריץ שוב את האפקט.** אפקט רץ שוב כשמשהו ברשימת התלויות שלו משתנה. שמנו שם את `attempt`. לחיצה על Retry מגדילה אותו:

```jsx
}, [attempt]);
...
<button onClick={() => setAttempt(attempt + 1)}>Retry</button>
```

בנוסף, קראו ל-`setStatus('loading')` בתחילת האפקט, כדי שהמשתמש יראה התקדמות בניסיון חוזר.

**5. מציגים את שלושת השלבים.** בחרו עם `if / else if / else` לפני ה-`return`, ושמרו את התוצאה במשתנה (`let content;`). זה נקרא טוב יותר מאופרטורים טרנריים מקוננים.

## מה אמורים לראות

העמוד מציג קופסה אדומה `Could not load people: HTTP 500` עם כפתור **Retry**. לחצו על Retry: הניסיון השני משתמש בכתובת האמיתית וחמשת האנשים מופיעים. הבודק רואה את מסך השגיאה, כי הוא מסתכל על העמוד לפני שמישהו לוחץ. כדי לכבות את הבדיקה, שנו את `FAIL_FIRST_TRY` ל-`false`.

> **שימו לב:**
> - בלי `if (!res.ok)`, תשובת 500 עם גוף שגיאה מטופלת כנתונים, ו-`people.map is not a function` מקריסה את העמוד.
> - Retry שרק קורא שוב לפונקציה הישנה בלי לשנות state אולי לא יגרום לשום רינדור מחדש. שינוי של `attempt` הוא מה שמפעיל את האפקט.
> - אם שוכחים את `[attempt]` במערך התלויות, Retry לא עושה כלום.
> - במוצר אמיתי לא מציגים למשתמשים רגילים שגיאות טכניות גולמיות. כאן עושים את זה כי אתם המפתחים.

> **תורכם:** עקבו אחרי ארבע הערות ה-`TODO`: השתמשו ב-state בשם `status`, הוסיפו `error` ו-`attempt`, בנו את הכתובת בעזרת המתג, בדקו את `res.ok`, הוסיפו `.catch`, השתמשו ב-`[attempt]` כתלויות, והציגו טעינה, שגיאה ותוכן מוכן. העמוד חייב להציג `Could not load people: HTTP 500` וכפתור Retry בתוך `div.error`.
