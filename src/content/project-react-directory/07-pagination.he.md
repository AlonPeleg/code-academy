חמישה אנשים נכנסים במסך אחד. חמישים אלף לא. כל רשימה רצינית בכל אפליקציה, מהאימייל ועד חנות מקוונת, היא **מעומדת** (paginated): השרת שולח פרוסה אחת בכל פעם. בשלב הזה תוסיפו כפתורי הקודם והבא, ותלמדו לקרוא מידע שחי ב**כותרות** (headers) של HTTP ולא בגוף.

## איפה אנחנו עומדים

האפליקציה טוענת את כל האנשים בבת אחת, תומכת בחיפוש, בבחירה עם משימות ובעריכת העיר עם PATCH אחרי התחברות.

## מה נוסיף, ולמה זה חשוב

ל-API של התרגול יש שני פרמטרים של שאילתה לחיתוך: `_page` (איזה דף, מתחילים מ-1) ו-`_limit` (כמה בכל דף). עם `_limit=2` חמשת האנשים יוצרים שלושה דפים: `2 + 2 + 1`. התשובה נושאת גם כותרת `X-Total-Count: 5`. בלעדיה לא יכולנו לדעת אם יש דף הבא. שרתים שמים **מטא-נתונים** (metadata) כאלה בכותרות כדי שהגוף יישאר רשימה פשוטה.

## הדרכה שלב אחר שלב

**1. מבקשים דף.** בנו את הכתובת מה-state:

```jsx
API + '/users?_page=' + page + '&_limit=' + PAGE_SIZE
```

`?` מתחיל את מחרוזת השאילתה, ו-`&` מפריד בין פרמטרים. מספר הדף הוא **state**, ולכן שינוי שלו חייב להפעיל בקשה חדשה. בשביל זה קיים מערך התלויות: `[attempt, page]`.

**2. קוראים את הכותרת.** לאובייקט התשובה יש `headers`. `get` מוצאת כותרת לפי שם, בלי להבדיל בין אותיות גדולות לקטנות, ותמיד נותנת טקסט (או `null`):

```jsx
const count = Number(res.headers.get('X-Total-Count'));
const data = await res.json();
return { data: data, count: count };
```

אנחנו מחזירים את שני הערכים מה-`.then` הראשון, וה-`.then` הבא מקבל אותם ב-`result.data` וב-`result.count`. (ה-callback הוא `async` כדי שנוכל להשתמש בו ב-`await`.)

**3. מחשבים את הדפים.** עם 5 אנשים וגודל דף 2:

```jsx
const totalPages = Math.max(1, Math.ceil(total / PAGE_SIZE)); // Math.ceil(2.5) is 3
```

`Math.ceil` מעגלת כלפי מעלה, כי גם דף אחרון חלקי הוא דף. `Math.max(1, ...)` שומרת על מינימום 1 כל עוד הסך הכול עדיין 0.

**4. הכפתורים.** הקודם חוזר אחורה, הבא מתקדם. השביתו אותם בקצוות במקום להסתיר, כדי שהפריסה לא תקפוץ:

```jsx
<button disabled={page <= 1} onClick={() => goToPage(page - 1)}>Previous</button>
<button disabled={page >= totalPages} onClick={() => goToPage(page + 1)}>Next</button>
```

`goToPage` גם מנקה את הבחירה, כי ייתכן שהאדם שנבחר לא נמצא בדף החדש. (אפליקציה גדולה יותר הייתה מביאה אותו לפי מזהה עם `GET /users/:id`.)

**5. באג שתפגשו.** ה-effect של ההדגמה שלנו רץ כשה-`status` נהיה `'ready'`. פתיחת דף 3 הופכת את הסטטוס ל-`'ready'` שוב, ולכן ההדגמה הייתה שומרת עיר שוב! **ref** פותר את זה. `useRef(false)` נותנת לכם קופסה, `demoDone.current`, ששורדת רינדורים אבל לא גורמת לרינדור מחדש כשמשנים אותה. מושלם לדגלים של "האם זה כבר קרה?".

**6. חיפוש ודפים.** תיבת החיפוש שלנו עדיין מסננת רק את האנשים בדף הנוכחי, כי הנתונים שבזיכרון הם הדף הנוכחי. בספר כתובות אמיתי הייתם שולחים את החיפוש לשרת (למשל `?q=lov`) כדי שיחפש בכולם. זו הרחבה טובה להמשך.

## מה אמורים לראות

האפליקציה נפתחת בדף 2: Alan Turing ו-Katherine Johnson. Alan נבחר, העיר שלו נשמרה כ-Cambridge, והמשימות שלו מציגות `1 of 2 done`. מד הדפים מציג `Page 2 of 3`. לחצו על הקודם או על הבא כדי לנוע בין הדפים.

> **שימו לב:**
> - `_page` מתחיל ב-1, לא ב-0. דף 0 לא נותן לכם שום דבר שימושי.
> - `res.headers.get(...)` מחזירה טקסט. בלי `Number(...)` החישוב `total / PAGE_SIZE` עדיין עובד, אבל השוואות כמו `page >= total` היו משוות מספר עם טקסט.
> - שכחתם את `page` במערך התלויות: הכפתורים משנים את המספר, אבל שום דבר לא נשלח.
> - הצגת מספרי דפים שלא קיימים: תמיד בדקו מול `totalPages`.
> - דפדפנים חושפים רק חלק מהכותרות לסקריפטים מאתרים אחרים (CORS). שרת אמיתי חייב לרשום את `X-Total-Count` ב-`Access-Control-Expose-Headers`; שרת התרגול עושה את זה בשבילכם.
