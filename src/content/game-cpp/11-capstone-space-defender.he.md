זה פרויקט הסיום: משחק יריות חלל קטן שמשתמש כמעט בכל מה שלמדתם במסלול. יש לכם ספינה, כדורים, אויבים נופלים, ניקוד ושלושה חיים. העבודה כאן היא **ארגון** של תוכנית גדולה יותר בעזרת מחלקה (class) כדי שתישאר קריאה.

## חלקים שאתם כבר מכירים

| רעיון | מתוך | שימוש כאן |
|---|---|---|
| מחלקות | שיעור 4 | `Game`, שמחזיקה את כל המצב |
| וקטורים של אובייקטים | שיעור 5 | כדורים ואויבים שבאים והולכים |
| בדיקת חפיפה | שיעור 6 | `Rect::overlaps` |
| key_down / key_pressed | שיעורים 2 ו-3 | הגה וירי |
| מהירות וקפיצה | Pong | כדורים למעלה ב-8, אויבים למטה ב-2 |
| למדות ואלגוריתמים | Breakout | הטאטוא שמסיר דברים מתים |

## טיפוסים קטנים, מחלקה גדולה אחת

ל-`Rect` יש יכולת לחפוף למלבן אחר, ו-`Thing` הוא `Rect` ועוד דגל `dead`:

```cpp
struct Thing {
    Rect box;
    bool dead = false;
};
```

המחלקה `Game` מחזיקה הכול ומציעה שלוש פעולות ברורות: `step()` מעדכנת את העולם, `draw()` מציגה אותו, וגטרים קטנים נותנים את התוצאה:

```cpp
class Game {
public:
    void step();
    void draw() const;
    bool game_over() const { return lives_ <= 0; }
private:
    Rect player_{150, 215, 20, 12};
    std::vector<Thing> bullets_, enemies_;
    int score_ = 0, lives_ = 3, lane_ = 0;
};
```

`main` נשארת קטנטנה: `if (!game.game_over()) game.step(); game.draw();`. הפרדת **העדכון** מ**הציור** היא ההרגל ששומר על משחקים אמיתיים בני-ניהול. `draw()` היא `const`, הבטחה שציור אף פעם לא משנה את המשחק.

## סימון כמתים, ואז טאטוא

מחיקה מוקטור בזמן מעבר עליו היא מסוכנת, ולכן אנחנו משתמשים בכלל דו-שלבי: במהלך הפריים דברים רק **מסומנים** `dead = true`. בסוף הפריים למדה אחת מסירה את כולם:

```cpp
auto sweep = [](std::vector<Thing>& v) {
    v.erase(std::remove_if(v.begin(), v.end(), [](const Thing& t) { return t.dead; }), v.end());
};
sweep(bullets_);
sweep(enemies_);
```

למדה שמקבלת וקטור בהפניה עובדת עבור שתי הרשימות: אותו קוד, שנכתב פעם אחת. לסימון קודם יש בונוס: כדור שהרגע פגע באויב הוא `dead`, ולכן בדיקה שנייה באותו פריים מתעלמת ממנו.

## הגבלות ואויבים מתוסרטים

`bullets_.size() < MAX_BULLETS` שומרת על לכל היותר 4 כדורים באוויר, כלל ארקייד קלאסי שמונע מכם פשוט להחזיק את האש לחוץ. אין `rand()`: הקלטה צריכה להישמע שוב בצורה זהה. אויבים נוצרים ב-`LANES[lane_++ % 8]`, רשימה קבועה של מיקומי x, וה-`%` מחזיר את האינדקס ל-0 אחרי האחרון. טבלה חוזרת היא דרך טובה לבדוק משחק.

## שתי לולאות של התנגשות

- **ירי:** range-for כפול על כדורים ואויבים. אם אף אחד מהם לא מת והתיבות שלהם חופפות, מסמנים את שניהם כמתים ומוסיפים 10 נקודות.
- **נזק:** כל אויב שאינו מת ושחופף ל-`player_` או נפל מתחת למסך (`box.y > SCREEN_H`) מסומן כמת וגורם לאובדן חיים. לתת לאויב לברוח כואב בדיוק כמו להיפגע.

```cpp
for (auto& b : bullets_)
    for (auto& e : enemies_)
        if (!b.dead && !e.dead && b.box.overlaps(e.box)) { b.dead = e.dead = true; score_ += 10; }
```

`b.dead = e.dead = true;` מבצעת השמה מימין לשמאל: קודם `e.dead`, ואז `b.dead`.

> **שימו לב:**
> - הורדת ההפניה: `for (auto b : bullets_)` מסמנת **עותק** כמת, ושום דבר אף פעם לא מוסר.
> - קריאה ל-`erase` בתוך לולאות ה-range-for מבטלת את תקפות האיטרטורים; שמרו על הסימון והטאטוא בשני שלבים.
> - אם שוכחים `!e.dead` בלולאת הנזק: אויב שהרגע נורה עדיין גורם לאובדן חיים.
> - `static constexpr int LANES[8]` בתוך מחלקה בסדר ב-C++17. ב-C++11 או 14 אפשר לקבל `undefined reference to Game::LANES` בזמן הקישור (link).

## להמשיך הלאה

הפכו את האויבים למהירים יותר אחרי כל 5 חיסולים, הוסיפו סוג אויב שני ששווה 30 נקודות, או הציגו את החיים כספינות קטנות. נסו לשנות את `MAX_BULLETS` וערכו את קלט השחקן (Player input) כדי לראות איך הניקוד שלכם משתנה.

> **תורכם:** ב-`Game::step`, הוסיפו (1) את לולאות הירי: כל כדור שחופף לאויב (שניהם לא מתים) מסמן את שניהם כמתים ומוסיף 10 ל-`score_`; (2) את לולאת הנזק: אויב שאינו מת וחופף ל-`player_` או שיש לו `box.y > SCREEN_H` מסומן כמת וגורם לאובדן חיים אחד (`lives_--`). עם המקשים שניתנו התוכנית אמורה להדפיס `score: 110, lives: 2`.
