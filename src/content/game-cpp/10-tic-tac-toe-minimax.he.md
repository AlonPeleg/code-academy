איקס עיגול הוא משחק קטן מספיק כדי שמחשב יוכל לשחק אותו **בצורה מושלמת**. בשיעור הזה תכתבו את אלגוריתם **minimax** המפורסם: פונקציה שקוראת לעצמה כדי להסתכל על כל העתיד האפשרי של המשחק ולבחור את המהלך הטוב ביותר. בדרך תכירו את `std::array` וכמה אלגוריתמים סטנדרטיים.

## הלוח

```cpp
using Cells = std::array<char, 9>;
Cells board;
board.fill(' ');
//  0 | 1 | 2
//  3 | 4 | 5
//  6 | 7 | 8
```

`std::array<char, 9>` הוא מערך (array) בגודל קבוע שיודע את הגודל של עצמו, אפשר להעביר אותו בהפניה, והוא עובד עם לולאות range-for ועם אלגוריתמים סטנדרטיים. `using Cells = ...` נותן לו שם קצר. `' '` הוא תא ריק, `'X'` הוא האדם ו-`'O'` הוא המחשב.

הסמן זז עם מקשי החצים, ו-SPACE מניח X בתא שנבחר אם הוא ריק. אחר כך המחשב עונה מיד.

## מי ניצח?

יש רק שמונה קווים מנצחים. אנחנו כותבים אותם כנתונים ועוברים עליהם בלולאה:

```cpp
static const int LINES[8][3] = {
    {0, 1, 2}, {3, 4, 5}, {6, 7, 8},      // rows
    {0, 3, 6}, {1, 4, 7}, {2, 5, 8},      // columns
    {0, 4, 8}, {2, 4, 6}                  // diagonals
};
for (const auto& line : LINES) { /* line[0], line[1], line[2] are cell numbers */ }
```

קו הוא מנצח כשהתא הראשון שלו אינו ריק ושלושת התאים מכילים את אותו תו. עבור "האם הלוח מלא?" אלגוריתם סטנדרטי אומר את זה בשורה אחת: `std::none_of(b.begin(), b.end(), [](char c) { return c == ' '; })` ("אף תא אינו ריק").

## הרעיון של minimax

דמיינו שאתם המחשב. לכל תא ריק שאפשר לקחת, שאלו: "אם אשחק כאן, איך המשחק יסתיים אם **שנינו** נשחק בצורה מושלמת מאותו רגע?" כדי לענות צריך לדמיין את התגובה של היריב, אחר כך את המהלך הבא שלכם, וכן הלאה עד שמישהו מנצח או שהלוח מלא. אז בוחרים את התא עם התוצאה הטובה ביותר.

כל משחק שהסתיים מקבל **ציון מנקודת המבט של המחשב**: `+1` אם O מנצח, `-1` אם X מנצח, `0` לתיקו. הכלל הוא אז:

- בתורו של O לוקחים את המהלך עם הציון **הגבוה ביותר** (O ממקסם).
- בתורו של X מניחים ש-X לוקח את המהלך עם הציון **הנמוך ביותר** (X ממזער: מה שטוב ל-X רע ל-O).

מכאן השם **מיני**מקס. פונקציה אחת עושה את שתי המשימות:

```cpp
int minimax(Cells& b, bool o_to_move) {
    char w = winner(b);
    if (w == 'O') return 1;           // base cases: the game is over
    if (w == 'X') return -1;
    if (is_full(b)) return 0;

    int best = o_to_move ? -2 : 2;    // worse than any real score
    for (auto& cell : b) {
        if (cell != ' ') continue;
        cell = o_to_move ? 'O' : 'X';             // try the move...
        int score = minimax(b, !o_to_move);       // ...see how it ends...
        cell = ' ';                               // ...and take it back
        best = o_to_move ? std::max(best, score) : std::min(best, score);
    }
    return best;
}
```

קראו לאט. **מקרי הבסיס** עוצרים את הרקורסיה (recursion); בלעדיהם הפונקציה הייתה קוראת לעצמה לנצח עד שהתוכנית קורסת (גלישת מחסנית, stack overflow). התבנית **נסה, קרא רקורסיבית, בטל** היא הלב של כל אלגוריתם חיפוש: משנים את הלוח, חוקרים, ואז משחזרים אותו בדיוק כדי שהתא הבא ינוסה על אותו לוח. `for (auto& cell : b)` נותן **הפניה** לכל תא, ולכן השמה ל-`cell` משנה את הלוח האמיתי, ו-`Cells& b` (פרמטר הפניה) מבטיח שיש רק לוח אחד.

`best_move` עושה אחר כך את הרמה העליונה של אותה לולאה עבור המהלך של O וזוכרת את התא עם הציון הטוב ביותר. בתיקו היא שומרת את התא **הראשון** שנמצא, ולכן התוצאה תמיד זהה. הדטרמיניזם הזה נדרש בהשמעה חוזרת.

## כמה עבודה זה?

מלוח ריק יש בערך 550,000 מצבים. מחשב מבקר בהם בכמה אלפיות שנייה. בשחמט אותו רעיון דורש גיזום חכם (alpha-beta) כי המספרים מתפוצצים.

> **שימו לב:**
> - אם שוכחים את `cell = ' '` (הביטול): הלוח מתמלא במהלכי רפאים וה-AI משחק שטויות.
> - מקרי בסיס חסרים: `Segmentation fault` אחרי שטף של קריאות מקוננות.
> - התחלת `best` ב-`0` במקום ב-`-2` / `2`: ציון אמיתי של `-1` לעולם לא ינצח אותו, ולכן ה-AI לא רואה הפסדים כפויים.
> - העברת הלוח **לפי ערך** (`Cells b`) מעתיקה אותו. התוכנית עדיין עובדת אבל היא איטית יותר, ולשורת הביטול שלכם אין השפעה גלויה על הקורא. השתמשו בהפניה כשרוצים לשנות את המקור.

## להמשיך הלאה

עם המקשים שניתנו השחקן טועה והמחשב המושלם מעניש אותו. ערכו את קלט השחקן (Player input) כדי לנסות סדרי תאים אחרים; לא משנה מה תעשו, המקסימום שתשיגו הוא `winner: draw`. הרחבה נחמדה היא להעדיף ניצחונות מהירים על ידי החזרת `10 - depth`.

> **תורכם:** כתבו את שני החלקים החסרים. (1) `winner` עוברת בלולאה על 8 ה-`LINES` ומחזירה את הסימן של קו שהושלם, אחרת 0. (2) `minimax` מחזירה 1 / -1 / 0 עבור משחקים שהסתיימו, אחרת מנסה כל תא ריק, קוראת רקורסיבית עם `!o_to_move`, מבטלת את המהלך, ושומרת את הציון הגבוה ביותר (O) או הנמוך ביותר (X). עם המקשים שניתנו התוכנית אמורה להדפיס `winner: O`.
