עד עכשיו השחקן היה רק כמה משתנים רופפים, `x` ו-`y`, ליד הלולאה. C++ מאפשרת יותר: **מחלקה** (class) אורזת את הנתונים *ואת* הפונקציות שעובדות עליהם ליחידה אחת. בשיעור הזה תבנו מחלקה בשם `Player` עם בנאי, מתודה `update()` ומתודה `draw()`.

## האנטומיה של מחלקה

```cpp
class Player {
public:
    Player(int start_x, int start_y) : x_(start_x), y_(start_y) {}

    void update() { /* react to the keys */ }
    void draw() const { /* paint the player */ }

    int x() const { return x_; }

private:
    int x_ = 0;
    int y_ = 0;
};
```

חלק אחר חלק:

- `class Player { ... };` מגדירה טיפוס חדש. **אל תשכחו את ה-`;` אחרי הסוגר הסוגר.**
- חברים של `public:` אפשר להשתמש בהם מכל מקום. חברים של `private:` אפשר לגעת בהם רק מהפונקציות של המחלקה עצמה. שמירת הנתונים פרטיים אומרת שקוד אחר לא יכול להכניס את השחקן למצב שבור, למשל על ידי קביעת `x_` לערך חסר היגיון. אנחנו מסיימים שמות פרטיים בקו תחתון (`x_`) כהרגל נפוץ, ולכן `x_` הוא השדה ו-`x()` הוא ה-getter שמאפשר לקרוא אותו.
- פונקציות בתוך מחלקה נקראות **מתודות** (methods). בתוך מתודה אפשר להשתמש בחברים ישירות, בלי `player.`.
- `const` אחרי ה-`()` של מתודה הוא הבטחה שהמתודה לא תשנה את האובייקט. `draw()` רק קוראת, ולכן היא `const`. המהדר מתלונן אם מפרים את ההבטחה.

## הבנאי

**בנאי** הוא מתודה מיוחדת עם **אותו שם כמו המחלקה** ו**בלי טיפוס החזרה**. הוא רץ אוטומטית כשאובייקט נוצר:

```cpp
Player player(150, 110);    // calls Player(150, 110)
```

החלק אחרי הנקודתיים, `: x_(start_x), y_(start_y)`, הוא **רשימת האתחול** (initializer list). היא קובעת כל חבר ברגע הלידה של האובייקט. זו הדרך האידיומטית ב-C++ והיא רצה לפני גוף ה-`{ }`. הגוף כאן ריק, `{}`, כי אין עוד מה לעשות.

אפשר גם לתת לחברים ערכי ברירת מחדל במחלקה, כמו `int size_ = 20;`. חברים שהבנאי לא מזכיר משתמשים בברירות המחדל האלה.

## שימוש באובייקט

```cpp
Player player(150, 110);

while (engine_running()) {
    player.update();          // the dot calls a method on this object

    engine_clear(RGB_DARK);
    player.draw();
    engine_present();
}

std::cout << player.x() << std::endl;    // 150 at the start
```

השוו לגרסת ה-C: `player_update(&player)` הפכה ל-`player.update()`. בלי מצביעים, והנתונים חיים יחד עם הקוד שמבין אותם. אפשר ליצור עוד אובייקטים מאותה מחלקה: `Player other(10, 10);` ולכל אחד יש `x_` ו-`y_` משלו.

> **שימו לב:**
> - `error: 'int Player::x_' is private within this context`: ניסיתם `player.x_` מבחוץ. השתמשו ב-getter, `player.x()`.
> - `;` חסרה אחרי הסוגר הסוגר של המחלקה נותנת `expected ';' after class definition`.
> - כתיבת `Player player();` מצהירה על *פונקציה* בשם player, לא על אובייקט (ה-"most vexing parse"). כתבו `Player player(150, 110);` או `Player player{150, 110};`.
> - אם שוכחים לקבוע חבר בבנאי ולא נותנים לו ברירת מחדל, הוא מחזיק ערך אקראי שנשאר בזיכרון. תמיד אתחלו את החברים שלכם.

## להמשיך הלאה

צרו `Player` שני עם מיקום התחלה אחר. שניהם נשלטים באותם מקשים, ולכן הם זזים יחד. אחר כך הוסיפו חבר `color_` שהבנאי מקבל, כך שכל שחקן יוכל להיראות אחרת. (זהירות: צבעים כמו `RGB_RED` מתרחבים לשלושה מספרים, לכן שמרו אותם כשלושה `int`-ים.)

> **תורכם:** כתבו את הבנאי כך שישמור את `start_x` ו-`start_y` ב-`x_` וב-`y_`, ואז כתבו את ארבע שורות מקשי החצים ב-`update()` בעזרת `speed_`. התוכנית אמורה להדפיס `final: 260, 130`.
