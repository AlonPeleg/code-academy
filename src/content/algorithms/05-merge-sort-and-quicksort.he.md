המיונים הפשוטים מהשיעור הקודם לוקחים בערך `n * n` צעדים. עבור מיליון פריטים זה טריליון צעדים, איטי מדי בהרבה. השיעור הזה מציג את שני האלגוריתמים המפורסמים שעושים את זה בערך ב-`n * log n` צעדים, בעזרת אסטרטגיה חזקה שנקראת **הפרד ומשול** (divide and conquer), וטכניקה שהולכת איתה: **רקורסיה** (recursion).

## רקורסיה בשתי דקות

פונקציה (function) **רקורסיבית** היא פונקציה שקוראת לעצמה, על גרסה קטנה יותר של הבעיה. היא צריכה שני מרכיבים:

1. **מקרה בסיס** (base case): קלט קטן כל כך שהתשובה ברורה מאליה, ושם הפונקציה עוצרת.
2. **מקרה רקורסיבי**: מפרקים את הקלט לחלקים קטנים יותר וקוראים לאותה פונקציה עליהם.

```python
def total(numbers):
    if not numbers:                  # base case: empty list
        return 0
    return numbers[0] + total(numbers[1:])   # smaller problem

print(total([1, 2, 3, 4]))   # prints: 10
```

בלי מקרה בסיס הפונקציה תקרא לעצמה לנצח, עד ש-Python תעצור אותה עם `RecursionError: maximum recursion depth exceeded`.

## הפרד ומשול

האסטרטגיה כוללת שלושה שלבים: **מחלקים** את הבעיה לחלקים קטנים יותר, **פותרים** כל חלק (בדרך כלל ברקורסיה), ואז **משלבים** את התוצאות.

## מיון מיזוג

מיון מיזוג (merge sort) מחלק את הרשימה לשניים, ממיין כל חצי ברקורסיה, ו**ממזג** את שני החצאים הממוינים.

```text
              [38, 27, 43, 3]
             /               \
        [38, 27]           [43, 3]
        /     \            /     \
     [38]    [27]       [43]     [3]       <- single items are sorted
        \     /            \     /
        [27, 38]           [3, 43]         <- merge
             \               /
           [3, 27, 38, 43]                 <- merge
```

החלק החכם הוא `merge`: קל לשלב שתי רשימות ממוינות. שומרים אצבע בתחילת כל רשימה, תמיד לוקחים את הפריט הקדמי הקטן יותר, ומזיזים את האצבע. נוגעים בכל פריט פעם אחת, ולכן מיזוג עולה O(n). חצייה חוזרת של רשימה נותנת בערך log n רמות, וכל רמה ממזגת בסך הכול n פריטים, ולכן העלות היא **O(n log n)**. עבור מיליון פריטים זה בערך 20 מיליון צעדים במקום טריליון.

```python
def merge_sort(items):
    if len(items) <= 1:
        return items                       # base case
    mid = len(items) // 2
    left = merge_sort(items[:mid])         # conquer the left half
    right = merge_sort(items[mid:])        # conquer the right half
    return merge(left, right)              # combine
```

מיון מיזוג הוא **יציב** (stable), כלומר פריטים שווים שומרים על הסדר המקורי שלהם, והוא תמיד O(n log n), אבל הוא משתמש בזיכרון נוסף עבור הרשימות החדשות.

## Quicksort

Quicksort מחלק אחרת. בוחרים פריט אחד, **הציר** (pivot). שמים כל מה שקטן ממנו משמאלו וכל מה שגדול ממנו מימינו. הציר נמצא עכשיו במקומו הסופי. ממיינים את שני הצדדים ברקורסיה.

```text
[38, 27, 43, 3, 9, 82, 10]    pivot = 38
smaller: [27, 3, 9, 10]       bigger: [43, 82]
result:  quick_sort(smaller) + [38] + quick_sort(bigger)
```

```python
def quick_sort(items):
    if len(items) <= 1:
        return items
    pivot = items[0]
    smaller = [x for x in items[1:] if x < pivot]
    bigger = [x for x in items[1:] if x >= pivot]
    return quick_sort(smaller) + [pivot] + quick_sort(bigger)
```

עם ציר סביר שני הצדדים כמעט שווים, ולכן העומק הוא log n והעלות היא **O(n log n)**. עם ציר גרוע הביצועים יורדים ל-**O(n בריבוע)**. בחירה בפריט הראשון כציר גרועה ברשימה שכבר ממוינת: אין פריט קטן יותר, ולכן כל קריאה מסירה רק פריט אחד. מימושים אמיתיים בוחרים פריט אקראי או את החציוני מבין שלושה כדי להימנע מזה. האלגוריתם מהיר בפועל וממיין במקום, אבל הוא לא יציב.

## איזה מהם הוא sorted() של Python?

Python משתמשת ב-**Timsort**, אלגוריתם היברידי ששילב מיון מיזוג ומיון הכנסה, והוא חכם בטיפול בנתונים שכבר ממוינים חלקית. בקוד אמיתי תמיד השתמשו ב-`sorted()` או ב-`.sort()`. אתם כותבים את האלגוריתמים האלה ביד כדי ללמוד את הרעיונות, לא כדי להחליף את הספרייה.

> **שימו לב:**
> - אם שוכחים את מקרה הבסיס מקבלים `RecursionError: maximum recursion depth exceeded`.
> - אם מחזירים ערך רק מענף אחד, מקבלים בחזרה `None`, ואז `TypeError: can only concatenate list (not "NoneType") to list`.
> - `items[:mid]` ו-`items[mid:]` חייבים יחד לכסות את כל הרשימה. אם תפילו פריט, הוא ייעלם מהתוצאה.
> - ב-quicksort, סינון עם `x < pivot` וגם עם `x > pivot` מאבד כפילויות. השתמשו ב-`>=` עבור אחד הצדדים.
> - מיון של הרשימה הממוינת עם 1000 פריטים כשהציר הוא הפריט הראשון יורד בערך 1000 רמות לעומק, ויכול להגיע למגבלת הרקורסיה ברירת המחדל של Python ולגרום ל-RecursionError.

## להמשיך הלאה

נסו לשנות את הציר לפריט האמצעי `items[len(items) // 2]` ובדקו איך עומק הרקורסיה מתנהג על נתונים ממוינים. איך הייתם סופרים את מספר הקריאות הרקורסיביות? מונה גלובלי עובד, וכך גם החזרה שלו יחד עם הרשימה.

> **תורכם:** כתבו את `merge_sort` ואת `quick_sort` ברקורסיה (פונקציית העזר `merge` כבר קיימת). שתיהן חייבות להחזיר רשימה ממוינת חדשה ולטפל ברשימות ריקות וברשימות עם פריט אחד. אל תשתמשו ב-`sorted()` או ב-`.sort()`.
