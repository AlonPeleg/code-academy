דמיינו ספרייה שבה לכל ספר יש תווית שאומרת בדיוק באיזו מדף הוא נמצא. אתם אף פעם לא מסתובבים בין המדפים: קוראים את התווית והולכים ישר לשם. **טבלת גיבוב** (hash table) עובדת באותה דרך, וב-Python היא נקראת **מילון** (`dict`). זה כנראה מבנה הנתונים השימושי ביותר שתלמדו אי פעם, כי הוא הופך הרבה לולאות איטיות לחיפוש בצעד אחד.

## איך טבלת גיבוב עובדת

מילון שומר זוגות של **מפתח: ערך** (key: value). כדי להחליט איפה לשים מפתח, Python מריצה אותו דרך **פונקציית גיבוב** (hash function), שהופכת את המפתח למספר. המספר הזה בוחר **משבצת** (slot, או "דלי") במערך (array) פנימי. כדי לחפש את המפתח אחר כך, Python מגבבת אותו שוב וקופצת לאותה משבצת. בלי חיפוש.

```text
key "cat"  -> hash -> 7  -> slot 7:  "cat": 3
key "dog"  -> hash -> 2  -> slot 2:  "dog": 5
```

שני מפתחות שונים יכולים לנחות באותה משבצת (**התנגשות**, collision). Python מטפלת בזה בפנים, ולכן החיפוש הוא **O(1) בממוצע**: הזמן לא גדל כשהמילון גדל. השוו לזה את `x in some_list`, שהוא O(n), כי Python צריכה לסרוק את הרשימה.

```python
ages = {"Ana": 30, "Ben": 25}
ages["Cy"] = 41                 # add
print(ages["Ben"])              # prints: 25
print("Ana" in ages)            # prints: True   (fast!)
print(ages.get("Zed", 0))       # prints: 0      (default instead of an error)
```

מפתחות חייבים להיות **ניתנים לגיבוב** (hashable): דברים שלא משתנים, כמו מספרים, מחרוזות (string) ו-tuples. רשימה כמפתח גורמת ל-`TypeError: unhashable type: 'list'`, כי הרשימה יכולה להשתנות אחרי שגובבה.

## תבנית 1: ספירת תדירות

כמה פעמים כל תו מופיע? בלי מילון הייתם צריכים לולאה בתוך לולאה. עם מילון מספיק מעבר אחד:

```python
counts = {}
for ch in "banana":
    counts[ch] = counts.get(ch, 0) + 1
print(counts)   # prints: {'b': 1, 'a': 3, 'n': 2}
```

`counts.get(ch, 0)` מחזירה את הספירה הנוכחית, או `0` כשהתו חדש. בספרייה הסטנדרטית יש אפילו את `collections.Counter` שעושה את זה בשורה אחת, אבל עכשיו אתם יודעים מה הוא עושה מבפנים.

## תבנית 2: two-sum

בהינתן מספרים ויעד, מצאו שני מיקומים שהערכים שלהם מסתכמים ליעד. הדרך האיטית מנסה כל זוג: שתי לולאות מקוננות, O(n בריבוע). הדרך המהירה זוכרת מה היא כבר ראתה:

```python
nums = [2, 7, 11, 15]
target = 9
seen = {}                        # value -> position
for j, x in enumerate(nums):
    need = target - x            # the partner we are looking for
    if need in seen:
        print(seen[need], j)     # prints: 0 1
    seen[x] = j
```

ב-`x = 2` בן הזוג הוא 7: עוד לא ראינו אותו, אז שומרים את `2`. ב-`x = 7` בן הזוג הוא 2: הוא נמצא ב-`seen`, במיקום 0. סיימנו במעבר אחד: **O(n)**. אנחנו מחפשים את `need` **לפני** ששומרים את `x`, ולכן מספר אף פעם לא יכול להתחבר לעצמו.

## תבנית 3: קיבוץ לפי מפתח

אנגרמות (`listen` ו-`silent`) הן אותן אותיות בסדר שונה. אם ממיינים את האותיות של כל מילה, אנגרמות מייצרות את **אותו מפתח**: `"eilnst"`. מילון ממפתח לרשימת מילים מקבץ אותן:

```python
groups = {}
for word in ["listen", "silent", "cat", "act"]:
    key = "".join(sorted(word))
    groups.setdefault(key, []).append(word)
print(list(groups.values()))   # prints: [['listen', 'silent'], ['cat', 'act']]
```

`setdefault(key, [])` מחזירה את הרשימה הקיימת של המפתח, או מכניסה ומחזירה רשימה ריקה חדשה. הרעיון "מחשבים מפתח ואז מחלקים לדליים לפיו" הוא הבסיס של הרבה משימות אמיתיות: קיבוץ לוגים לפי משתמש, שורות לפי תאריך, קבצים לפי גודל.

> **שימו לב:**
> - `counts[ch] += 1` על מפתח חדש גורם ל-`KeyError: 'b'`. השתמשו קודם ב-`.get(ch, 0)` או ב-`setdefault`.
> - מפתחות שניתנים לשינוי נכשלים: `{[1, 2]: "x"}` נותן `TypeError: unhashable type: 'list'`. השתמשו ב-tuple במקום.
> - מילונים לא מבטיחים מפתחות ממוינים. הם זוכרים את סדר ההכנסה, אבל כדי להדפיס בסדר אלפביתי השתמשו ב-`sorted(d.items())`.
> - עשו את החיפוש **לפני** `seen[x] = j` ב-two-sum, אחרת `two_sum([3], 6)` היה מחבר בטעות את 3 עם עצמו.
> - גיבוב הוא O(1) בממוצע. פונקציית גיבוב גרועה ששולחת הכול למשבצת אחת הייתה הופכת אותו ל-O(n), אבל הפונקציות המובנות של Python טובות.
