יש בעיות שנראות קשות כי הן שואלות שוב ושוב את אותה שאלה קטנה. **תכנות דינמי** (dynamic programming, או DP) היא הטכניקה של לענות על כל שאלה קטנה **פעם אחת**, לרשום את התשובה ולהשתמש בה שוב. השם ישן ולא מועיל. חשבו על זה כ"רקורסיה עם זיכרון" או כ"מילוי טבלה". הטכניקה הופכת אלגוריתמים שהיו לוקחים יותר מגיל היקום לאלגוריתמים שמסתיימים מיד.

## הבעיה: עבודה חוזרת

מספרי פיבונאצ'י: כל מספר הוא סכום שני הקודמים לו (0, 1, 1, 2, 3, 5, 8 ...). ההגדרה הרקורסיבית הישירה יפה מאוד:

```python
def fib(n):
    if n < 2:
        return n
    return fib(n - 1) + fib(n - 2)
```

אבל הביטו בקריאות של `fib(5)`:

```text
                     fib(5)
                  /          \
             fib(4)           fib(3)
            /      \          /     \
        fib(3)    fib(2)   fib(2)   fib(1)
        /   \
    fib(2) fib(1)  ...
```

`fib(3)` מחושב פעמיים, `fib(2)` שלוש פעמים. עבור `fib(25)` הפונקציה נקראת **242,785 פעמים** כדי להפיק מספר אחד. כל צעד נוסף למעלה מכפיל בערך את העבודה: זה **אקספוננציאלי**, O(2 בחזקת n).

## רעיון 1: memoization (מלמעלה למטה)

**Memoization** שומרת מילון של תוצאות. לפני החישוב בודקים את ה-memo, ואחרי החישוב שומרים את התשובה.

```python
def fib_memo(n, memo=None):
    if memo is None:
        memo = {}
    if n < 2:
        return n
    if n in memo:
        return memo[n]
    memo[n] = fib_memo(n - 1, memo) + fib_memo(n - 2, memo)
    return memo[n]

print(fib_memo(80))   # prints: 23416728348467685
```

כל ערך מ-0 עד n מחושב עכשיו בדיוק פעם אחת, ולכן העלות יורדת מאקספוננציאלית ל-**O(n)**. אותו רעיון גרם ל-`fib(25)` להזדקק לכ-49 קריאות במקום 242,785. מספרים שלמים ב-Python אף פעם לא גולשים, ולכן אפילו `fib(80)` מדויק. (בספרייה הסטנדרטית יש את `functools.lru_cache` שעושה את זה בשורה אחת. כדאי להכיר אותו, אבל קודם בנו את זה ביד.)

## רעיון 2: מילוי טבלה (מלמטה למעלה)

במקום רקורסיה, ממלאים טבלה מבעיית המשנה הקטנה ביותר ומעלה, כך שכל תא צריך רק תאים שכבר מילאתם.

**החזר מטבעות.** מה המספר הקטן ביותר של מטבעות שמרכיבים סכום נתון, בהינתן ערכי מטבעות? אלגוריתם חמדן (greedy, תמיד המטבע הגדול ביותר) נכשל: עבור מטבעות `[1, 3, 4]` וסכום 6, החמדן בוחר 4+1+1 (שלושה מטבעות), אבל 3+3 צריך רק שניים. DP מנסה הכול באופן שיטתי. נסמן ב-`best[a]` את מספר המטבעות הקטן ביותר עבור סכום `a`. כדי להרכיב את `a`, המטבע האחרון הוא איזה `c`, ולפניו הרכבתם את `a - c`:

```text
best[a] = 1 + min(best[a - c]) over coins c with c <= a

coins [1, 3, 4]
amount: 0  1  2  3  4  5  6
best:   0  1  2  1  1  2  2
```

```python
best = [0] + [impossible] * amount
for a in range(1, amount + 1):
    for c in coins:
        if c <= a and best[a - c] + 1 < best[a]:
            best[a] = best[a - c] + 1
```

`impossible` הוא פשוט מספר גדול מכל תשובה אמיתית (`amount + 1`), שמייצג "עוד לא נמצאה דרך". אם הוא עדיין שם בסוף, מחזירים `-1`. העלות היא O(amount x מספר המטבעות).

**תת-סדרה משותפת ארוכה ביותר (LCS).** תת-סדרה שומרת על הסדר אבל יכולה לדלג על אותיות. ה-LCS של `ABCBDAB` ו-`BDCABA` הוא באורך 4 (למשל `BCBA`). זה הרעיון מאחורי כלי `diff` והשוואת DNA. נסמן ב-`table[i][j]` את התשובה עבור `i` האותיות הראשונות של `a` ו-`j` האותיות הראשונות של `b`:

- אם האותיות האחרונות זהות, מרחיבים את התשובה הטובה ביותר לשתי המחרוזות המקוצרות: `table[i-1][j-1] + 1`.
- אחרת מורידים את האות האחרונה של מחרוזת אחת או של השנייה ולוקחים את התוצאה הטובה יותר.

```text
a = "AC", b = "ABC"
        ""  A  B  C
   ""    0  0  0  0
   A     0  1  1  1
   C     0  1  1  2     <- LCS length is 2 ("AC")
```

בטבלה יש `len(a) x len(b)` תאים, וכל אחד ממולא ב-O(1): בסך הכול **O(n x m)**, במקום העלות האקספוננציאלית של ניסיון כל תת-סדרה.

## איך מזהים בעיית DP

1. אפשר לבטא את התשובה בעזרת תשובות ל**גרסאות קטנות יותר** של אותה בעיה.
2. בעיות המשנה האלה **חופפות**, ולכן אותן בעיות מופיעות שוב ושוב.
3. שאלו: מהו המצב (מה משתנה בין בעיות משנה), ומהו מקרה הבסיס?

> **שימו לב:**
> - ארגומנט ברירת מחדל `memo={}` נוצר רק פעם אחת ומשותף בין קריאות. כאן זה עובד במקרה, אבל זו מלכודת קלאסית, ולכן השתמשו ב-`memo=None`.
> - אם שוכחים לשמור ב-memo (או בטבלה), הכול שוב נעשה איטי בשקט, לא שגוי.
> - טעות של אחד בטבלאות: הן צריכות `len + 1` שורות ועמודות (עבור הקידומת הריקה), והאותיות הן `a[i - 1]`, לא `a[i]`.
> - `[[0] * m] * n` הופך כל שורה לאותו אובייקט רשימה. השתמשו ב-`[[0] * m for _ in range(n)]`.
> - רקורסיה עמוקה עבור `n` גדול מגיעה ל-`RecursionError`. לולאות מלמטה למעלה לא.

## להמשיך הלאה

גרמו ל-`coin_change` להחזיר גם אילו מטבעות שימשו, על ידי זכירת המטבע האחרון בכל סכום. או ספרו את מספר ה**דרכים** להרכיב סכום, שזו וריאציה נוספת של DP.

> **תורכם:** ממשו את `fib_memo` (רקורסיה ועוד מילון), את `coin_change` (רשימה מלמטה למעלה) ואת `lcs_length` (טבלה דו-ממדית). אל תשתמשו ב-`lru_cache`.
