כמעט לכל תוכנית צריך למצוא דברים: איש קשר בספר טלפונים, מוצר בקטלוג, מילה במילון. בשיעור הזה תכירו את שתי הדרכים הקלאסיות לחפש ברשימה, ותראו במספרים אמיתיים למה אחת מהן מהירה להפליא.

## חיפוש לינארי: מסתכלים על הכול

**חיפוש לינארי** (linear search) הוא מה שעושים עם ערימה מבולגנת של ניירות: בודקים אותם אחד אחד עד שמוצאים את זה שרוצים.

```python
def linear_search(items, target):
    for i in range(len(items)):
        if items[i] == target:
            return i          # found: return the position
    return -1                 # not found

print(linear_search([7, 3, 9, 4], 9))   # prints: 2
print(linear_search([7, 3, 9, 4], 5))   # prints: -1
```

החזרת `-1` עבור "לא נמצא" היא מוסכמה נפוצה, כי `-1` לא יכול להיות אינדקס אמיתי. חיפוש לינארי עובד על כל רשימה, ממוינת או לא. העלות שלו היא **O(n)**: במקרה הגרוע (הפריט אחרון, או חסר) הוא מסתכל על כל `n` הפריטים.

## חיפוש בינארי: חוצים את הבעיה

חשבו על משחק ניחוש המספר. אני בוחר מספר בין 1 ל-100. אתם מנחשים 50. אני אומר "גבוה יותר". עכשיו אתם יודעים שהתשובה בין 51 ל-100, וזרקתם חצי מהאפשרויות בשאלה אחת. מנחשים 75, "נמוך יותר", ושוב חצי. אתם צריכים לכל היותר 7 ניחושים עבור 100 מספרים.

זה **חיפוש בינארי** (binary search). יש לו דרישה גדולה אחת: **הרשימה חייבת להיות ממוינת**. אז תמיד אפשר להסתכל באמצע ולזרוק את החצי שלא יכול להכיל את היעד.

```text
find 150 in [0, 2, 4, ... 198]   (100 items, positions 0 to 99)

round 1: low=0  high=99  mid=49  items[49]=98   too small -> low = 50
round 2: low=50 high=99  mid=74  items[74]=148  too small -> low = 75
round 3: low=75 high=99  mid=87  items[87]=174  too big   -> high = 86
round 4: low=75 high=86  mid=80  items[80]=160  too big   -> high = 79
round 5: low=75 high=79  mid=77  items[77]=154  too big   -> high = 76
round 6: low=75 high=76  mid=75  items[75]=150  found!
```

שישה סיבובים במקום 76. החלון `[low, high]` מצטמצם בחצי בכל פעם.

## הקוד, חלק אחרי חלק

```python
def binary_search(items, target):
    low = 0
    high = len(items) - 1
    while low <= high:
        mid = (low + high) // 2
        if items[mid] == target:
            return mid
        elif items[mid] < target:
            low = mid + 1       # target can only be to the right
        else:
            high = mid - 1      # target can only be to the left
    return -1
```

- `low` ו-`high` מסמנים את החלק ברשימה שעדיין יכול להכיל את היעד.
- `(low + high) // 2` הוא המיקום האמצעי. `//` הוא חילוק שלם, כי מיקום ברשימה חייב להיות מספר שלם.
- אנחנו מציבים `low = mid + 1` (ולא `mid`) כי כבר בדקנו את `mid`. דילוג עליו מבטיח שהחלון מצטמצם בכל סיבוב.
- כש-`low` עובר את `high`, החלון ריק: היעד לא שם.

## למה זה הרבה יותר מהיר

מכיוון שהחלון נחצה בכל סיבוב, חיפוש בינארי הוא **O(log n)**. השוו את המקרים הגרועים:

| פריטים | חיפוש לינארי | חיפוש בינארי |
| --- | --- | --- |
| 100 | 100 | 7 |
| 10,000 | 10,000 | 14 |
| 1,000,000 | 1,000,000 | 20 |
| 1,000,000,000 | 1,000,000,000 | 30 |

אפשר לחפש במיליארד פריטים ממוינים ב-30 צעדים. התנאי: גם מיון עולה זמן. אם מחפשים ברשימה רק פעם אחת, לא כדאי למיין קודם. אם מחפשים בה אלפי פעמים, ממיינים פעם אחת ואז משתמשים בחיפוש בינארי בכל פעם. (השיעורים הבאים עוסקים במיון.)

> **שימו לב:**
> - שימוש בחיפוש בינארי על רשימה לא ממוינת נותן תשובות שגויות בלי שום הודעת שגיאה. הוא מחזיר בשקט `-1` עבור פריטים שנמצאים שם באמת.
> - `while low < high` במקום `low <= high` מדלג על המקרה שנשאר פריט אחד, ומחמיץ את המועמד האחרון.
> - כתיבת `low = mid` או `high = mid` במקום `mid + 1` / `mid - 1` יכולה ליצור לולאה אינסופית.
> - `mid = (low + high) / 2` נותן מספר עשרוני (float) ופייתון זורקת `TypeError: list indices must be integers or slices, not float`. השתמשו ב-`//`.

## להמשיך הלאה

לפייתון כבר יש חיפוש בינארי בדוק במודול `bisect`. חשוב ללמוד לכתוב אותו בעצמכם, כי אותו רעיון של חצייה מופיע בכל מקום: מציאת באג בהיסטוריה ארוכה של שינויים, ניחוש ערך במשחק, ואפילו חיפוש מילה במילון מנייר.

> **תורכם:** כתבו את `binary_search(items, target)` שמחזירה `(index, steps)`, וסופרת צעד אחד לכל סיבוב של הלולאה, ו-`(-1, steps)` כשהיעד חסר. הפונקציה `linear_search` כבר כתובה כדי שתוכלו להשוות בין מספרי הצעדים.
