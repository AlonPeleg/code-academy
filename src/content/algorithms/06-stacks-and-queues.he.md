יש מבני נתונים שמוגדרים לא לפי מה שהם מחזיקים, אלא לפי **הסדר שבו מוציאים מהם דברים**. שניים מהם נמצאים בכל מקום בתוכנה: **המחסנית** (stack) ו**התור** (queue). אחרי שתלמדו אותם תזהו אותם בכפתורי ביטול, בהיסטוריית הדפדפן, במתזמני משימות ובדרך שבה התוכניות שלכם רצות.

## מחסנית: אחרון נכנס, ראשון יוצא (LIFO)

חשבו על ערימת צלחות. מוסיפים צלחת למעלה, ולוקחים צלחת מלמעלה. הצלחת שהונחה אחרונה יוצאת ראשונה.

```text
push 1    push 2    push 3    pop -> 3    pop -> 2
 [1]      [1,2]    [1,2,3]     [1,2]       [1]
                      ^ top
```

רשימה (list) ב-Python היא כבר מחסנית. `append` דוחפת לסוף, ו-`pop()` מסירה ומחזירה את הסוף:

```python
stack = []
stack.append("a")
stack.append("b")
stack.append("c")
print(stack.pop())   # prints: c
print(stack.pop())   # prints: b
print(stack)         # prints: ['a']
```

שתי הפעולות הן O(1). איפה חיות מחסניות? בכפתור **הביטול** (undo) של עורך, שבו השינוי האחרון מבוטל ראשון, בכפתור החזרה של דפדפן, וב**מחסנית הקריאות** (call stack) של התוכנית שלכם: כשפונקציה קוראת לפונקציה אחרת, Python זוכרת לאן לחזור, הקריאה האחרונה ראשונה.

## דוגמה: סוגריים מאוזנים

האם `{[()()]}` תקין? ומה לגבי `(]`? מהדרים ועורכים בודקים את זה כל הזמן. הכלל: כל סוגר פותח חייב להיסגר על ידי בן הזוג שלו, בסדר הנכון. מחסנית פותרת את זה בצורה אלגנטית:

1. קוראים את הטקסט משמאל לימין.
2. סוגר פותח: **דוחפים** (push) אותו.
3. סוגר סוגר: ראש המחסנית חייב להיות בן הזוג שלו. אם כן, **מוציאים** (pop) אותו. אם המחסנית ריקה או שהראש הוא סוגר אחר, הטקסט שבור.
4. בסוף המחסנית חייבת להיות ריקה. כל מה שנשאר הוא סוגר פותח שאף פעם לא נסגר.

```text
text: ( [ ] )
 (   push          stack: (
 [   push          stack: ( [
 ]   top is [ ok   stack: (
 )   top is ( ok   stack: (empty)  -> balanced
```

מילון (dictionary) של זוגות שומר על קוד קצר: `pairs = {")": "(", "]": "[", "}": "{"}`. בהינתן סוגר סוגר, `pairs[closer]` הוא הסוגר הפותח שהוא צריך.

## תור: ראשון נכנס, ראשון יוצא (FIFO)

תור הוא שורה בחנות: מי שהגיע ראשון מקבל שירות ראשון. מוסיפים בסוף (**enqueue**) ומוציאים מההתחלה (**dequeue**).

רשימה היא תור גרוע: `items.pop(0)` מסירה את הפריט הראשון, אבל אז כל שאר הפריטים צריכים לזוז מקום אחד שמאלה, וזה עולה O(n). ספריית הליבה מציעה את **`collections.deque`** (קוראים "דק", קיצור של double-ended queue), שמוסיף ומסיר ב**שני הקצוות** ב-O(1):

```python
from collections import deque

q = deque(["Ana", "Ben"])
q.append("Cy")            # join the back of the line
print(q.popleft())        # prints: Ana   (front of the line leaves)
print(q)                  # prints: deque(['Ben', 'Cy'])
```

תורים מדמים המתנה: משימות הדפסה, פניות לתמיכת לקוחות, והסדר שבו שרת אינטרנט מטפל בבקשות. בשיעור 10 תור הוא המרכיב הסודי של חיפוש לרוחב (breadth-first search).

## סימולציה: תפוח אדמה לוהט

תרגיל תור קלאסי: שחקנים עומדים במעגל ומעבירים תפוח אדמה. אחרי מספר קבוע של העברות, השחקן שמחזיק בו יוצא מהמשחק. בעזרת תור, "העברה" פירושה שהשחקן הראשון עובר לסוף: `q.append(q.popleft())`. אחרי ההעברות, `q.popleft()` מסיר סופית את מי שנמצא בראש התור. חוזרים על זה עד שנשאר שחקן אחד. מעגל של אנשים מתאים בדיוק לתור שבו הראשון תמיד עובר לסוף.

> **שימו לב:**
> - `stack.pop()` על רשימה ריקה גורמת ל-`IndexError: pop from empty list`. בדקו קודם `if stack`.
> - `deque.popleft()` על deque ריק גורם ל-`IndexError: pop from an empty deque`.
> - לרשימה אין `popleft`: `AttributeError: 'list' object has no attribute 'popleft'`. רק ל-`deque` יש אותה.
> - אם מחזירים `True` כשהלולאה נגמרת בלי לבדוק שהמחסנית ריקה, מקבלים את `((` כתקין.
> - גם קריאה של `stack[-1]` על מחסנית ריקה היא `IndexError`. בדקו קודם אם היא ריקה.

## להמשיך הלאה

הרחיבו את `is_balanced` כך שתדווח על המיקום של הבעיה הראשונה. או ממשו היסטוריית ביטול קטנה: שמרו מחסנית של גרסאות קודמות של מחרוזת (string) והוציאו ממנה כדי לחזור אחורה.

> **תורכם:** כתבו את `is_balanced(text)` עם רשימה שמשמשת כמחסנית, ואת `hot_potato(names, passes)` עם `deque`. השנייה מחזירה tuple של סדר ההדחה והמנצח.
