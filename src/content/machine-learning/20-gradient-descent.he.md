כמעט כל מודל ש"לומד", מרגרסיה לינארית ועד רשתות נוירונים עם מיליארדי מספרים, לומד באותה לולאה: מודדים כמה טועים, מחשבים לאיזה כיוון כדאי להזיז כל מספר כדי לטעות פחות, מזיזים וחוזרים. זו **ירידת גרדיאנט** (gradient descent). בשיעור הזה תכתבו אותה בעצמכם רק עם NumPy, ותתאימו קו ישר לכמה נקודות.

## ההגדרה

אנחנו רוצים קו `y = w * x + b`. השיפוע `w` ונקודת החיתוך `b` הם ה**פרמטרים** (parameters) שהמודל לומד. כדי לומר עד כמה קו גרוע, צריך **הפסד** (loss): שגיאה ריבועית ממוצעת (MSE), הממוצע של `(prediction - truth)^2`. לקו מושלם יש הפסד 0, ולקו גרוע יש הפסד גדול. למידה פירושה למצוא את `w` ואת `b` עם ההפסד הקטן ביותר.

דמיינו את ההפסד כנוף הרים: כל זוג `(w, b)` הוא מקום וההפסד הוא הגובה. אנחנו רוצים את העמק הנמוך ביותר. כשעומדים באיזשהו מקום בערפל, אפשר להרגיש לאיזה כיוון יורד השטח. ירידת גרדיאנט עושה צעד קטן לשם וחוזרת על זה.

## דוגמה מחושבת ביד

ניקח רק שלוש נקודות: `x = 1, 2, 3` ו-`y = 3, 5, 7` (הקו האמיתי הוא `w = 2, b = 1`). מתחילים ב-`w = 0, b = 0`.

* כל החיזויים הם 0, ולכן ה**שגיאה** `pred - y` היא `-3, -5, -7`.
* ה**גרדיאנט** (gradient) אומר איך ההפסד משתנה כששינינו פרמטר. עבור MSE הוא
  `grad_w = 2 * mean(error * x) = 2 * (-3 - 10 - 21) / 3 = -22.67` ו-
  `grad_b = 2 * mean(error) = 2 * (-15 / 3) = -10`.
* שני הגרדיאנטים שליליים: הגדלה של `w` או של `b` תקטין את ההפסד. כלל העדכון הוא `new = old - lr * gradient`. עם קצב למידה `lr = 0.01`: `w = 0 - 0.01 * (-22.67) = 0.23` ו-`b = 0 - 0.01 * (-10) = 0.10`.

צעד אחד קירב את שני המספרים לאמת (2 ו-1). הקוד שלהלן חוזר על זה אלפי פעמים.

## לולאת האימון

```python
for _ in range(epochs):
    pred = w * x + b
    error = pred - y
    grad_w = 2 * np.mean(error * x)
    grad_b = 2 * np.mean(error)
    w = w - lr * grad_w
    b = b - lr * grad_b
```

**Epoch** הוא מעבר אחד שבו כל נקודת נתונים תרמה לעדכון אחד. שימו לב ש-`x`, `y`, `pred` ו-`error` הם מערכים (arrays) של NumPy, ולכן כל שורה פועלת על כל הנקודות בבת אחת (וקטורית). הגרדיאנט הוא הנגזרת של ההפסד: עבור נקודה אחת ההפסד הוא `(w*x + b - y)^2`, והנגזרת שלו לפי `w` היא `2 * (w*x + b - y) * x`, ואנחנו לוקחים את הממוצע שלה על פני הנקודות.

## קצב הלמידה

`lr` הוא **היפר-פרמטר** (hyperparameter): הגדרה שאתם בוחרים, ולא משהו שנלמד. הוא קובע את גודל הצעד:

| קצב למידה | מה קורה |
|---|---|
| קטן מדי (0.001) | זז בכיוון הנכון, אבל אחרי 100 epochs הערך של `w` הוא רק 2.1 ו-`b` רחוק מ-1. היו נדרשים אלפי צעדים. |
| מתאים (0.02) | מתייצב על `w = 2.02`, `b = 1.00` אחרי כ-3000 epochs. |
| גדול מדי (0.06) | כל צעד עובר מעל העמק ונוחת גבוה יותר בצד השני. ההפסד גדל, והמספרים מתפוצצים. זה נקרא **התבדרות** (divergence). |

## איך קוראים את הפלט

* `loss before 123` ו-`loss after 0.06`: ההפסד קרס. הדפסת ההפסד היא ההרגל החשוב ביותר ל-debug בלמידת מכונה. אם הוא לא יורד, משהו לא בסדר.
* `w 2.02 b 1.00` מתאים לנתונים, שנוצרו מהקו `y = 2x + 1` ועוד מעט רעש. מודל לא יכול להגיע להפסד 0 בגלל הרעש, ולכן 0.06 הוא כמעט הטוב ביותר שאפשר.
* `True` מ-`np.allclose(..., atol=0.01)` אומר שירידת גרדיאנט מצאה את אותו קו כמו הנוסחה המדויקת של ריבועים פחותים ב-`np.polyfit`. לקו יש נוסחה סגורה; ירידת גרדיאנט חשובה כי היא עובדת גם במקומות שבהם אין נוסחה.
* `diverged: True` מראה מה קצב למידה גרוע עושה.

> **שימו לב:**
> - עדכון של `w` לפני שחישבתם את `grad_b` עם ה-`w` החדש. חשבו קודם את שני הגרדיאנטים, ורק אחר כך עדכנו את שניהם.
> - טעות בסימן (`w = w + lr * grad_w`) שולחת אתכם במעלה ההר. ההפסד גדל בכל epoch.
> - שכחה ש-`x` חייב להיות מערך NumPy של מספרים עשרוניים (float). רשימה רגילה של Python נותנת `TypeError: can't multiply sequence by non-int of type 'float'`.
> - אם לתכונות (features) יש גדלים שונים מאוד (כמו 1 עד 8 לצד 1000 עד 9000), קצב למידה אחד לא יתאים לשתיהן. זו עוד סיבה לשנות את קנה המידה של התכונות.
> - `RuntimeWarning: overflow encountered` או ערכי `nan` אומרים שקצב הלמידה גבוה מדי בהרבה.

> **תורכם:** השלימו את הפונקציה `train` בארבעת השלבים (חיזוי, שגיאה, גרדיאנטים, עדכון), אמנו עם `lr = 0.02` במשך 3000 epochs, השוו ל-`np.polyfit`, ואז בדקו איך מתנהגים קצב למידה זעיר וקצב למידה ענקי. עקבו אחר ההערות הממוספרות.
