כרגע הריבוע שלכם יכול לברוח מהמסך ולהיעלם לנצח. משחקים אמיתיים שומרים על הגיבורים בתוך העולם, או לפחות מחליטים מה קורה בקצה. השיעור הזה מלמד את הטריק הרגיל לכך, שנקרא **הגבלה** (clamping): הכרחת מספר להישאר בין ערך נמוך ביותר לערך גבוה ביותר.

## איפה הקצוות?

המסך הוא ברוחב `game.WIDTH` (320) פיקסלים ובגובה `game.HEIGHT` (240) פיקסלים. מלבן ממוקם לפי **הפינה השמאלית העליונה** שלו `(x, y)`, ויש לו רוחב וגובה. לכן:

- מגיעים לקצה השמאלי כש-`x` שווה ל-`0`.
- הקצה הימני של ריבוע הוא `x + SIZE`. הוא נוגע בצד הימני של המסך כש-`x + SIZE` שווה ל-`game.WIDTH`, ולכן ה-`x` הגדול ביותר המותר הוא `game.WIDTH - SIZE`.
- הקצה העליון הוא `y = 0`, וה-`y` הגדול ביותר המותר הוא `game.HEIGHT - SIZE`.

באג נפוץ הוא לשכוח את הגודל ולהשתמש ב-`game.WIDTH` כגבול: אז הריבוע מחליק החוצה עד חציו.

## הגבלה עם if

אפשר לתקן את המיקום עם משפטי `if` רגילים, אחרי קוד התנועה:

```js
if (x < 0) {
  x = 0;
}
if (x > game.WIDTH - SIZE) {
  x = game.WIDTH - SIZE;
}
```

ה-`if` הראשון אומר: אם יצאנו שמאלה מהמסך, החזירו אותנו לקצה השמאלי. השני עושה אותו דבר בצד הימני. זה עובד, אבל דרושים ארבעה משפטי `if` כדי לטפל בשני הצירים.

## הגבלה עם Math.min ו-Math.max

ב-JavaScript יש אובייקט (object) מובנה בשם `Math` עם פונקציות שימושיות:

- `Math.max(a, b)` מחזירה את המספר **הגדול** מבין שניים.
- `Math.min(a, b)` מחזירה את המספר **הקטן** מבין שניים.

בהתחלה זה נשמע הפוך, אבל חשבו על זה: `Math.max(0, x)` אף פעם לא קטנה מ-0, ולכן היא פועלת כ**רצפה**. ו-`Math.min(300, x)` אף פעם לא גדולה מ-300, ולכן היא **תקרה**. שלבו את שתיהן:

```js
x = Math.max(0, Math.min(game.WIDTH - SIZE, x));
```

קראו מבפנים החוצה: קודם מגבילים את `x` לגבול הימני, ואחר כך מוודאים שהוא לא מתחת ל-0. דוגמאות:

```js
Math.max(0, Math.min(300, 450))   // 450 capped to 300, so 300
Math.max(0, Math.min(300, -20))   // -20 is below the floor, so 0
Math.max(0, Math.min(300, 120))   // already inside, stays 120
```

שורה אחת זו מחליפה ארבע. אם עושים את זה לעתים קרובות, אפשר לעטוף אותה בפונקציה משלכם:

```js
function clamp(value, low, high) {
  return Math.max(low, Math.min(high, value));
}
```

## מתי לעשות את זה

תמיד מגבילים **אחרי** שזזים. הסדר ב-`update` הוא: קוראים את המקשים וזזים, אחר כך מתקנים את המיקום, ואז (בהמשך המסלול) בודקים התנגשויות. אם מגבילים קודם וזזים אחר כך, השחקן עדיין יכול להיות כמה פיקסלים מחוץ למסך למשך פריים אחד.

## כללי קצה אחרים

קירות שעוצרים אתכם הם רק אפשרות אחת. משחקים משתמשים גם ב:

- **גלישה** (wrapping): יוצאים מימין ונכנסים משמאל (`if (x > game.WIDTH) x = 0;`), כמו ב-Asteroids.
- **ריקושט** (bouncing): הופכים את כיוון המהירות כשפוגעים בקצה (תעשו את זה ב-Pong).
- **מוות**: יציאה מהמסך עולה בחיים.

> **שימו לב:** בלבול בין `Math.min` ל-`Math.max` הוא הטעות מספר אחת: `Math.min(0, x)` גורמת ל-`x` לא להיות אף פעם **גדול** מ-0, וזה מצמיד את הריבוע לפינה השמאלית העליונה. אם הריבוע לא זז, החליפו ביניהן.
>
> **שימו לב:** `Math` מתחילה באות גדולה. `math.max(...)` מניבה `ReferenceError: math is not defined`.
>
> **שימו לב:** שכחה להשים את התוצאה: `Math.max(0, x);` לבדה בשורה מחשבת מספר וזורקת אותו. צריך לכתוב `x = Math.max(0, x);`.
>
> **שימו לב:** הגבלה בתוך `draw` במקום ב-`update` מסתירה את הבעיה בתמונה, אבל המיקום האמיתי עדיין מחוץ למסך.

> **תורכם:** אחרי קוד התנועה ב-`update`, השאירו את `x` בין `0` ל-`game.WIDTH - SIZE` ואת `y` בין `0` ל-`game.HEIGHT - SIZE`. נסו בשידור חי: החזיקו מקש חץ וודאו שהריבוע עוצר בקצה.
