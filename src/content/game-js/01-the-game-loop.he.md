כל משחק וידאו, מ-Pong ועד סרט הענק התלת-ממדי הגדול ביותר, בנוי סביב רעיון פשוט אחד: **לולאה** (loop) שרצה פעמים רבות בכל שנייה. בכל סיבוב של הלולאה המשחק עושה שני דברים: הוא **מעדכן** את העולם (מזיז דברים, בודק מקשים, סופר נקודות) והוא **מצייר** את העולם על המסך. אם עושים זאת 60 פעמים בשנייה, העיניים רואות תנועה חלקה. במסלול הזה תבנו משחקים ב-JavaScript שרצים בשידור חי בדפדפן.

## המבנה של כל משחק

```js
let x = 0;

function update(dt) {
  // change the numbers
}

function draw() {
  // paint the numbers
}

game.run(update, draw);
```

- `game` הוא ארגז כלים קטן שאנחנו נותנים לכם. הוא יודע לצייר צורות, לקרוא את המקלדת ולהריץ את הלולאה. אין צורך לייבא אותו.
- `update` ו-`draw` הן שתי **פונקציות** (functions) שאתם כותבים. פונקציה היא קטע קוד בעל שם שאפשר לקרוא לו פעמים רבות.
- `game.run(update, draw)` היא השורה האחרונה בכל תוכנית. היא מוסרת את שתי הפונקציות שלכם למנוע, שקורא להן בערך 60 פעמים בשנייה, קודם ל-`update` ואחר כך ל-`draw`.

משתנים (variables) שמוגדרים עם `let` בראש הקובץ (מחוץ לכל פונקציה) הם ה**מצב** (state) של המשחק: הם שומרים על הערכים שלהם מפריים לפריים. כאן שומרים מיקומים, ניקוד וחיים.

## המסך

המסך הוא **ברוחב 320 פיקסלים ובגובה 240 פיקסלים**. הנקודה `(0, 0)` היא הפינה **השמאלית העליונה**. הערך `x` גדל ימינה, והערך `y` גדל **כלפי מטה** (ההפך מגרף במתמטיקה). `game.WIDTH` ו-`game.HEIGHT` מחזיקים את הגדלים האלה.

## ציור

בתחילת כל `draw` מנקים את המסך, אחרת התמונות הישנות יישארו ויימרחו:

```js
game.clear(game.DARK);
```

צבעים מובנים מראש (`game.RED`, `game.YELLOW`, `game.CYAN` ועוד). מלבן מציירים באמצעות `game.rect(x, y, width, height, color)`:

```js
game.rect(100, 50, 40, 20, game.GREEN);   // a green box, 40 wide and 20 high
```

## תנועה עם dt

הפונקציה `update` מקבלת מספר בשם `dt` (*delta time*, כלומר הפרש זמן): **מספר השניות שעברו מאז הפריים הקודם**. ב-60 פריימים לשנייה הוא בערך `0.0167`. כדי לנוע במהירות מסוימת, מכפילים את המהירות ב-dt:

```js
x += speed * dt;      // short for: x = x + speed * dt
```

אם `speed` הוא 100 פיקסלים בשנייה, בכל פריים הריבוע נע `100 * 0.0167`, כלומר בערך 1.7 פיקסלים, ואחרי שנייה אחת הוא עבר 100 פיקסלים. זה גם אומר שהמשחק מרגיש אותו דבר במחשב איטי שמצליח להפיק רק 30 פריימים לשנייה, כי אז dt גדול יותר.

## לראות מה קורה

לחצו על **Run** כדי לשחק במשחק בשידור חי. השתמשו ב-`console.log(x)` בתוך `update` כדי להדפיס ערכים בלשונית Console (אבל לא בכל פריים לאורך זמן, היא תתמלא מהר מאוד!). כשלוחצים על **Check answer**, המשחק רץ בלי להיראות למשך מספר קבוע של פריימים, והמשתנים שלכם נבדקים.

> **שימו לב:** אם שוכחים את `game.run(update, draw)` בסוף, מקבלים את ההודעה "Your program never called game.run". בלעדיה שום דבר לא מתחיל.
>
> **שימו לב:** אם הצורה נמרחת על פני המסך, שכחתם את `game.clear(...)` בתחילת `draw`.
>
> **שימו לב:** `ReferenceError: x is not defined` פירושו ש-`x` כתוב אחרת בשני מקומות, או שהוא הוגדר בתוך פונקציה (ולכן הוא נעלם בסוף אותה פונקציה).
>
> **שימו לב:** שינוי מצב בתוך `draw` במקום ב-`update` עובד בהתחלה, אבל מערבב בין שתי המשימות. השאירו את `draw` לציור בלבד.

## להתקדם הלאה

נסו מהירות של `-100` או של `300`. שנו את הצבע, את הגודל או את המיקום `y`. הוסיפו משתנה שני `y` ומהירות שנייה כדי שהריבוע ינוע באלכסון.

> **תורכם:** בתוך `update`, הוסיפו `speed * dt` ל-`x`. בתוך `draw`, ציירו עם `game.rect` ריבוע צהוב בגודל 30 על 30 ב-`x`, `105`.
