זהו קו הסיום של המסלול: משחק ארקייד קטן ושלם. ספינה בתחתית מחליקה שמאלה וימינה, מחזיקים אש כדי לירות כדורים, ואויבים ממשיכים להגיע מלמעלה. יורים בהם כדי לצבור נקודות, ואם מעבירים יותר מדי המשחק נגמר. אין בו שום דבר שלא פגשתם כבר: השיעור הזה עוסק ב**חיבור החלקים יחד**, וזה מה שרוב תכנות המשחקים הוא.

## המרכיבים

| חלק | איפה למדתם אותו |
| --- | --- |
| לולאת `update` / `draw` ו-`dt` | לולאת המשחק |
| הזזת הספינה עם המקשים | תנועה עם המקלדת |
| שמירת הספינה על המסך | להישאר על המסך |
| `touching` וניקוד | התנגשות ומטבעות |
| מערכים של כדורים, קירור ירי, `filter` | מערכים של כדורים ובלוקים |
| `state` ו-`lives` | מצבי משחק, חיים וניקוד |
| טיימר שמפעיל דברים באופן קבוע | סנייק |

## הצורה של update

קל יותר לכתוב `update` גדולה אם נותנים לה סדר קבוע. זו עושה תמיד:

1. **קלט**: קוראת את המקשים, מזיזה את השחקן.
2. **הופעה**: טיימרים יוצרים דברים חדשים (כדור, אויב).
3. **תנועה**: כל כדור ואויב משנה מיקום ב-`speed * dt`.
4. **התנגשות**: מחפשת דברים שנוגעים זה בזה ומסמנת אותם `alive = false`.
5. **ניקוי**: מסננת עם `filter` כל מה שלא חי או שיצא מהמסך, ואז בודקת את המצב (למשל `lives <= 0`).

עשייה בסדר זהה בכל פריים מונעת באגים מוזרים, כמו כדור שפוגע באויב שכבר הוסר.

## אויבים על טיימר

האויבים מופיעים כל 0.8 שניות בעזרת צובר הטיימר שאתם מכירים מסנייק:

```js
spawnTimer += dt;
if (spawnTimer >= 0.8) {
  spawnTimer -= 0.8;
  spawnEnemy();
}
```

איפה הם מופיעים? כדי לשמור על המשחק צפוי (וניתן לבדיקה), העמודה באה מרשימה קבועה: `columns[spawnCount % columns.length]`. האופרטור `%` גורם לאינדקס לעבור בצורה מעגלית, ולכן הרצף 150, 60, 240, 150, 100, 200 חוזר לנצח. כשאתם מרוצים מהמשחק, החליפו אותו ב-`Math.random() * (game.WIDTH - 20)` לעמודות אקראיות.

## שני מערכים נפגשים

כדי לגלות אילו כדורים פגעו באילו אויבים, בודקים **כל** כדור מול **כל** אויב עם שתי לולאות מקוננות:

```js
for (const b of bullets) {
  for (const e of enemies) {
    if (touching(b.x, b.y, 4, 10, e.x, e.y, 20, 20)) {
      b.alive = false;
      e.alive = false;
      score += 10;
    }
  }
}
```

עם כמה עשרות דברים על המסך זה מהיר מספיק. (משחק עם אלפי אובייקטים היה צריך שיטות חכמות יותר, כמו חלוקת המסך לאזורים.)

שימו לב שאף פעם לא מסירים דבר בתוך הלולאה: רק מסמנים. קריאות ה-`filter` בסוף `update` עושות את כל ההסרה במקום אחד.

## הופכים אותו לשלכם

כשמשחק היריות שלכם עובד, שחקו בו ואז שנו את האופי שלו. רעיונות קלים:

- ציירו ספינות עם כמה מלבנים, או עיגול לאויבים. השתמשו בצבעים שלכם.
- גרמו לניקוד לעלות מהר יותר עבור אויבים בעמודות הרחוקות.
- הגבירו את הקושי: כל 100 נקודות קצרו מעט את מרווח ההופעה.
- הוסיפו מצב `'menu'` עם כותרת והתחלה מחדש עם `enter` כמו בשיעור המצבים.
- גרמו לאויבים לירות בחזרה, או לנוע בזיגזג עם `Math.sin(game.time() * 3)`.

> **שימו לב:** אם מסירים פריטים עם `splice` בתוך לולאת `for...of`, הפריט הבא מדולג. סמנו וסננו עם `filter` במקום.
>
> **שימו לב:** כששני כדורים פוגעים באותו אויב בפריים אחד, שניהם נספרים. זה בסדר למשחק הזה, אבל אם זה חשוב, בדקו את `e.alive` לפני מתן הנקודות.
>
> **שימו לב:** `TypeError: Cannot read properties of undefined (reading 'x')` אומרת לעיתים קרובות שסיננתם מערך ואז השתמשתם באינדקס ישן, או שכתבתם תכונה אחרת (`e.X`).
>
> **שימו לב:** משחק שנהיה איטי יותר ויותר הוא כמעט תמיד מערך שאף פעם לא מתכווץ. ודאו שכדורים שיצאו מהמסך מסוננים החוצה.

> **תורכם:** השלימו את חמשת השלבים הממוספרים ב-`update`: ירו עם `bullets.push` והקירור, הזיזו כדורים ואויבים, תנו 10 נקודות על כל כדור ואויב שנוגעים זה בזה, הפחיתו חיים על כל אויב שמגיע לתחתית או לשחקן, ונקו עם `filter` לפני המעבר ל-`'gameover'` כשהחיים נגמרו.
