עד עכשיו המשחקים שלכם נמשכים לנצח. למשחקים אמיתיים יש התחלה, אמצע וסוף: מסך פתיחה, המשחק, מסך "Game Over". הם נותנים לשחקן שלושה חיים וסופרים נקודות. בשיעור הזה תוסיפו את המבנה שעושה את כל זה, ותתחילו ברעיון החשוב ביותר: ה**מצב** (state).

## מצבים

**מצב** הוא משתנה (variable) שנותן שם למה שהמשחק עושה כרגע:

```js
let state = 'playing';     // or 'gameover'
```

אחר כך `update` ו-`draw` שואלות איפה אנחנו ומתנהגות בהתאם:

```js
function update(dt) {
  if (state === 'playing') {
    // move things, check hits, ...
  } else {
    // wait for the player to press a key
  }
}
```

משתמשים ב-`===` כדי **להשוות** (שלושה סימני שווה). סימן `=` יחיד **שומר** ערך, ולכן `if (state = 'gameover')` היה דורס את המצב והיה תמיד נכון, באג מפורסם של מתחילים. הערכים בתוך המרכאות נקראים **מחרוזות** (strings).

במשחק גדול יותר יכולים להיות `'menu'`, ‏`'playing'`, ‏`'paused'`, ‏`'gameover'` ו-`'won'`. התבנית נשארת זהה: משתנה אחד, `if` אחד לכל מצב.

## חיים וניקוד

שניהם מספרים פשוטים שמוגדרים בראש הקובץ:

```js
let lives = 3;
let score = 0;
```

כשקורה משהו טוב, `score += 1`. כשקורה משהו רע, `lives -= 1`, ואז חייבים לבדוק אם זה היה החיים האחרון:

```js
lives -= 1;
if (lives <= 0) {
  state = 'gameover';
}
```

השתמשו ב-`<= 0` במקום `=== 0` כרשת ביטחון: אם משהו יפחית פעם 2 חיים בבת אחת, לא תדלגו מעל האפס.

## הבלוק הנופל

במשחק בשיעור הזה יש בלוק אחד שנופל מלמעלה. הבלוקים מגיעים בשלוש עמודות, אחד אחרי השני (הרשימה `lanes`), והשחקן צריך לעמוד במקום הנכון. יש שתי דרכים שבהן בלוק יכול להסתיים:

1. הוא **נוגע בשחקן**: מאבדים חיים. מזהים את זה עם הפונקציה `touching` מהשיעור על התנגשות.
2. הוא **נופל מהתחתית** (`block.y > game.HEIGHT`) בלי לגעת: השחקן התחמק ממנו, ולכן מקבלים נקודה.

בשני המקרים `nextBlock()` שולחת את הבלוק בחזרה למעלה בעמודה הבאה. שימוש ב-`else if` למקרה השני מבטיח שבלוק יכול להיספר רק פעם אחת בפריים.

## התחלה מחדש

כדי לשחק שוב, כל משתנה חייב לחזור לערך ההתחלתי שלו. כתיבה של זה בתוך פונקציה (`restart()`) שומרת את זה במקום אחד, ואפשר לקרוא לה מכל מקום:

```js
} else {
  if (game.keyPressed('enter')) {
    restart();
  }
}
```

השתמשו ב-`keyPressed` (נכונה בפריים האחד שבו המקש יורד) ולא ב-`keyDown`, אחרת שחקן שעדיין מחזיק את enter היה מתחיל מחדש שוב ושוב.

## מציירים את הדבר הנכון

גם `draw` מסתכלת על המצב. במצב `'playing'` היא מציירת את העולם, ובמצב `'gameover'` היא מציירת את ההודעה. הניקוד והחיים מצוירים בשני המצבים כדי שהשחקן יוכל לראות את התוצאה הסופית.

> **שימו לב:** `if (state = 'gameover')` (סימן שווה אחד) אינו השוואה. זו הצבה, והתנאי תמיד נכון.
>
> **שימו לב:** שגיאות כתיב בשמות מצבים (`'gameOver'` במקום אחד ו-`'gameover'` באחר) שוברות את המשחק בשקט, כי JavaScript לא מתלוננת. העתיקו והדביקו את המילים, או שמרו אותן בקבועים.
>
> **שימו לב:** אם שוכחים לאפס **כל** משתנה ב-`restart()`, הסיבוב השני מתחיל עם ערכים ישנים, כמו ניקוד שעדיין 5.
>
> **שימו לב:** אם תצוגת החיים מציגה `-1`, בדקתם `=== 0` אחרי שהפחתתם פעמיים או ששכחתם לבדוק בכלל.

## להמשיך הלאה

נסו מצב `'menu'` שמחכה ל-space לפני שהמשחק מתחיל, או שמרו את הניקוד הטוב ביותר במשתנה ש-`restart()` לא מאפסת.

> **תורכם:** בענף `'playing'`, כשהבלוק נוגע בשחקן, הפחיתו חיים, קראו ל-`nextBlock()` ועברו למצב `'gameover'` כשלא נשארו חיים. אחרת, כשהבלוק עובר את התחתית, הוסיפו נקודה וקראו ל-`nextBlock()`. בענף סיום המשחק, קראו ל-`restart()` כשנלחץ enter.
