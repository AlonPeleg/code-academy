משחק לא כל כך מהנה אם אפשר רק לצפות בו. בשיעור הזה תתנו לשחקן שליטה: מקשי החצים יזיזו ריבוע על המסך. תלמדו איך לשאול את המקלדת מה קורה, ואיך `if` מאפשר לקוד שלכם להגיב.

## לשאול את המקלדת

המנוע זוכר אילו מקשים לחוצים כרגע. שואלים באמצעות `game.keyDown('name')`, שמחזירה `true` או `false`:

```js
if (game.keyDown('right')) {
  x += SPEED * dt;
}
```

קראו את זה כמו אנגלית פשוטה: *אם מקש ימינה לחוץ, הוסיפו SPEED כפול dt ל-x*. משפט `if` מריץ את הקוד שבתוך הסוגריים המסולסלים רק כשהתנאי (condition) שבתוך הסוגריים העגולים הוא `true`. מכיוון ש-`update` רצה בכל פריים, הריבוע ממשיך לנוע כל עוד מחזיקים את המקש, ועוצר כשמרפים ממנו.

שמות המקשים הם טקסט באותיות קטנות בתוך מרכאות: `'left'`, `'right'`, `'up'`, `'down'`, `'space'`, `'enter'`, והאותיות `'a'`, `'d'`, `'w'`, `'s'`, `'z'`, `'x'`. כך אפשר להציע שליטה עם WASD וגם עם החצים.

## כיוון וסימנים

במסך הזה `x` גדל ימינה ו-`y` גדל **כלפי מטה**. לכן:

| מקש | מה משתנה |
| --- | --- |
| right | `x` גדל: `x += SPEED * dt` |
| left | `x` קטן: `x -= SPEED * dt` |
| down | `y` גדל: `y += SPEED * dt` |
| up | `y` קטן: `y -= SPEED * dt` |

`+=` מוסיף למשתנה, ו-`-=` מחסר ממנו. לכל מקש יש `if` משלו, ולכן החזקת שני מקשים בו-זמנית (ימינה ולמטה) מזיזה באלכסון. לעתים קרובות זה בדיוק מה ששחקנים מצפים לו.

## const לעומת let

בקוד ההתחלתי `SIZE` ו-`SPEED` מוגדרים עם `const`. `const` הוא משתנה שאי אפשר לתת לו ערך חדש לעולם, וזה מושלם להגדרות כמו גדלים, מהירויות וצבעים. השתמשו ב-`let` עבור ערכים שמשתנים עם הזמן, כמו `x` ו-`y`. הרגל נפוץ הוא לכתוב הגדרות באותיות גדולות, וכך להבהיר לקורא ש"זו הגדרה".

למה לטרוח עם הגדרות בעלות שם? אם `120` מופיע בארבעה מקומות, זה "מספר קסם" (magic number): כדי שהשחקן יהיה מהיר יותר צריך למצוא ולשנות את כולם. עם `SPEED` משנים שורה אחת.

## מקשים שקורים פעם אחת

יש פעולות שצריכות לקרות **פעם אחת** בכל לחיצה: קפיצה, ירי של כדור בודד, השהיה. עבורן משתמשים ב-`game.keyPressed('space')`. היא `true` רק בפריים היחיד שבו המקש נלחץ לראשונה, ו-`false` כל עוד הוא נשאר לחוץ. תשתמשו בה בהמשך המסלול.

```js
if (game.keyPressed('space')) {
  console.log('bang!');   // prints once per push, not 60 times a second
}
```

## בדיקה עם מקשים מתוסרטים

כשלוחצים על **Check answer**, אף אדם לא מקליד. הבודק "מחזיק" מקשים בשבילכם לפי תסריט (למשל ימינה למשך 30 פריימים, ואז למטה למשך 30 פריימים) ואז מסתכל על המשתנים שלכם. לכן לוגיקת המשחק צריכה לחיות במשתנים כמו `x` ו-`y`: הבודק יכול לקרוא אותם.

> **שימו לב:** `game.keyDown(left)` בלי מרכאות פירושו "המשתנה בשם left", ומניב `ReferenceError: left is not defined`. שם המקש חייב להיות טקסט בתוך מרכאות: `'left'`.
>
> **שימו לב:** שימוש ב-`else if` לכל ארבעת הכיוונים גורם לכך שרק כיוון אחד עובד בכל פעם (אין תנועה באלכסון). כאן עדיף להשתמש בארבעה משפטי `if` נפרדים.
>
> **שימו לב:** אות גדולה בשם מקש (`'Left'`) מתקבלת, אבל `'ArrowLeft'` אינו שם שהמנוע הזה מכיר. השתמשו בשמות הפשוטים.
>
> **שימו לב:** אם הריבוע זז לכיוון הלא נכון כשלוחצים למעלה, כנראה כתבתם `y +=` במקום `y -=`. זכרו ש-y גדל כלפי מטה.

## להתקדם הלאה

הוסיפו גם שליטה עם WASD (`game.keyDown('a') || game.keyDown('left')`), או גרמו לשחקן להיות מהיר יותר כל עוד המקש `'z'` לחוץ.

> **תורכם:** השלימו את `update` כך שמקשי שמאלה, למטה ולמעלה יזיזו את הריבוע, בדיוק כמו מקש ימינה. ודאו שהחזקת שמאלה מקטינה את `x` ושלמעלה מקטינה את `y`.
