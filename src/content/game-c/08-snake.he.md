סנייק מלמד את אחד הרעיונות השימושיים ביותר במשחקים: **רשת** (grid) ו**רשימה שגדלה**. תשמרו את הנחש כמערך (array) של תאים, תזיזו אותו על ידי הזזת המערך, ותאריכו אותו כשהוא אוכל.

## קואורדינטות של רשת

המסך הוא 320 על 240 פיקסלים. אנחנו חותכים אותו לריבועים של 20 פיקסלים, וכך מקבלים רשת של 16 עמודות ו-12 שורות. הנחש חי בקואורדינטות של **תאים**, כמו `(4, 6)`, ורק כשמציירים הופכים תאים לפיקסלים:

```c
#define CELL 20
engine_rect(cell.x * CELL, cell.y * CELL, CELL, CELL, RGB_GREEN);
```

עבודה בתאים הופכת את הכללים לקלים: "הנחש זז תא אחד", "האוכל נמצא בתא (8, 6)", "הקיר נמצא בעמודה 16".

## הנחש הוא מערך של תאים

```c
typedef struct { int x, y; } Cell;

Cell body[MAX_LEN] = {{4, 6}, {3, 6}, {2, 6}};   // body[0] is the head
int len = 3;
```

אנחנו שומרים מקום ל-`MAX_LEN` תאים, אבל רק `len` מהם בשימוש. זו הדרך הסטנדרטית לבנות ב-C רשימה שגדלה: מערך גדול מספיק וספירה. `body[0]` הוא הראש ו-`body[len - 1]` הוא הזנב.

## תנועה כל N פריימים

לולאת המשחק רצה 30 פעמים בשנייה, אבל נחש שזז 30 תאים בשנייה אי אפשר לנווט. לכן העולם **עושה צעד** רק כל 5 פריימים:

```c
if (engine_frame() % STEP_FRAMES == 0) {
    // one step of the snake
}
```

`%` הוא שארית החילוק. `engine_frame() % 5` הוא 0 בפריימים 0, 5, 10, 15... ולכן הנחש זז 6 פעמים בשנייה, בזמן שהמקשים עדיין נקראים בכל פריים.

## זחילה

כדי לזוז תא אחד, הראש עובר לתא חדש וכל קטע אחר עובר למקום של הקטע שלפניו. התא הישן של הזנב פשוט נשכח:

```c
for (int i = len - 1; i > 0; i--) {
    body[i] = body[i - 1];     // copy the segment in front of me
}
body[0] = head;                 // the new head position
```

למה לעבור **אחורה**? כשהולכים מהזנב לכיוון הראש, כל העתקה קוראת תא שעדיין לא נדרס. אם הולכים קדימה, `body[1] = body[0]` ואז `body[2] = body[1]` היו צובעים את תא הראש על כל הנחש.

## אכילה גורמת לו לגדול

גדילה היא פשוט "לא לשכוח את הזנב הפעם". מגדילים את `len` באחד **לפני** ההזזה:

```c
if (head.x == food.x && head.y == food.y) len++;
```

אז הלולאה מתחילה באינדקס האחרון החדש ומעתיקה את הזנב הישן למקום החדש. הנחש ארוך בתא אחד. מקומות האוכל קבועים במערך (`foods[]`) ו-`next_food` אומר איזה מהם נמצא על הלוח, כך שהמשחק צפוי לגמרי: אותם מקשים תמיד נותנים אותה תוצאה.

## הגה

הכיוון נשמר כ-`dx`, `dy` (אחד מהם הוא אפס). לחיצה על מקש משנה אותו, אבל נחש לא יכול להסתובב לתוך עצמו, ולכן מתעלמים מהכיוון ההפוך:

```c
if (key_pressed(KEY_LEFT) && dx == 0) { dx = -1; dy = 0; }
```

לנחש שנע ימינה יש `dx == 1`, ולכן מתעלמים מהמקש שמאלה. כשהוא נע למעלה או למטה (`dx == 0`) מותר.

> **שימו לב:**
> - הזזת המערך **קדימה** נותנת נחש שמורכב מתא אחד שחוזר על עצמו. תמיד מעתיקים מהזנב כלפי מעלה.
> - אם שוכחים `len++` הנחש מחליק אבל אף פעם לא גדל. הגדלת `len` מעבר ל-`MAX_LEN` כותבת מחוץ למערך: התנהגות לא מוגדרת (undefined behavior), ולרוב קריסה (`Segmentation fault`).
> - השוואת שני תאים עם `==` לא מתקמפלת עבור structs (`invalid operands to binary ==`). משווים את השדות: `a.x == b.x && a.y == b.y`.
> - מאקרואים של צבעים כמו `RGB_RED` מתרחבים לשלושה מספרים, ולכן אי אפשר לכתוב `cond ? RGB_RED : RGB_GREEN`. השתמשו ב-`if` וב-`else` במקום זה (gcc מזהיר `left-hand operand of comma expression has no effect`).

## להמשיך הלאה

התוכנית כבר מסיימת את המשחק כשנוגעים בקיר. הוסיפו לולאה שבודקת אם הראש החדש נוחת על תא כלשהו של הגוף, וסיימו את המשחק גם בנשיכה. אחר כך ערכו את קלט השחקן (Player input) כך שייקח מסלול ארוך יותר שאוכל את האוכל האחרון ב-(14, 1).

> **תורכם:** בצעד, (1) כשהראש החדש נמצא על `foods[next_food]` (ו-`next_food < NUM_FOODS`) הוסיפו 1 ל-`len` ו-1 ל-`next_food`, ואז (2) הזיזו את הגוף מהזנב קדימה ושמרו את הראש ב-`body[0]`. עם המקשים שניתנו התוכנית אמורה להדפיס `length: 7`.
