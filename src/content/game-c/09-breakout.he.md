ברייקאאוט הוא משחק של הרבה מטרות קטנות וקפיצה חכמה אחת. כאן תבנו **קיר של לבנים** ממערך (array) ולולאה, ותתנו למחבט **קפיצה בזווית** שמאפשרת לשחקן לכוון.

## קיר מלולאה אחת

24 לבנים ב-8 עמודות ו-3 שורות. אנחנו לא מקלידים 24 מיקומים ביד. לולאה אחת וקצת חשבון מציבות אותם:

```c
for (int i = 0; i < NUM_BRICKS; i++) {
    bricks[i].box.x = 1 + (i % COLS) * 40;     // column = i % 8
    bricks[i].box.y = 30 + (i / COLS) * 16;    // row    = i / 8
    bricks[i].box.w = 38;
    bricks[i].box.h = 12;
    bricks[i].alive = 1;
}
```

זה **טריק הרשת**: פריסה דו-ממדית שנשמרת במערך חד-ממדי. עבור אינדקס `i`, העמודה היא השארית `i % COLS` והשורה היא החילוק `i / COLS` (חילוק שלמים זורק את השבר). אינדקס 0 הוא הלבנה השמאלית העליונה, אינדקס 7 הימנית העליונה, ואינדקס 8 פותח את השורה השנייה.

כל לבנה היא struct עם מלבן ודגל, כמו המטבעות בשיעור Coin Collector:

```c
typedef struct { Rect box; int alive; } Brick;
```

שבירת לבנה לא מכווצת את המערך אף פעם. אנחנו רק קובעים `alive = 0`, מדלגים עליה בציור ומתעלמים ממנה בהתנגשויות. מספר הלבנים שנשארו הוא מונה שמורידים באחד בכל פעם.

> הצבעים עובדים דרך טבלה. `RGB_RED` מתרחב לשלושה מספרים, ולכן אפשר לשים אותו בתוך סוגריים מסולסלים: `static const int palette[3][3] = {{RGB_RED}, {RGB_ORANGE}, {RGB_YELLOW}};`. אז `palette[row]` הוא צבע אחד.

## הכדור והקפיצות שלו

הכדור זז לפי `vx` ו-`vy` בכל פריים, וכל קיר הופך אחד מהם:

```c
if (ball.x < 0 || ball.x + ball.size > SCREEN_W) ball.vx = -ball.vx;
if (ball.y < 0) ball.vy = -ball.vy;
```

אין קיר תחתון: אם הכדור נופל מתחת למסך, הסיבוב נגמר (`playing = 0`) והכול קופא.

## פגיעה בלבנה

עבור הלבנים אנחנו עוברים על המערך ובודקים את התיבה של הכדור מול כל לבנה שעדיין חיה:

```c
for (int i = 0; i < NUM_BRICKS; i++) {
    if (bricks[i].alive && overlaps(ball_box, bricks[i].box)) {
        bricks[i].alive = 0;
        bricks_left--;
        ball.vy = -ball.vy;
        break;
    }
}
```

שני פרטים חשובים. `alive &&` מגיע ראשון כדי לדלג על לבנים מתות. וה-`break` עוצר את הלולאה אחרי הפגיעה **הראשונה**: אם הכדור נגע בשתי לבנים בפריים אחד והיינו הופכים את `vy` פעמיים, הוא היה עובר ישר דרך שתיהן. היפוך `vy` הוא פישוט (משחק אמיתי בודק אם הכדור פגע בצד או בתחתית הלבנה), אבל הוא מספיק טוב ושומר את הקוד קצר.

## מחבט שאפשר לכוון

אם המחבט תמיד היה מחזיר את הכדור באותה זווית, המשחק היה משעמם, ולבנים מסוימות היו בלתי נגישות. הטריק הוא להשתמש ב**מקום שבו הכדור נוגע במחבט**:

```c
int offset = (ball.x + ball.size / 2) - (paddle.x + paddle.w / 2);
ball.vx = offset / 5;
```

`offset` הוא המרחק ממרכז המחבט למרכז הכדור: שלילי בחצי השמאלי, חיובי בחצי הימני. פגיעה באמצע שולחת את הכדור ישר למעלה, פגיעה בקצה הימני שולחת אותו בחדות ימינה. החילוק ב-5 הופך פיקסלים למהירות סבירה, בערך בין -5 ל-+5.

בנוסף, כשהכדור קופץ אנחנו מניחים אותו על גבי המחבט (`ball.y = paddle.y - ball.size`) וקופצים רק כש-`ball.vy > 0` (הכדור נע למטה). בלי שני הכללים האלה הכדור יכול להיתקע בתוך המחבט ולהחליף כיוון בכל פריים, וזה נראה כמו רעידה.

> **שימו לב:**
> - אם שוכחים `break` אחרי פגיעה בלבנה: כמה לבנים נעלמות בפריים אחד והכדור חודר דרך הקיר.
> - אם `i / COLS` ו-`i % COLS` מוחלפים: הקיר יוצא 3 עמודות על 8 שורות, וזה לא נכנס במסך.
> - כתיבת `if (bricks[i].alive = 0)` (סימן `=` אחד) מבצעת השמה במקום השוואה; gcc מזהיר `suggest parentheses around assignment used as truth value`.
> - חילוק ה-offset ב-`5.0` הופך אותו ל-float, והשמה שלו ל-int חותכת בשקט את הספרות אחרי הנקודה.

## להמשיך הלאה

ספרו כמה פעמים הכדור נגע במחבט והדפיסו גם את זה. הפכו את הכדור למהיר יותר בפיקסל אחד כל 3 לבנים. הלשונית קלט השחקן (Player input) מכילה את לחיצות המקשים של המחבט; ערכו אותן וראו איך מספר הלבנים שנשארו משתנה.

> **תורכם:** (1) מחבט: כש-`ball.vy > 0` ו-`ball_box` חופף ל-`paddle`, קבעו `ball.vy = -ball.vy`, `ball.y = paddle.y - ball.size` ו-`ball.vx = (ball.x + ball.size / 2 - (paddle.x + paddle.w / 2)) / 5`. (2) לבנים: עברו בלולאה על כל הלבנים; עבור הראשונה שחיה וחופפת ל-`ball_box` קבעו `alive = 0`, הפחיתו 1 מ-`bricks_left`, הפכו את `ball.vy` ובצעו `break`. עם המקשים שניתנו התוכנית מדפיסה `bricks left: 5`.
