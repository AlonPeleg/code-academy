ברוכים הבאים לתכנות משחקים ב-C! בשיעור הזה תלמדו מהי **לולאת משחק** (game loop), הרעיון האחד שעומד מאחורי כל משחק שנוצר אי פעם, ותקבלו רשימה מלאה של כל מה שמנוע המיני יודע לעשות.

## הרעיון הגדול: חוברת הזזה

סרט הוא ערימה של תמונות נייחות שמוצגות מהר מספיק כדי שהעיניים יראו תנועה. משחק עובד באותו אופן. הוא מריץ לולאה, וכל סיבוב בלולאה הוא **פריים** (frame):

1. **עדכון**: משנים את המספרים שמתארים את העולם (מזיזים את השחקן, סופרים את הניקוד).
2. **ציור**: מציירים את העולם לפי המספרים האלה.
3. **הצגה**: אומרים למנוע שהתמונה הזאת הסתיימה.

המנוע הזה רץ ב-**30 פריימים בשנייה**, ולכן פריים אחד הוא 1/30 שנייה. הלולאה נראית כך:

```c
while (engine_running()) {
    /* update: change variables */
    /* draw: engine_clear(...), engine_rect(...), ... */
    engine_present();
}
```

`engine_running()` מחזירה אמת (true) עד שההקלטה נגמרת (180 פריימים, שהם 6 שניות, אלא אם מבקשים כמות אחרת). בכל פעם שקוראים לה היא גם מקדמת את המנוע לפריים הבא.

## קואורדינטות

המסך הוא **ברוחב 320 פיקסלים ובגובה 240**. הנקודה `(0, 0)` היא הפינה **השמאלית העליונה**. `x` גדל ימינה ו-`y` גדל **כלפי מטה**. מלבן מצויר מהפינה השמאלית העליונה שלו:

```c
engine_rect(50, 20, 30, 10, RGB_RED);   /* x, y, width, height, color */
```

## מדריך למנוע

כל מה שאפשר להשתמש בו. צבעים נכתבים כמילה אחת, כמו `RGB_RED`, והם מתרחבים לשלושה מספרים.

| פונקציה | מה היא עושה |
|---|---|
| `engine_running()` | תנאי הלולאה. אמת כל עוד נשארו פריימים, ומקדמת לפריים הבא. |
| `engine_present()` | מסיימת את הפריים. קראו לה פעם אחת בתחתית הלולאה. |
| `engine_clear(color)` | ממלאת את כל המסך בצבע אחד. |
| `engine_rect(x, y, w, h, color)` | מלבן מלא, ‏`(x, y)` היא הפינה השמאלית העליונה שלו. |
| `engine_circle(x, y, radius, color)` | עיגול מלא, ‏`(x, y)` הוא המרכז שלו. |
| `engine_line(x1, y1, x2, y2, color)` | קו בין שתי נקודות. |
| `engine_text(x, y, size, color, "text")` | מציירת טקסט. גודל 14 הוא התחלה טובה. |
| `key_down(KEY_...)` | אמת בכל פריים שהמקש לחוץ. |
| `key_pressed(KEY_...)` | אמת רק בפריים היחיד שבו המקש יורד. |
| `engine_frames(n)` | מקליטה `n` פריימים (ברירת מחדל 180, מקסימום 600). קראו לה לפני הלולאה. |
| `engine_frame()` | מספר הפריים הנוכחי, מתחיל מ-0. |
| `SCREEN_W`, `SCREEN_H` | גודל המסך: 320 ו-240. |

**צבעים:** `RGB_BLACK RGB_WHITE RGB_GRAY RGB_DARK RGB_RED RGB_ORANGE RGB_YELLOW RGB_GREEN RGB_CYAN RGB_BLUE RGB_PURPLE RGB_PINK`. אפשר גם לתת במקומם שלושה מספרים מ-0 עד 255: `engine_rect(10, 10, 20, 20, 255, 0, 0)`.

**מקשים:** `KEY_LEFT KEY_RIGHT KEY_UP KEY_DOWN KEY_SPACE KEY_A KEY_D KEY_W KEY_S KEY_Z KEY_X KEY_ENTER`.

## זו הקלטה שמנגנים מחדש

אי אפשר לשחק בתוכנית ה-C שלכם בזמן אמת בדפדפן. במקום זאת היא רצה על שרת עם **שחקן מתוסרט**: הלשונית *Player input* מכילה שורות כמו `10 right down` (בפריים 10, לחצו ימינה). התוכנית מציירת את כל הפריימים, והדפדפן מנגן אותם כמו וידאו. ערכו את שורות הקלט כדי "לשחק" במשחק שלכם אחרת, ואז לחצו שוב על Run.

כל מה ש-`printf` מדפיסה הוא פלט רגיל. אנחנו משתמשים בזה כדי להדפיס תוצאה סופית (כמו `final x: 200`) כך ש-**Check answer** יוכל לוודא את ההיגיון שלכם.

> **שימו לב:**
> - אם שוכחים את `#include "engine.h"` מקבלים שגיאות כמו `implicit declaration of function 'engine_running'`. השאירו את השורה הזאת מיד אחרי ה-include-ים הסטנדרטיים.
> - ציור לפני `engine_clear()` גורם לתמונות ישנות להישאר. קודם מנקים, אחר כך מציירים, ואז מציגים.
> - אם שוכחים את `engine_present()`, שום דבר לא מוצג: המנוע סופר פריים כגמור רק כשמציגים אותו.
> - שינוי של `x` אחרי קוד הציור אינו שגוי, אבל הוא גורם לתמונה לאחר בפריים אחד. קודם מעדכנים, ואז מציירים.

## להמשך

נסו `engine_circle(x, y, 15, RGB_CYAN)` במקום הריבוע, או שנו גם את `y` כדי שהצורה תנוע באלכסון. שנו את מהירות הריבוע וראו איך ה-`x` הסופי המודפס משתנה.

> **תורכם:** קראו ל-`engine_frames(90)` לפני הלולאה, והוסיפו `x += 2;` בתוך הלולאה כדי שהריבוע יזוז 2 פיקסלים ימינה בכל פריים. התוכנית צריכה להדפיס `final x: 200`.
