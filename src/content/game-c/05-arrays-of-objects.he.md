כדור אחד זה קל: שלושה משתנים. אבל משחק ירי צריך הרבה כדורים בבת אחת, ואתם לא יודעים מראש כמה. בשיעור הזה תשמרו **מערך** (array) בגודל קבוע של structs של כדורים ותשתמשו בדגל כדי לומר אילו משבצות בשימוש.

## מערך של structs

מערך הוא שורה ממוספרת של קופסאות מאותו טיפוס. נשלב את ה-struct `Bullet` מהשיעור הקודם עם מערך:

```c
#define MAX_BULLETS 4

typedef struct {
    int x, y;
    int active;
} Bullet;

Bullet bullets[MAX_BULLETS] = {0};     /* four bullets, all zero */

bullets[2].x = 100;                    /* index 2 = the THIRD bullet */
```

האינדקסים מתחילים ב-**0**, ולכן התקפים הם `0` עד `MAX_BULLETS - 1`. כתיבה ל-`bullets[4]` היא מחוץ לגבולות: C לא עוצרת אתכם, אבל תקלקלו זיכרון אחר.

`= {0}` ממלא הכול באפסים. זה חשוב: בלי זה מערך מקומי מתחיל עם שאריות אקראיות, וחלק מהכדורים ייראו כאילו הם עפים כבר בהתחלה.

## תבנית המאגר (pool)

מערכים ב-C לא יכולים לגדול, ולכן מתכנתי משחקים משתמשים לעיתים קרובות ב**מאגר** (pool): מספר קבוע של משבצות, ולכל אחת דגל `active`.

- **לירות** כדור: למצוא את המשבצת הראשונה שבה `active` הוא 0, למלא אותה ולקבוע `active = 1`.
- **עדכון**: לכל משבצת פעילה, להזיז את הכדור. כשהוא יוצא מהמסך, לקבוע `active = 0`. המשבצת פנויה עכשיו לשימוש חוזר.
- **ציור**: לצייר רק את המשבצות הפעילות.

שום דבר לא מוקצה ולא נמחק. כדור "מת" פשוט בכך שהדגל שלו מכובה.

## מעבר בלולאה על המאגר

```c
for (int i = 0; i < MAX_BULLETS; i++) {
    if (bullets[i].active) {
        bullets[i].y -= BULLET_SPEED;
    }
}
```

ללולאת `for` יש שלושה חלקים: התחלה (`int i = 0`), התנאי להמשיך (`i < MAX_BULLETS`), והצעד אחרי כל סיבוב (`i++`). בפנים, `bullets[i]` הוא הכדור הנוכחי, ו-`bullets[i].y` הוא השדה שלו.

שימו לב לפרמטר המערך בפונקציות: `void update_bullets(Bullet bullets[])`. מערכים מועברים אוטומטית לפי הכתובת שלהם, ולכן הפונקציה משנה את הכדורים *האמיתיים* ולא עותקים.

## יורים רק כשהמקש נלחץ

```c
if (key_pressed(KEY_SPACE) && fire_bullet(bullets, player_x + 8, 200)) fired++;
```

`&&` הוא "וגם", והוא עוצר ברגע שהצד השמאלי שקרי. `key_pressed` אמיתי למסגרת (frame) אחת בכל לחיצה, ורק אז נקראת `fire_bullet`. היא מחזירה 1 אם נמצאה משבצת פנויה, ולכן `fired` סופר רק את הירי שבאמת קרה. אם כל ארבעת הכדורים תפוסים, הירייה מתעלמת.

> **שימו לב:**
> - שוכחים לקבוע `active = 1` בזמן הירי: הכדור "נוצר" אבל אף פעם לא זז ולא מצויר.
> - שוכחים `active = 0` כשהכדור יוצא: המשבצות מתמלאות ואי אפשר לירות יותר לעולם.
> - לולאה עם `i <= MAX_BULLETS` קוראת איבר אחד אחרי הסוף (מחוץ לגבולות). השתמשו ב-`<`.
> - שימוש ב-`=` במקום ב-`==` בתנאי, כמו `if (bullets[i].active = 0)`, מבצע השמה במקום להשוות. gcc מזהיר: `suggest parentheses around assignment used as truth value`.

## להמשך

הגדילו את המאגר (שנו את `MAX_BULLETS` ל-10) וראו יותר כדורים עפים. או הפכו את הכדורים למהירים פי שניים עם `BULLET_SPEED 12` וראו כמה יריות מתקבלות.

> **תורכם:** סיימו את `fire_bullet` (מצאו משבצת פנויה, מלאו אותה, החזירו 1) ואת `update_bullets` (הזיזו כדורים פעילים למעלה ב-`BULLET_SPEED` וכבו אותם כש-`y < 0`). עם תסריט המקשים הנתון התוכנית צריכה להדפיס `fired: 7, in flight: 1`.
