זה פרויקט הסיום: משחק יריות חלל קטן שמשתמש כמעט בכל מה שלמדתם במסלול. יש לכם ספינה, כדורים, אויבים נופלים, ניקוד ושלושה חיים. העבודה כאן היא **ארגון** של תוכנית גדולה יותר כדי שתישאר קריאה.

## חלקים שאתם כבר מכירים

| רעיון | מתוך | שימוש כאן |
|---|---|---|
| structs | שיעור 4 | ה-`Thing` שהוא ספינה, כדור או אויב |
| מערכים של אובייקטים | שיעור 5 | מאגרים של כדורים ואויבים |
| בדיקת חפיפה | שיעור 6 | כדור פוגע באויב, אויב פוגע בספינה |
| key_down / key_pressed | שיעורים 2 ו-3 | הגה וירי |
| צעד כל N פריימים | Snake | אויב חדש כל 30 פריימים |
| מהירות | Pong | כדורים למעלה ב-8, אויבים למטה ב-2 |

## struct אחד לכול

ספינות, כדורים ואויבים הם כולם מלבנים שיכולים להיות על המסך או לא. struct אחד מכסה את כולם:

```c
typedef struct { int x, y, w, h, active; } Thing;
```

`active` הוא דגל ה-**חי** משיעור Breakout. קביעתו ל-0 מסירה את הדבר מהמשחק בלי להזיז שום דבר בזיכרון.

## מאגר של משבצות

כדורים באים והולכים. במקום להקצות זיכרון, אנחנו שומרים **מאגר** (pool) קבוע: מערך של `MAX_BULLETS` דברים, רובם לא פעילים. כדי לירות, תופסים את המשבצת החופשית הראשונה:

```c
static void spawn(Thing *list, int n, int x, int y, int w, int h) {
    for (int i = 0; i < n; i++) {
        if (!list[i].active) { list[i] = (Thing){x, y, w, h, 1}; return; }
    }
}
```

אם כל המשבצות תפוסות, הקריאה לא עושה כלום. זה נותן כלל משחק בחינם: לכל היותר 4 כדורים באוויר, ולכן אי אפשר פשוט להחזיק את האש לחוץ. `(Thing){x, y, w, h, 1}` הוא **compound literal**: struct זמני שנבנה במקום ומועתק אל המשבצת.

## אריזת המצב ב-struct בשם Game

במשחק גדול יותר יש הרבה משתנים ששייכים יחד. אריזתם ב-struct אחד מאפשרת להעביר לפונקציה מצביע יחיד:

```c
typedef struct {
    Thing player, bullets[MAX_BULLETS], enemies[MAX_ENEMIES];
    int score, lives, lane;
} Game;

static void step(Game *g) { ... g->score += 10; ... }
```

`main` נשארת קטנטנה: `if (g.lives > 0) step(&g);` ואז ציור. הפרדת **העדכון** מ**הציור** היא ההרגל ששומר על משחקים אמיתיים בני-ניהול. כשהחיים נגמרים, העולם פשוט מפסיק להתעדכן, והמסך מציג GAME OVER.

## אויבים "אקראיים" דטרמיניסטיים

אין כאן `rand()`, כי הקלטה צריכה להישמע שוב בצורה זהה. אויבים מופיעים ב-`LANES[lane++ % NUM_LANES]`, רשימה קבועה של מיקומי x שחוזרת על עצמה. ה-`%` גורם לאינדקס לחזור ל-0 אחרי המסלול האחרון. משחק שנראה אקראי אבל הוא טבלה חוזרת נקרא **מתוסרט** (scripted) או **פסאודו-אקראי**, וכך גם בודקים משחק.

## שתי לולאות של התנגשות

הכללים המרכזיים הם שתי לולאות קצרות:

- **ירי:** לכל כדור פעיל ולכל אויב פעיל, אם הם חופפים, מכבים את שניהם ומוסיפים 10 נקודות. שתי לולאות מקוננות משוות כל זוג. עם 4 כדורים ו-8 אויבים זה רק 32 השוואות בפריים.
- **נזק:** כל אויב פעיל שחופף לספינה, או שנפל מתחת למסך (`y > SCREEN_H`), מכובה וגורם לאובדן חיים אחד. לתת לאויב לברוח כואב בדיוק כמו להיפגע.

שימו לב לסדר הבדיקות בתוך הלולאה הכפולה: `bullets[b].active && enemies[e].active && overlaps(...)`. אחרי שכדור פוגע, הוא לא פעיל, ולכן הוא לא יכול להרוס גם אויב שני באותו פריים.

> **שימו לב:**
> - שימוש במצביע לתוך מערך (`Thing *en = &g->enemies[e]`) ואז שכחת `->`: `request for member 'active' in something not a structure or union`.
> - שכחת `active` בבדיקת הנזק: אויבים מתים ממשיכים לקחת חיים כל עוד הם יושבים בתחתית.
> - ניקוד בצד ה-`!active` בטעות: הנקודות גדלות ב-10 בכל פריים עבור כל אויב מת.
> - יצירת אויבים ב-`y = 0` גורמת להם להופיע בבת אחת. התחילו אותם ממש מעל המסך (`y = -16`) כדי שיחליקו פנימה.

## להמשיך הלאה

הפכו את האויבים למהירים יותר אחרי כל 5 חיסולים, הוסיפו סוג אויב שני ששווה 30 נקודות, או ציירו את החיים כספינות קטנות.

> **תורכם:** ב-`step`, הוסיפו (1) את לולאות הירי: כל כדור פעיל שחופף לאויב פעיל מכבה את שניהם ומוסיף 10 ל-`g->score`; (2) את לולאת הנזק: אויב פעיל שחופף ל-`g->player` או שיש לו `y > SCREEN_H` הופך ללא פעיל וגורם לאובדן חיים אחד (`g->lives--`). עם המקשים שניתנו התוכנית אמורה להדפיס `score: 110, lives: 2`.
