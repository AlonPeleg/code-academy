דמיינו שאתם כותבים חיבור ושומרים עותקים בשמות `essay-final.doc`, `essay-final-2.doc` ו-`essay-REALLY-final.doc`. **Git** עושה את העבודה הזאת כמו שצריך: היא זוכרת כל גרסה חשובה של הפרויקט, מי שינה מה ולמה, ומאפשרת לחזור אחורה בזמן. כל מתכנת מקצועי משתמש בה, ולכן זה כלי מצוין ללמוד ראשון.

## Git היא לא GitHub

אנשים מבלבלים בין השניים, אז נפריד ביניהם כבר עכשיו:

- **Git** היא תוכנה חינמית שרצה על המחשב שלכם ושומרת את ההיסטוריה של פרויקט.
- **GitHub** הוא אתר שאפשר להעלות אליו פרויקטים של Git כדי לשתף אותם, לגבות אותם ולעבוד יחד. יש אתרים דומים (GitLab, Bitbucket), וכולם משתמשים ב-Git מתחת לפני השטח.

תפגשו את GitHub בשיעורים האחרונים. קודם נלמד את Git עצמה.

## איפה אנחנו?

בשיעור הזה משתמשים בטרמינל תרגול. זה מחשב מדומה, ולכן שום דבר שתקלידו לא יכול לשבור כלום. אתם כותבים **סקריפט** (script): פקודה אחת בכל שורה. שורות שמתחילות ב-`#` הן הערות ומדלגים עליהן. לחצו על **הרצה** (Run) והטרמינל ידפיס כל פקודה אחרי `$`, ואחריה את התשובה שלה.

שתי פקודות עזר מהמעטפת (shell) הרגילה:

- `pwd` מדפיסה את התיקייה שאתם נמצאים בה (הקיצור של "print working directory").
- `ls` מציגה את רשימת הקבצים בתיקייה הזאת.

## יצירת מאגר

**מאגר** (repository, או בקיצור "repo") הוא תיקיית פרויקט ש-Git עוקבת אחריה. יוצרים אותו כך:

```bash
git init
```

הפקודה מדפיסה `Initialized empty Git repository in /home/learner/project/.git/`. Git יצרה תיקייה נסתרת בשם `.git`. שם נשמרת כל ההיסטוריה. לעולם אל תערכו אותה ידנית, ואם תמחקו אותה הפרויקט יאבד את ההיסטוריה שלו (הקבצים יישארו).

אם מריצים פקודת Git בתיקייה שאינה מאגר, Git אומרת את זה:

```
fatal: not a git repository (or any of the parent directories): .git
```

זו השגיאה הראשונה והנפוצה ביותר. פירושה פשוט "הריצו קודם `git init`, או עברו עם `cd` לתיקייה הנכונה".

## בקשת סטטוס

`git status` היא הפקודה שתשתמשו בה הכי הרבה. היא עונה על שלוש שאלות: באיזה ענף אני נמצא, מה השתנה, ומה Git מתעלמת ממנו או מחכה לו?

```bash
git status
```

במאגר חדש לגמרי היא אומרת `On branch main` (ענף הוא קו של היסטוריה, עוד על כך בשיעור 6) ו-`No commits yet` (עדיין לא נשמר כלום).

## יצירת קובץ

כדי שיהיה מה לעקוב אחריו, הטרמינל מאפשר ליצור קבצים עם `echo`:

```bash
echo "# My first project" > README.md
```

`echo` מדפיסה טקסט, ו-`>` מפנה את הטקסט לקובץ במקום למסך (היא יוצרת את הקובץ, או מחליפה אותו אם הוא קיים). בפרויקט אמיתי תשתמשו בעורך. כשתריצו `git status` שוב, הקובץ החדש יופיע תחת **Untracked files**: Git רואה אותו, אבל עדיין לא עוקבת אחריו. נתקן את זה בשיעור הבא.

> **שימו לב:**
> - `fatal: not a git repository` אומר שאתם לא נמצאים בתוך מאגר. הריצו קודם `git init`.
> - הרצה של `git init` פעמיים אינה מזיקה. Git עונה `Reinitialized existing Git repository`.
> - במחשב אמיתי צריך להתקין את Git פעם אחת ולהגיד לה מי אתם (`git config --global user.name "Your Name"` ו-`git config --global user.email "you@example.com"`). בטרמינל התרגול זה נעשה בשבילכם.
> - פקודות Git תמיד מתחילות במילה `git`. אם תקלידו רק `status` תקבלו `command not found`.

## להמשך

הריצו `git init` פעם שנייה וקראו את ההודעה. אחר כך צרו קובץ שני עם `echo "hello" > hello.txt` ובדקו ש-`git status` מציגה את שני הקבצים.

> **תורכם:** כתבו את שישה השלבים האלה ב-`session.sh`: הדפיסו את התיקייה (`pwd`), הריצו `git status` (זה ייכשל), הריצו `git init`, צרו את `README.md` עם התוכן `# My first project`, הריצו `git status` שוב, וסיימו עם `ls`. אחר כך לחצו על **בדיקת תשובה** (Check answer).
