שני כלים קטנים שהופכים את העבודה היומיומית לרגועה הרבה יותר: `.gitignore` שומר קבצים לא רצויים מחוץ למאגר, ו-`git stash` מאפשר להניח עבודה חצי גמורה על מדף לזמן מה.

## חלק א: .gitignore

יש קבצים שאסור לשמור בהיסטוריה:

- **סודות**: סיסמאות, מפתחות API, קבצי `.env`. ברגע שסוד נדחף ל-GitHub, צריך להתייחס אליו כאל סוד שנגנב.
- **תלויות (dependencies)**: תיקיות כמו `node_modules/` שאפשר לבנות מחדש והן ענקיות.
- **קבצים שנוצרים אוטומטית או אישיים**: לוגים (`*.log`), פלט של build, הגדרות עורך, `.DS_Store`.

בלי עזרה, `git status` מציג את כולם כקבצים שלא במעקב (untracked), ואפשר להוסיף אותם בטעות עם `git add .`. התרופה היא קובץ טקסט פשוט בשם **`.gitignore`** בשורש הפרויקט. כל שורה בו היא תבנית:

```
*.log
node_modules/
.env
```

- `*.log` הוא **תו כללי** (wildcard): ה-`*` מייצג טקסט כלשהו, ולכן התבנית מתאימה ל-`debug.log`, ל-`build.log` וכן הלאה.
- `node_modules/` עם לוכסן בסוף פירושו תיקייה שלמה.
- `.env` מתאים לשם הקובץ המדויק הזה.
- שורות שמתחילות ב-`#` הן הערות, ושורות ריקות מתעלמים מהן.

יוצרים אותו כמו כל קובץ. אנחנו בונים אותו שורה אחרי שורה עם `echo`: השורה הראשונה עם `>` (יצירה), הבאות עם `>>` (הוספה לסוף):

```bash
echo "*.log" > .gitignore
echo "node_modules/" >> .gitignore
echo ".env" >> .gitignore
```

עכשיו `git status` מציג רק את `.gitignore` כקובץ שלא במעקב. הקבצים שהתעלמו מהם בלתי נראים ל-Git, ו-`git add .` מדלג עליהם. את הקובץ `.gitignore` עצמו **כדאי לעשות לו commit**, כדי שכל הצוות יתעלם מאותם דברים. לשפות פופולריות קיימות רשימות מוכנות (GitHub אפילו מציע אותן כשיוצרים מאגר).

מלכוד חשוב אחד: `.gitignore` משפיע רק על קבצים ש-Git **עדיין לא עוקב** אחריהם. אם כבר עשיתם commit ל-`.env`, התעלמות ממנו אחר כך לא מסירה אותו. צריך להריץ `git rm --cached .env` (הוא מפסיק לעקוב אבל משאיר את הקובץ שלכם) ולעשות commit. וזכרו שהסוד עדיין נמצא בהיסטוריה הישנה.

## חלק ב: git stash

אתם באמצע שינוי כשהמנהל מבקש תיקון דחוף. העריכה שלכם לא מוכנה ל-commit, אבל גם אי אפשר לעבור למשימה אחרת עם תיקייה מבולגנת. משתמשים ב-stash:

```bash
git stash
```

```
Saved working directory and index state WIP on main: 627aad0 Add .gitignore
```

Git שומר את השינויים שלא נעשה להם commit על מדף ומחזיר את הקבצים שלכם ל-commit האחרון. התיקייה נקייה, ולכן אפשר לתקן את הבאג, לעבור בין ענפים ולעשות commit. מאוחר יותר:

```bash
git stash list      # stash@{0}: WIP on main: 627aad0 Add .gitignore
git stash pop       # put the changes back and remove them from the shelf
```

גם `git stash apply` מחזיר את השינויים, אבל משאיר אותם על המדף. אפשר לעשות stash כמה פעמים; הרשומות ממוספרות `stash@{0}` (החדשה ביותר), `stash@{1}` וכן הלאה. כברירת מחדל stash מטפל רק בשינויים בקבצים שבמעקב; הוסיפו `-u` כדי לכלול גם קבצים שלא במעקב (ב-Git אמיתי).

> **שימו לב:**
> - אל תכתבו תבניות `.gitignore` עם רווח בהתחלה או עם לוכסנים הפוכים של Windows; השתמשו בלוכסנים רגילים (`logs/`).
> - אם קובץ לא מתעלמים ממנו, כנראה שהוא כבר במעקב. בדקו עם `git ls-files` (ב-Git אמיתי) והשתמשו ב-`git rm --cached`.
> - `git stash pop` יכול לגרום לקונפליקט אם אותן שורות השתנו בינתיים. פתרו אותו כמו קונפליקט מיזוג. רשומת ה-stash נשארת אז כדי שלא תאבדו אותה.
> - קל לשכוח stash. הסתכלו מדי פעם ב-`git stash list`, ואל תשתמשו בו כאחסון לטווח ארוך: בשביל זה יש ענף.

> **תורכם:** עקבו אחרי ההערות הממוספרות. בנו את `.gitignore` עם שלוש השורות `*.log`, `node_modules/` ו-`.env`, בדקו את הסטטוס, הוסיפו ל-staging ועשו commit עם ההודעה `Add .gitignore`, ובדקו שוב את הסטטוס. בחלק ב הניחו את העריכה בצד עם `git stash`, בדקו את הסטטוס, הציגו את רשימת ה-stash, ו(אחרי ה-commit של התיקון הדחוף בקוד ההתחלה) החזירו את העריכה עם `git stash pop`, בדקו את הסטטוס והציגו את רשימת ה-stash שוב.
