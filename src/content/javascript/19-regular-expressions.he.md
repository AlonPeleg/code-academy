מחרוזות מסתירות לעיתים קרובות מבנה: תאריכים, מספרי טלפון, מספרי הזמנה, צבעים, כתובות אימייל. **ביטוי רגולרי** (regular expression, או regex) הוא דרך קומפקטית לתאר תבנית, כדי שתוכלו למצוא אותה, לבדוק אותה, לחלץ ממנה חלקים או לכתוב אותה מחדש. ביטויים רגולריים נראים מפחידים בהתחלה, אבל אבני הבניין מעטות ואפשר ללמוד אותן אחת אחת.

## יצירה ובדיקה

ליטרל של regex יושב בין שני לוכסנים. **דגלים** (flags) אופציונליים באים אחרי הלוכסן הסוגר:

```js
const re = /cat/i;
console.log(re.test("Concatenate")); // prints: true  (i = ignore case)
```

`re.test(text)` עונה true או false. דגלים נפוצים: `g` (גלובלי, מוצא את כל ההתאמות), `i` (מתעלם מאותיות גדולות וקטנות), `m` (‏`^` ו-`$` מתאימים בכל שורה), `u` (יוניקוד מלא).

## אבני הבניין

| חלק | משמעות |
| --- | --- |
| `abc` | הטקסט המילולי abc |
| `.` | תו אחד כלשהו (חוץ משורה חדשה) |
| `\d` `\w` `\s` | ספרה, תו של מילה (אות, ספרה, קו תחתון), רווח לבן |
| `[abc]` `[a-f0-9]` | תו אחד מהקבוצה או מהטווח |
| `[^abc]` | תו אחד שאינו בקבוצה |
| `*` `+` `?` | 0 או יותר, 1 או יותר, 0 או 1 מהפריט הקודם |
| `{3}` `{2,4}` | בדיוק 3, או בין 2 ל-4 מהפריט הקודם |
| `^` `$` | תחילת הטקסט וסופו |
| `a\|b` | a או b |
| `( )` | קבוצה, שגם לוכדת את הטקסט שהיא מתאימה לו |

כדי להתאים תו שיש לו משמעות מיוחדת, הוסיפו לפניו קו נטוי הפוך: `\.` היא נקודה אמיתית, `\$` סימן דולר אמיתי.

## מציאת דברים

- `text.match(/re/g)` מחזירה מערך של כל ההתאמות (או `null` אם אין).
- `text.matchAll(/re/g)` מחזירה כל התאמה **עם הקבוצות שלה**. היא דורשת את הדגל `g`, ופורשים אותה למערך:

```js
const log = "Order #123, order #456";
const ids = [...log.matchAll(/#(\d+)/g)].map((m) => m[1]);
console.log(ids.join(", ")); // prints: 123, 456
```

כל התאמה `m` היא מערך: `m[0]` הוא הטקסט המלא (`#123`) ו-`m[1]` היא הקבוצה הראשונה (`123`).

## קבוצות עם שם ו-replace

קבוצות עם אינדקס מספרי מבלבלות. תנו להן שם עם `(?<name>...)`, והתייחסו אליהן ב-`replace` כ-`$<name>`:

```js
const date = /(?<year>\d{4})-(?<month>\d{2})-(?<day>\d{2})/;
"2024-03-15".replace(date, "$<day>/$<month>/$<year>"); // "15/03/2024"
```

`replace` עם regex שחסר בו הדגל `g` משנה רק את ההתאמה הראשונה. עם `g` היא משנה את כולן. אפשר גם להעביר פונקציה שמחשבת כל החלפה.

## אימות: עיגון התבנית

`/\d{3}/.test("a1234b")` היא true כי הטקסט *מכיל* שלוש ספרות. כדי לדרוש שהמחרוזת **כולה** נראית בצורה מסוימת, עגנו אותה:

```js
const hex = /^#([0-9a-f]{3}|[0-9a-f]{6})$/i;
```

קראו את זה בקול: תחילה, `#`, ואז או שלוש או שש ספרות הקסדצימליות, ואז סוף, בלי הבדל בין אותיות גדולות וקטנות. הקבוצה עם `|` מציעה את שתי האפשרויות.

## חמדני מול עצלן

כמתים (quantifiers) הם **חמדנים** (greedy): הם לוקחים כמה שהם יכולים. על `"<b>x</b>"`, התבנית `/<.+>/` מתאימה לכל המחרוזת, לא רק ל-`<b>`. הוספת `?` הופכת אותה לעצלנית: `/<.+?>/` נעצרת ב-`>` הראשון.

> **שימו לב:**
> - שימוש ב-`matchAll` בלי הדגל `g`: `TypeError: String.prototype.matchAll called with a non-global RegExp argument`.
> - לשכוח ש-`match` עם `g` מחזירה `null` כשאין התאמה, ולכן `.length` על התוצאה קורס. השתמשו ב-`(text.match(re) ?? []).length`.
> - שימוש חוזר ב-regex עם הדגל `g` ובקריאות חוזרות ל-`test()`. ה-regex זוכר את המיקום שלו (`lastIndex`), ולכן קריאות לסירוגין יכולות לתת תשובות שונות. צרו regex חדש או הימנעו מ-`g` עבור `test`.
> - שכחת הוספת קו נטוי הפוך לנקודה: `/a.com/` מתאימה גם ל-`abcom`. כתבו `/a\.com/`.
> - ניסיון לאמת אימיילים אמיתיים או HTML עם regex. שמרו תבניות אימייל פשוטות ואשרו עם הודעה אמיתית, והשתמשו במנתח (parser) מתאים ל-HTML.
> - כתיבת regex שלוקח זמן אקספוננציאלי על קלט לא מוצלח (כמתים מקוננים כמו `(a+)+`). שמרו תבניות פשוטות על טקסט לא מהימן.

## להמשיך הלאה

השתמשו ב-`/\b\w/g` עם `replace` ופונקציה כדי להפוך את האות הראשונה של כל מילה לגדולה. נסו את האתר regex101.com כדי לראות הסבר על כל חלק בתבנית.

> **תורכם:** הדפיסו את מספרי ההזמנות עם `matchAll`, עצבו מחדש את התאריכים עם קבוצות בעלות שם ו-`replace`, רשמו את האימיילים עם `match`, וכתבו את `isHexColor` עם תבנית מעוגנת ו-`test()`.
