מערכים ואובייקטים רגילים יכולים לעשות כמעט הכול, אבל JavaScript מציעה גם אוספים שתוכננו למשימות מסוימות. בחירה באוסף הנכון הופכת את הקוד לקצר ומהיר יותר, וידיעה איך `sort()` באמת עובדת מונעת כמה באגים מפורסמים.

## Set: אוסף בלי כפילויות

`Set` שומר כל ערך פעם אחת, לפי סדר ההוספה:

```js
const tags = new Set(["js", "css", "js"]);
tags.add("html");
console.log(tags.has("css")); // prints: true
console.log(tags.size);       // prints: 3
```

השימוש הקלאסי הוא הסרת כפילויות: `[...new Set(array)]`. Spread הופך את ה-Set בחזרה למערך. `has` מהירה גם עבור קבוצות ענקיות, הרבה יותר מ-`array.includes` על מערך ארוך. השתמשו ב-`delete(value)` כדי להסיר פריט אחד.

## Map: מילון עם מפתחות מכל סוג

`Map` שומרת זוגות של מפתח/ערך. בניגוד לאובייקט רגיל, כל ערך יכול להיות מפתח (מספרים, אובייקטים), היא זוכרת את סדר ההוספה, ויש לה `size`:

```js
const counts = new Map();
counts.set("a", 1);
counts.set("a", (counts.get("a") ?? 0) + 1);
console.log(counts.get("a")); // prints: 2
```

`get` מחזירה `undefined` עבור מפתח חסר, ולכן `?? 0` נותן ערך התחלתי למונים. עוברים בלולאה עם `for (const [key, value] of map)`, או פורשים למערך של זוגות `[key, value]`: `[...map]`. זמינות גם: `map.keys()`, `map.values()`, `map.has(key)`, `map.delete(key)`.

אובייקטים רגילים מתאימים לרשומות קבועות כמו `{ name: "Ada" }`. עבור מילון עם מפתחות משתנים שמגיעים מהמשתמש, `Map` מונעת הפתעות (כמו המפתח `"constructor"` או `"__proto__"`).

## WeakMap ו-WeakSet

`WeakMap` היא Map שהמפתחות שלה חייבים להיות **אובייקטים**, והיא לא מונעת מהאובייקטים האלה להיאסף על ידי garbage collection. כשאף דבר אחר לא מפנה לאובייקט המפתח, הרשומה שלו נעלמת בשקט. זה הופך אותה למושלמת לתליית נתונים נוספים על אובייקטים שאינם שלכם, כמו מטמונים (caches) או מונים, בלי לגרום לדליפות זיכרון. המחיר: אי אפשר לעבור על WeakMap בלולאה או לבקש את הגודל שלה.

```js
const visits = new WeakMap();
const page = {};
visits.set(page, 1);
```

## מיון עם פונקציית השוואה

`array.sort()` משנה את המערך **במקום** וכברירת מחדל ממיינת ערכים כ**טקסט**. בגלל זה מספרים יוצאים שגויים:

```js
[10, 9, 1, 100].sort();               // [1, 10, 100, 9]
[10, 9, 1, 100].sort((a, b) => a - b); // [1, 9, 10, 100]
```

**פונקציית השוואה** (comparator) היא פונקציה `(a, b) => number`. קוראים לה עם שני פריטים והיא חייבת להחזיר:

- מספר שלילי אם `a` צריך לבוא ראשון,
- מספר חיובי אם `b` צריך לבוא ראשון,
- אפס אם הם שווים.

עבור מספרים, `a - b` ממיין בסדר עולה ו-`b - a` בסדר יורד. עבור מחרוזות, השתמשו ב-`a.localeCompare(b)`, שמטפלת בצורה הגיונית גם בסימני הטעמה ובאותיות גדולות.

כדי למיין לפי כמה כללים, שרשרו אותם עם `||`. הכלל השני משמש רק כשהראשון מחזיר 0, שהוא falsy:

```js
people.sort((a, b) => b.age - a.age || a.name.localeCompare(b.name));
```

מכיוון ש-`sort` משנה את המקור, העתיקו קודם כשצריך לשמור עליו: `[...students].sort(...)`. ל-JavaScript מודרנית יש גם `toSorted(...)`, שמחזירה עותק ממוין. המיון הוא **יציב**: פריטים שנחשבים שווים שומרים על הסדר המקורי שלהם.

> **שימו לב:**
> - מיון מספרים בלי פונקציית השוואה, וקבלת `[1, 10, 100, 9]`.
> - כתיבת פונקציית השוואה שמחזירה ערך בוליאני, כמו `(a, b) => a > b`. ‏`true` ו-`false` הופכים ל-1 ול-0, והתוצאה בלתי צפויה. החזירו מספר.
> - מיון של משהו שרציתם לשמור. `const sorted = list.sort()` משנה גם את `list`, כי שני השמות מצביעים על אותו מערך.
> - שימוש באובייקט כמפתח של Map ואז יצירת אובייקט חדש "שנראה אותו דבר" כדי לחפש אותו: `map.get({id: 1})` לא מוצאת כלום, כי אובייקטים מושווים לפי זהות, לא לפי תוכן.
> - `TypeError: Invalid value used as weak map key` כשמשתמשים במחרוזת או במספר כמפתח של WeakMap. מותרים רק אובייקטים.
> - ציפייה ש-`JSON.stringify(new Map(...))` תעבוד. היא נותנת `{}`. המירו קודם עם `[...map]` או `Object.fromEntries(map)`.

## להמשיך הלאה

ספרו את האותיות של משפט בעזרת Map, ואז הדפיסו את שלוש המובילות. נסו `Object.fromEntries(counts)` כדי להפוך Map לאובייקט רגיל, ו-`new Map(Object.entries(obj))` לכיוון ההפוך.

> **תורכם:** הדפיסו את המילים הייחודיות בעזרת `Set`, ספרו ודרגו את המילים עם `Map` ופונקציית השוואה בעלת שני כללים, מיינו עותק של `students` לפי ציון ואז שם, וצרו את ה-WeakMap בשם `visits` עם הפונקציה `visit`.
