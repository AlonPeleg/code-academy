פונקציה **רקורסיבית** היא פונקציה שקוראת לעצמה. זה נשמע כמו תעלול, אבל זו הדרך הטבעית לטפל בכל דבר שיש לו צורה מקוננת או חוזרת: תיקיות בתוך תיקיות, תגובות עם תשובות, עץ של תפריטים, רשימה בתוך רשימה. בשיעור הזה תלמדו איך לכתוב רקורסיה בבטחה, ואז איך **memoization** הופכת פונקציה רקורסיבית איטית עד כדי חוסר שימוש לפונקציה מהירה.

## שני החלקים של רקורסיה

לכל פונקציה רקורסיבית נכונה יש:

1. **מקרה בסיס** (base case): קלט פשוט מספיק כדי לענות עליו ישירות. כאן הקריאות נעצרות.
2. **מקרה רקורסיבי**: הפונקציה קוראת לעצמה עם גרסה *קטנה יותר* של הבעיה ומשלבת את התוצאה.

```js
function factorial(n) {
  if (n <= 1) return 1;          // base case
  return n * factorial(n - 1);   // recursive case
}
console.log(factorial(5)); // prints: 120
```

הקריאה `factorial(3)` ממתינה ל-`factorial(2)`, שממתינה ל-`factorial(1)`, שמחזירה `1` מיד. אחר כך התשובות זורמות בחזרה: `2 * 1`, ואז `3 * 2`. כל קריאה ממתינה נשמרת ב**מחסנית הקריאות** (call stack), ערימת העבודה הלא גמורה של JavaScript.

אם שוכחים את מקרה הבסיס, או שהקלט אף פעם לא קטן, המחסנית מתמלאת ו-JavaScript עוצרת אתכם: `RangeError: Maximum call stack size exceeded`. הגבולות האופייניים הם בערך עשרת אלפים קריאות, ולכן אל תשתמשו ברקורסיה כדי לחזור על משהו מיליון פעמים (בשביל זה משתמשים בלולאה).

## רקורסיה על נתונים מקוננים

רקורסיה זורחת כשהנתונים מקוננים לעומק לא ידוע. כדי לשטח את `[1, [2, [3]]]` אי אפשר לדעת כמה רמות לפרק, אבל פונקציה יכולה לטפל ברמה אחת ולסמוך על עצמה לגבי השאר:

```js
function flatten(list) {
  const out = [];
  for (const item of list) {
    if (Array.isArray(item)) out.push(...flatten(item)); // go deeper
    else out.push(item);                                 // a plain value
  }
  return out;
}
```

`Array.isArray(item)` מבדילה בין רשימות מקוננות לערכים רגילים, ו-`...` (spread) שופכת את התוצאה המשוטחת הפנימית לתוך `out`. (המתודה המובנית `list.flat(Infinity)` עושה את זה גם.)

## כשרקורסיה חוזרת על עצמה: פיבונאצ'י

מספרי פיבונאצ'י מוגדרים באופן רקורסיבי: כל אחד הוא סכום שני הקודמים לו.

```js
function fibNaive(n) {
  return n < 2 ? n : fibNaive(n - 1) + fibNaive(n - 2);
}
```

היא נכונה אבל איטית להחריד. `fibNaive(5)` קוראת ל-`fibNaive(3)` פעמיים ול-`fibNaive(2)` שלוש פעמים, והבזבוז מתנפח ככדור שלג: `fibNaive(20)` מבצעת 21,891 קריאות ו-`fibNaive(40)` יותר מ-300 מיליון.

## Memoization

**Memoization** פירושה לזכור את התשובה לכל קלט, כך שכל בעיה שונה נפתרת רק פעם אחת. אפשר לכתוב את זה פעם אחת, כ**פונקציה מסדר גבוה** (higher-order function) שעוטפת כל פונקציה:

```js
function memoize(fn) {
  const cache = new Map();
  return (n) => {
    if (cache.has(n)) return cache.get(n);  // seen before: reuse
    const result = fn(n);                   // new: compute
    cache.set(n, result);                   // and remember
    return result;
  };
}
```

פונקציית החץ שמוחזרת **סוגרת על** (closes over) `cache` (זכרו closures משיעורים קודמים), ולכן המטמון שורד בין קריאות. עטפו את הלוגיקה של פיבונאצ'י וודאו שהקריאות הרקורסיביות עוברות דרך הגרסה העטופה:

```js
const fib = memoize((n) => (n < 2 ? n : fib(n - 1) + fib(n - 2)));
```

עכשיו `fib(20)` צריכה רק 21 קריאות ו-`fib(50)` מיידית: `12586269025`. הרעיון הזה, לפתור כל תת-בעיה פעם אחת ולשמור אותה, הוא לב של טכניקה חשובה שנקראת **תכנות דינמי** (dynamic programming).

Memoization עובדת רק עבור פונקציות **טהורות** (pure), כאלה שהתוצאה שלהן תלויה רק בקלט שלהן. שמירה במטמון של פונקציה שקוראת את השעון או מספרים אקראיים הייתה מחזירה תשובות מיושנות. וזכרו גם שמטמון גדל לנצח אלא אם מגבילים אותו.

> **שימו לב:**
> - אין מקרה בסיס, או מקרה בסיס שלעולם לא מגיעים אליו: `RangeError: Maximum call stack size exceeded`.
> - קריאה רקורסיבית עם אותו קלט, כמו `factorial(n)` במקום `factorial(n - 1)`. הבעיה חייבת להצטמצם.
> - עשיית memoization אבל קריאה רקורסיבית ל-*פונקציה המקורית*. בתרגיל הקריאות הפנימיות חייבות להשתמש ב-`fib`, הגרסה העטופה; אחרת שום דבר לא נשמר במטמון.
> - שימוש ב-`n * factorial(n - 1)` עם מספר שלילי. עם `if (n === 0)` כמקרה בסיס היא אף פעם לא הייתה נעצרת. `n <= 1` בטוח יותר.
> - שימוש ב-Map עם מפתח שהוא ארגומנט מסוג מערך או אובייקט: `cache.get([1, 2])` אף פעם לא מוצאת רשומה קודמת, כי כל מערך הוא אובייקט שונה. הפכו את הארגומנטים למפתח מחרוזת, למשל `JSON.stringify(args)`.
> - שימוש ברקורסיה למשימת ספירה פשוטה. לולאת `for` פשוטה יותר ואינה יכולה לגרום לגלישת מחסנית.

## להמשיך הלאה

גרמו ל-`memoize` לקבל פונקציות עם כל מספר של ארגומנטים בעזרת `(...args)` ו-`JSON.stringify(args)` כמפתח. אחר כך כתבו `sumDigits(n)` רקורסיבית ו-`countDown(n)` רקורסיבית שמדפיסה מ-`n` עד 1.

> **תורכם:** כתבו את `factorial` (עם מקרה בסיס), את `memoize` (עם מטמון של Map), ואת `flatten` רקורסיבית, כך ששש השורות יודפסו כמו שמוצג.
