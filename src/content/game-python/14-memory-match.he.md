עד עכשיו בדקנו את המשחקים שלנו בכך שצפינו בהם זזים. Memory match הוא המשחק הראשון שבו אכפת לנו ממשהו אחר: **תכנון**. משחק קלפים הוא בעיקר כללים (מה קורה כשהופכים קלף?), וכללים נכתבים הכי טוב כ**פונקציות** קטנות שלא יודעות כלום על העכבר או על המסך. זה הופך אותן לקלות להבנה, לקלות לשינוי ולקלות לבדיקה. כך מתכנתים מקצועיים בונים קוד, וזו מיומנות ששווה לתרגל.

## שלוש שכבות

מחלקים את התוכנית לשלוש שכבות:

1. **לוגיקה**: הפונקציות `flip(i)` ו-`check_pair()` והרשימות `matched` ו-`picked`. הן רק משנות נתונים.
2. **קלט**: `update` קוראת את העכבר והופכת לחיצה למספר קלף עם `card_at(x, y)`, ואז קוראת ל-`flip`.
3. **ציור**: `draw` מציירת את הנתונים. היא אף פעם לא משנה כלום.

הכלל "שכבות מדברות רק כלפי מטה" אומר שאפשר להחליף אחת בלי לגעת באחרות. רוצים שליטה במגע או במקלדת? משנים רק את הקלט. רוצים אמנות מפוארת לקלפים? משנים רק את הציור. רוצים לדעת אם הכללים עובדים? קוראים ללוגיקה ישירות, בלי עכבר. זה בדיוק מה ש**בדיקת תשובה** (Check answer) עושה בשיעור הזה.

## הנתונים

```python
cards = [3, 0, 5, 1, ...]        # cards[i] is the picture on card i (two cards share each picture)
matched = [False] * 16           # matched[i]: has card i found its partner?
picked = []                      # the cards that are face up right now (0, 1 or 2 indexes)
```

קלף מוצג עם הפנים כלפי מעלה אם `matched[i]` או `i in picked`; זה כלל ש-`draw` משתמשת בו. הקלפים ממוספרים מ-0 עד 15 מהפינה השמאלית העליונה, שורה אחר שורה. הקוד ההתחלתי משתמש בסידור קבוע כדי שהתוצאה תהיה צפויה. כדי לערבב באמת, כתבו `import random` ו-`random.shuffle(cards)` פעם אחת בהתחלה.

## flip: לחיצה אחת, כלל אחד

`flip(i)` נקראת כשהשחקן לוחץ על קלף `i`. היא חייבת **לסרב** ללחיצות חסרות היגיון, ולומר זאת בהחזרת `False`: קלף שכבר התאים, קלף שכבר הפוך, או קלף שלישי בזמן שזוג עדיין מוצג. אחרת היא מוסיפה את `i` ל-`picked` ומחזירה `True`. החזרת תוצאה היא מה שהופך פונקציה לניתנת לבדיקה: מי שקורא לה יכול להסתכל עליה.

## check_pair: שיפוט הזוג

כששני קלפים פתוחים, `check_pair()` משווה את התמונות שלהם. סופרים את הניסיון ב-`moves`, ואם התמונות שוות, מסמנים את שני הקלפים ב-`matched`. בין אם התאים ובין אם לא, מסיימים עם `picked.clear()` כדי שהתור הבא יתחיל נקי. היא מחזירה `True` או `False`, או `None` אם יש פחות משני קלפים לשפוט. שימו לב לשורה `global moves`: אנחנו משימים ל-`moves`, ולכן Python צריכה לדעת שזה המשתנה הגלובלי (`picked.clear()` ו-`matched[a] = True` רק משנות רשימה קיימת, ולכן הן לא צריכות `global`).

## ההשהיה והניצחון

אחרי ההפיכה השנייה השחקן צריך לראות את שני הקלפים לרגע. ב-`update`, ברגע ש-`len(picked) == 2`, טיימר סופר למעלה `dt` ואחרי 0.7 שניות קורא ל-`check_pair()`. (לחיצות מתעלמים מהן בזמן הזה, כי `flip` מסרבת לקלף שלישי.) לבסוף `all(matched)` היא `True` רק כשלכל קלף יש זוג: השחקן ניצח.

## קלט עכבר

`card_at` כתובה בשבילכם. `divmod(a, b)` נותנת את מספר הפעמים השלם ש-`b` נכנס ב-`a` *וגם* את השארית בבת אחת, כך שאנחנו לומדים את העמודה וגם אם העכבר בתוך הקלף או ברווח בין הקלפים. `card_at(*game.mouse_pos())` משתמשת ב-`*` כדי לפרוס את הזוג `(x, y)` לשני ארגומנטים.

> **שימו לב:** `UnboundLocalError: cannot access local variable 'moves' where it is not associated with a value`: אתם משימים `moves = moves + 1` ב-`check_pair`, ולכן הוסיפו `global moves` (זה כבר קיים בקוד ההתחלתי).
>
> **שימו לב:** `ValueError: too many values to unpack (expected 2)` ב-`a, b = picked` אומרת ש-`picked` הכילה יותר משני פריטים. `flip` חייבת לסרב לקלף השלישי.
>
> **שימו לב:** אם שוכחים `picked.clear()` שני קלפים נשארים "נבחרים" לנצח והמשחק קופא; אם שוכחים `return` ב-`flip` היא מחזירה `None`, וזה נחשב "סירוב".
>
> **שימו לב:** `matched = [False] * 16` בסדר גמור, אבל `matched = [[False]] * 16` משתפת רשימה פנימית אחת בין כל הפריטים.
