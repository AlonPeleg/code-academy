Breakout מוסיף לארגז הכלים שלכם מבנה נתונים שימושי מאוד: **רשת** (grid), שנכתבת ב-Python כ**רשימה של רשימות**. הוא גם מוסיף פיזיקה חכמה יותר לכדור: זווית ההחזרה תלויה במקום שבו הכדור פוגע במחבט. בסוף תהיה לכם משחק עם לבנים, שלושה חיים ותנאי ניצחון.

## רשימה של רשימות

הלבנים נשמרות שורה אחר שורה: כל שורה היא רשימה של 8 מספרים, והרשת כולה היא רשימה של 4 שורות.

```python
bricks = [[1] * COLS for r in range(ROWS)]
print(bricks[0])        # prints: [1, 1, 1, 1, 1, 1, 1, 1]
bricks[2][5] = 0        # row 2, column 5 is broken
print(bricks[2][5])     # prints: 0
```

`bricks[row][col]` בוחרת קודם את השורה, ואחר כך את הפריט בשורה הזאת. `1` פירושו "הלבנה שם", ו-`0` פירושו "היא נעלמה". כדי לצייר את הרשת, `draw` משתמשת בשתי לולאות, אחת בתוך השנייה: הלולאה החיצונית עוברת על כל `r`, הפנימית על כל `c`, ולבנה ב-`(r, c)` מצוירת בפיקסל `x = c * BW`, `y = TOP + r * BH`.

## מפיקסל ללבנה

התנגשות עם 32 לבנים עלולה להיות 32 השוואות בכל פריים. רשת מאפשרת לדלג על כל זה: שואלים "באיזה תא נמצא הכדור?" בחילוק אחד. חילוק עם עיגול כלפי מטה `//` מחלק וזורק את השבר:

```python
col = int(bx // BW)             # 95 // 40 is 2
row = int((by - TOP) // BH)     # subtract TOP first: the grid starts 30 pixels down
```

עכשיו `bricks[row][col]` היא בדיוק הלבנה שמתחת לכדור, שנמצאה בצעד אחד. הטריק הזה של "להמיר מיקום לאינדקס ברשת" הוא הדרך שבה כמעט כל משחק רשת עובד. לפני שקוראים מהרשימה צריך לבדוק שהמספרים בתוך הרשת (`0 <= row < ROWS`), כי הכדור נמצא רוב הזמן מחוץ לאזור הלבנים.

## החזרה

כשהכדור שובר לבנה הופכים את המהירות האנכית שלו, `vy = -vy`, כך שהוא קופץ חזרה בדרך שממנה בא. הכדור גם קופץ מהקירות השמאלי, הימני והעליון (כבר כתוב בשבילכם, עם `abs` כדי שלא ייתקע).

ה**מחבט** הוא המקום שבו זה נהיה מהנה. אילו הכדור היה תמיד יוצא באותה זווית המשחק היה משעמם ולשחקן לא הייתה שליטה. במקום זה משתמשים במרחק ממרכז המחבט שבו הכדור נחת:

```python
vx = (bx - (px + PW / 2)) * 5
```

פוגעים בקצה השמאלי ו-`vx` הופך לכ-(-125) (בחדות שמאלה), פוגעים באמצע והוא 0 (ישר למעלה). השחקן מכוון על ידי מיקום המחבט. אנחנו גם כותבים `vy = -abs(vy)`, "לך למעלה לא משנה מה", ועושים את זה רק כש-`vy > 0`, כדי שהכדור לא יקפוץ פעמיים מאותו מחבט. המונה `bounces` פשוט סופר את התפיסות.

## חיים ומצבים

כשהכדור נופל מתחת לתחתית (`by > game.HEIGHT`) מאבדים חיים והכדור חוזר למחבט עם `reset_ball()`. כשהחיים מגיעים ל-0 המצב הופך ל-`"game over"`, וכשהניקוד שווה למספר הלבנים (`ROWS * COLS`) הוא הופך ל-`"won"`. בראש `update`, `if state != "playing": return` מקפיאה את המשחק בשני מצבי הסיום. זה אותו רעיון של מכונת מצבים כמו בשיעור Dodge.

> **שימו לב:** `IndexError: list index out of range` קורית כשמשתמשים ב-`bricks[row][col]` עם שורה או עמודה מחוץ לרשת, למשל כשהכדור בתחתית המסך. בדקו קודם את הטווחים.
>
> **שימו לב:** אינדקס שלילי לא גורם לקריסה, הוא מתהפך בשקט! `bricks[-1]` היא השורה **האחרונה**, ולכן כדור מעל הרשת (`row = -1`) היה שובר לבנים בתחתית. בגלל זה אנחנו בודקים `0 <= row`.
>
> **שימו לב:** `bricks = [[1] * 8] * 4` יוצרת ארבע הפניות לאותה שורה, ולכן שבירת לבנה אחת שוברת את העמודה הזאת בכל שורה. השתמשו ב-`[[1] * 8 for r in range(4)]` כדי ליצור ארבע רשימות נפרדות.
>
> **שימו לב:** הכדור עף ישר דרך לבנים במהירות גבוהה? הוא נע כמה פיקסלים בפריים, ולכן המרכז יכול לדלג מעל שורה דקה. שמרו את המהירות מתחת לגובה הלבנה בפריים (כאן 2.7 פיקסלים מול 14).
