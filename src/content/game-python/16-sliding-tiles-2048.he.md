2048 נראה כמו משחק גרפי, אבל הוא באמת **חידה בנתונים**. אם מצליחים בלוגיקה של הרשת, השאר הוא ציור של ריבועים צבעוניים. השיעור הזה עוסק ב**צמצום בעיה**: כותבים את כלל ההזזה והמיזוג לשורה אחת שנעה שמאלה, ואז מקבלים את שלושת הכיוונים האחרים כמעט בחינם בעזרת *המרה* של הרשת. זו דרך חשיבה שתשתמשו בה כל חיי התכנות שלכם: פותרים מקרה אחד היטב, ואז הופכים את המקרים האחרים אליו.

## הכללים

אריחים מחליקים עד כמה שאפשר בכיוון שנבחר. שני אריחים שווים שמתנגשים ממוזגים לאריח אחד בערך כפול, והשחקן מרוויח את הערך הזה כנקודות. שני פרטים חשובים:

* אריח ממוזג **לכל היותר פעם אחת** בכל מהלך, ולכן שורה `[2, 2, 2, 2]` הופכת ל-`[4, 4, 0, 0]` (ולא ל-`[8, 0, 0, 0]`),
* המיזוג קורה **לכיוון התנועה**: `[2, 2, 2]` שנעה שמאלה נותנת `[4, 2, 0, 0]`.

שומרים את הרשת כרשימה של ארבע שורות, כל אחת רשימה של ארבעה מספרים, כאשר 0 פירושו תא ריק.

## שלב 1: שורה אחת, שמאלה

לפונקציה `slide_left(row)` יש שלושה שלבים:

1. **דחיסה**: שומרים רק את האריחים שאינם אפס: `tiles = [v for v in row if v != 0]`.
2. **מיזוג**: עוברים על `tiles` עם אינדקס `i`. אם האריח שווה לבא אחריו, מוציאים אריח כפול אחד, מוסיפים את ערכו ל-`points`, וקופצים קדימה ב-2 כדי ששני האריחים לא ישמשו שוב. אחרת מעתיקים את האריח וקדימה ב-1. לולאת `while` מתאימה כאן יותר מ-`for`, כי גודל הצעד משתנה.
3. **ריפוד**: מוסיפים אפסים עד שיש בשורה 4 פריטים: `out + [0] * (4 - len(out))`.

היא מחזירה **שני ערכים** כ-tuple, `(new_row, points)`. Python מאפשרת לפונקציה להחזיר כמה דברים; הקורא מקבל אותם עם `new, points = slide_left(row)`.

הפונקציה אף פעם לא משנה את שורת הקלט שלה; היא בונה חדשה. פונקציות שלא משנות את הקלט שלהן קלות הרבה יותר לבדיקה ולאמון.

## שלב 2: שלושת הכיוונים האחרים

במקום ארבעה אלגוריתמים נפרדים **ממירים** את הרשת כך שכל מהלך הופך למהלך שמאלה:

| כיוון | הטריק |
|---|---|
| שמאלה | מחליקים כל שורה כמות שהיא |
| ימינה | הופכים כל שורה (`row[::-1]`), מחליקים שמאלה, והופכים את התוצאה בחזרה |
| למעלה | עושים `transpose` לרשת (עמודות הופכות לשורות), מחליקים שמאלה, ועושים transpose בחזרה |
| למטה | transpose, אחר כך הטריק של "ימינה", ואז transpose בחזרה |

`transpose` כתובה בשבילכם: `zip(*g)` מזווגת את הפריטים הראשונים של כל השורות, אחר כך את השניים, וכן הלאה, וזה הופך עמודות לשורות. הפרוסה `row[::-1]` היא הרשימה כולה נקראת מהסוף להתחלה. `move(g, direction)` מחזירה `(new_grid, total_points)` ושוב משאירה את `g` ללא שינוי.

## שלב 3: המשחק סביבה

ב-`update`, לכל כיוון `d` ב-`DIRS`, אם `game.key_pressed(d)` קוראים ל-`move`. המפתח הוא שרק כשהרשת החדשה **שונה** (`new != grid`; Python משווה רשימות פריט אחר פריט) המהלך נחשב. אז הרשת מוחלפת, הנקודות מתווספות ו-`spawn()` מוריד אריח חדש, כך שלחיצה חסרת תועלת אף פעם לא נותנת אריח בחינם. המשחק נגמר כש-`stuck(grid)`: אף כיוון לא משנה את הרשת. הפונקציה הזאת היא שורה אחת, `all(move(g, d)[0] == g for d in DIRS)`, כי *לנסות* מהלך היא דרך זולה לשאול אם הוא אפשרי. (המשחק האמיתי מוריד 2 או 4 בתא ריק אקראי; אנחנו משתמשים בתא הריק הראשון כדי שהבדיקה תוכל לחזות את זה.)

> **שימו לב:** `TypeError: cannot unpack non-iterable NoneType object` ב-`new, points = move(...)` אומרת ש-`move` שכחה את משפט ה-`return` שלה.
>
> **שימו לב:** אם נראה שהרשת משתנה מעצמה, שיניתם את רשימת הקלט. `[list(r) for r in g]` יוצרת העתק אמיתי של כל שורה, ואילו `new_grid = g` רק נותנת לאותה רשת שם שני.
>
> **שימו לב:** `[2, 2, 2, 2]` שהופכת ל-`[8, 0, 0, 0]` אומרת שהאריח הממוזג מוזג שוב. דלגו על שני האריחים (`i = i + 2`) אחרי מיזוג.
>
> **שימו לב:** רשת שנוצרה כ-`[[0] * 4] * 4` מכילה ארבע שורות שהן בדיוק אותה רשימה. השתמשו בהבנת רשימה, או העתיקו שורות עם `list(r)`.
