רשימה מחזיקה את כל הערכים שלה בבת אחת. לפעמים זה בזבזני (מיליון מספרים) או בלתי אפשרי (זרם נתונים אינסופי). **גנרטור** (generator) מפיק את הערכים שלו **באופן עצל** (lazily): אחד אחד, רק כשמבקשים. תלמדו מהם איטרטורים, איך `yield` יוצר אותם, ולמה זה חשוב לנתונים גדולים או אינסופיים.

## איטרטורים ואובייקטים שאפשר לעבור עליהם

כשכותבים `for x in something`, Python עושה שני דברים מאחורי הקלעים:

1. היא מבקשת מ-`something` **איטרטור** (iterator) עם `iter(something)`.
2. היא קוראת ל-`next(iterator)` שוב ושוב עד שהאות `StopIteration` אומר שלא נשאר דבר.

```python
it = iter([10, 20, 30])
print(next(it))   # prints: 10
print(next(it))   # prints: 20
print(next(it))   # prints: 30
# next(it) now raises StopIteration
```

רשימה היא **iterable** (אובייקט שאפשר לעבור עליו, כלומר כזה שיכול לתת איטרטור). האיטרטור הוא הדבר שזוכר איפה אתם נמצאים.

## כתיבת גנרטור עם yield

כתיבת איטרטור ביד היא מייגעת. **פונקציית גנרטור** היא הקיצור: משתמשים ב-`yield` במקום ב-`return`.

```python
def countdown(n):
    while n > 0:
        yield n
        n -= 1

for i in countdown(3):
    print(i)      # prints: 3, then 2, then 1
```

איך זה עובד, צעד אחר צעד:

- קריאה ל-`countdown(3)` **לא** מריצה את הגוף. היא מחזירה אובייקט גנרטור.
- כל `next()` מריץ את הגוף עד שהוא מגיע ל-`yield`, מוסר את הערך ו**משהה** את הפונקציה, תוך שמירה על כל המשתנים המקומיים.
- ה-`next()` הבא ממשיך מיד אחרי ה-`yield`.
- כשהפונקציה מסתיימת, נזרק `StopIteration` ולולאת `for` נעצרת בשקט.

## מעבר אחד בלבד

גנרטור נגמר אחרי שעברתם עליו פעם אחת:

```python
g = countdown(3)
print(list(g))   # prints: [3, 2, 1]
print(list(g))   # prints: []   (already exhausted)
```

אם צריך את הערכים שוב, קראו שוב לפונקציית הגנרטור כדי לקבל גנרטור חדש.

## ביטויי גנרטור

list comprehension בסוגריים מרובעים בונה את הרשימה כולה. עם סוגריים עגולים מקבלים במקום זה גנרטור עצל:

```python
squares_list = [n * n for n in range(1000000)]   # a million numbers stored
squares_gen = (n * n for n in range(1000000))    # nothing computed yet
print(sum(n * n for n in range(10)))             # prints: 285
```

כשביטוי גנרטור הוא הארגומנט היחיד של פונקציה, אפשר לוותר על הסוגריים הנוספים, כמו ב-`sum(...)` שלמעלה.

## גנרטורים אינסופיים

מכיוון שהערכים נוצרים לפי דרישה, גנרטור יכול להיות אינסופי כל עוד מפסיקים לבקש:

```python
def naturals():
    n = 1
    while True:
        yield n
        n += 1
```

לעולם אל תקראו ל-`list(naturals())`, זה לא יסתיים אף פעם. קחו רק את מה שצריך, למשל עם `itertools.islice(naturals(), 5)`.

> **שימו לב:**
> - הדפסת גנרטור מציגה `<generator object fib at 0x...>` ולא את הערכים. עברו עליו בלולאה או עטפו אותו ב-`list(...)`.
> - שימוש בו פעמיים: המעבר השני ריק, בלי שגיאה. זה מקור נפוץ מאוד לבאגים מבלבלים.
> - קריאה ל-`next(g)` אחרי הסוף נותנת `StopIteration`. השתמשו ב-`next(g, None)` כדי לקבל ערך ברירת מחדל במקום.
> - לשכוח ש-`return value` בתוך גנרטור מסיים אותו (הערך לא מוסר).
> - `len(g)` לא עובד: `TypeError: object of type 'generator' has no len()`.

## להמשיך הלאה

כתבו גנרטור `read_chunks(items, size)` שמוסר רשימות של `size` פריטים בכל פעם, או שרשרו גנרטורים, כשכל אחד מסנן את הפלט של הקודם, כדי לבנות צינור עצל (pipeline).

> **תורכם:** כתבו את הגנרטור `fib(limit)`, ואז הדפיסו את שלושת הערכים הראשונים שלו עם `next`, את שאר הערכים עם `list(g)` ואת סכום הריבועים של 0..9 עם ביטוי גנרטור, כפי שמתואר בהערות.
