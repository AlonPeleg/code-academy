איך אתם יודעים שהקוד שלכם עובד? אפשר להריץ אותו, להסתכל על הפלט ולהחליט "נראה נכון". זה עובד בשביל פונקציה אחת פעם אחת, אבל לא בשביל פרויקט עם 200 פונקציות שמשנים כל יום. **בדיקות אוטומטיות** (automatic tests) הן תוכניות קטנות שקוראות לקוד שלכם עם קלטים ידועים ובודקות את התוצאות. מריצים אותן בשנייה ומיד לומדים מה נשבר. בשיעור הזה תכירו את הדרך הסטנדרטית לכתוב אותן ב-JavaScript.

## שלוש המילים שצריך

הבדיקות בקורס הזה משתמשות באותן מילים כמו **Jest**, כלי הבדיקות הפופולרי ביותר ב-JavaScript:

* `describe("name", () => { ... })` מקבצת בדיקות קשורות (**סוויטה**, suite).
* `it("does something", () => { ... })` היא **בדיקה** אחת: שם באנגלית פשוטה ופונקציה. (`test` זהה ל-`it`.)
* `expect(actual).toBe(expected)` היא **טענה** (assertion): היא משווה את מה שהקוד באמת החזיר (`actual`) עם מה שאתם רוצים (`expected`). אם הם שונים, הבדיקה נכשלת.

דוגמה מלאה:

```js
function double(n) {
  return n * 2;
}

describe("double", () => {
  it("doubles a positive number", () => {
    expect(double(4)).toBe(8);
  });
  it("doubles zero", () => {
    expect(double(0)).toBe(0);
  });
});
```

בדיקה **עוברת** כשהפונקציה שלה מסתיימת בלי שטענה נכשלת, ו**נכשלת** כש-`expect` לא מתאים (או כשהקוד זורק שגיאה).

## קריאת הדוח

כשלוחצים על **הרצה** (Run), אזור התרגול מדפיס דוח באותו סגנון של כלי בדיקות אמיתיים:

```text
double
  ✓ doubles a positive number
  ✗ doubles zero
      toBe (Object.is equality)
        Expected: 0
        Received: 1

Tests: 1 failed, 1 passed, 2 total
```

סימן וי אומר שהבדיקה עברה וסימן איקס אומר שנכשלה. מתחת לבדיקה שנכשלה רואים **Expected** (מה שהבדיקה רצתה) ו-**Received** (מה שהקוד שלכם באמת הפיק). השורה האחרונה היא הסיכום. המטרה שלכם במסלול הזה כמעט תמיד זהה: לגרום לה להציג `N passed, N total`.

## Matchers: יותר מ-toBe

החלק שאחרי `expect(...)` נקרא **matcher**. כמה מהם תשתמשו בכל הזמן:

| Matcher | עובר כש... |
| --- | --- |
| `toBe(5)` | הערך הוא בדיוק `5` (כמו `===`, עבור מספרים, מחרוזות וערכים בוליאניים) |
| `toEqual([1, 2])` | לאובייקטים ולמערכים יש אותו תוכן (השוואה עמוקה) |
| `toBeTruthy()` / `toBeFalsy()` | הערך הוא truthy או falsy |
| `toContain("cat")` | מחרוזת או מערך כוללים את הפריט |
| `toBeGreaterThan(3)` | מספר גדול יותר |
| `toThrow()` | פונקציה זורקת שגיאה |
| `.not.toBe(5)` | ההפך: הוא **לא** יכול להיות 5 |

השתמשו ב-`toEqual` עבור מערכים ואובייקטים, כי `toBe` משווה **זהות**: `expect([1]).toBe([1])` נכשלת מפני שאלה שני מערכים שונים.

## איפה הבדיקות נמצאות?

בפרויקטים אמיתיים שומרים את הקוד ב-`math.js` ואת הבדיקות ב-`math.test.js`; קובץ הבדיקות טוען את הקוד עם `require("./math")` (או `import`). באזור התרגול הזה שני הקבצים פתוחים כלשוניות: הלשונית הראשונה (קובץ הבדיקות) רצה, והדוח מופיע בפלט. במחשב שלכם תתקינו את Jest (`npm install --save-dev jest`) ותריצו `npx jest`. שאר השיעור עובד באותה צורה.

> **שימו לב:**
> * **מתקנים את הבדיקה במקום את הקוד.** אם בדיקה נכשלת, שאלו קודם: האם ה*קוד* שגוי או שה*בדיקה* שגויה? בדיקה שמתאימה למה שאתם רוצים היא המפרט (specification); אל תשנו אותה רק כדי שתהיה ירוקה.
> * **משווים מערכים עם `toBe`.** השתמשו ב-`toEqual`. ההודעה נראית כמו `Expected: [1, 2] Received: [1, 2]` ומבלבלת.
> * **שוכחים `module.exports`.** אם `math.js` לא מייצא פונקציה, הבדיקה נכשלת עם `TypeError: add is not a function`.
> * **בדיקות שתמיד עוברות.** בדיקה בלי `expect` עוברת גם אם הקוד שבור. בכל בדיקה צריכה להיות לפחות טענה אחת.

> **תורכם:** הריצו את הבדיקות וקראו את הכשלונות. תקנו את `add` ואת `isEven` ב-`math.js`, השלימו את `clamp`, וכתבו בדיקה חדשה אחת בשם `adds zero` בסוויטה `add` (מיד אחרי הבדיקות הקיימות) שבודקת ש-`add(5, 0)` הוא `5`. הדוח חייב להסתיים ב-`Tests: 8 passed, 8 total`.
