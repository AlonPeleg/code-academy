כשהקוד לא עושה מה שציפיתם, ניחושים הם דרך איטית. **דיבאגינג** (debugging) פירושו לגלות מה *באמת* קורה בתוך התוכנית, ואז לתקן את ההבדל בין מה שציפיתם לו לבין מה שקיבלתם. הכלי הפשוט והאוניברסלי ביותר הוא `console.log`: הוא מאפשר להסתכל על ערך בכל רגע. בשיעור הזה תלמדו להשתמש בו נכון.

## הופכים את הלוגים לקריאים

לוג עם ערך בלבד קשה לקריאה כשיש כמה כאלה:

```js
const total = 12;
console.log(total);              // prints: 12      (which total? where?)
console.log("total:", total);    // prints: total: 12
console.log(`i=${3} total=${total}`);   // prints: i=3 total=12
```

תמיד הוסיפו **תווית**. אם רוצים לראות אובייקט או מערך שלם, הדפיסו אותו ישירות (`console.log("user:", user)`) או, כדי לראות מחרוזות במדויק, השתמשו ב-`JSON.stringify(value)`. זה עוזר לזהות דברים בלתי נראים כמו רווחים מיותרים: `"abc "` ו-`"abc"` נראים אותו דבר בלי מרכאות.

אפשר גם להדפיס את ה**טיפוס** של ערך, שהוא מקור נפוץ מאוד להפתעות:

```js
const input = "5";
console.log(typeof input, input + 1);   // prints: string 51   (text, not a number!)
```

## שגרת דיבאגינג שעובדת

1. **שחזרו** את הבאג עם הקלט הקטן ביותר שמראה אותו (`average([4, 8, 6])`).
2. **אמרו מה אתם מצפים**, בקול או בהערה: "אני מצפה ל-6, אני מקבל NaN".
3. **הסתכלו פנימה** עם לוגים בתחילת הפונקציה, בתוך לולאות וממש לפני `return`.
4. **חצו לשניים**: אם התוכנית ארוכה, הדפיסו ערך *באמצע*. אם הוא כבר שגוי שם, הבאג בחצי הראשון; אם הוא עדיין נכון, הבאג בחצי השני. חזרו על זה עד שמצאתם שורה אחת.
5. **תקנו דבר אחד**, הריצו שוב והשוו למה שציפיתם.
6. **הסירו** את לוגי הדיבאגינג (או הפכו אותם לבדיקות (tests) מסודרות, שתלמדו בקרוב).

דוגמה. למה זה מדפיס `NaN`?

```js
function sum(numbers) {
  let total = 0;
  for (let i = 0; i <= numbers.length; i++) {
    console.log("i:", i, "value:", numbers[i], "total:", total);
    total += numbers[i];
  }
  return total;
}
sum([4, 8, 6]);
// prints: i: 0 value: 4 total: 0
// prints: i: 1 value: 8 total: 4
// prints: i: 2 value: 6 total: 12
// prints: i: 3 value: undefined total: 18
```

השורה האחרונה חושפת את זה: `numbers[3]` הוא `undefined`, כי ברשימה יש רק את האינדקסים 0, 1 ו-2. חיבור של `undefined` למספר נותן `NaN`. הלולאה רצה פעם אחת יותר מדי, והתיקון הוא `i < numbers.length`. מצאנו באג עם ארבע שורות פלט וללא ניחושים.

## כלים שימושיים נוספים

* `console.error("message")` ו-`console.warn("message")` מסמנים הודעה כשגיאה או כאזהרה. אזור התרגול מציג אותן בנפרד מהפלט הרגיל, והבודק משווה רק את הפלט **הרגיל**. לכן הן שימושיות להודעות דיבאגינג שאתם לא רוצים בתוצאה.
* `console.table(arrayOfObjects)` מצייר טבלה בקונסולת ה-DevTools של הדפדפן וב-Node אמיתית. זה מצוין לרשימות של רשומות. קונסולת התרגול כאן מציגה רק טקסט פשוט, ולכן השתמשו בו במחשב שלכם.
* **דיבאגינג עם ברווז גומי (Rubber duck):** הסבירו את הקוד שלכם שורה אחר שורה לברווז גומי (או לחבר, או לקובץ הערות). לעיתים קרובות מאוד אתם מזהים את הטעות בעצמכם תוך כדי ההסבר, כי אתם נאלצים לומר מה כל שורה *באמת* עושה במקום מה ש*התכוונתם*.
* ההוראה `debugger;` עוצרת את התוכנית כשה-DevTools של הדפדפן פתוחים, כך שאפשר לעבור על הקוד שורה אחר שורה.

> **שימו לב:**
> * **מדפיסים את הדבר הלא נכון.** אם לוג מדפיס `[object Object]`, חיברתם אובייקט למחרוזת. השתמשו בפסיק: `console.log("user:", user)`, ולא `"user: " + user`.
> * **שוכחים להסיר לוגים.** לוגי דיבאגינג שנשארו בקוד הופכים את הפלט לשגוי, ובאפליקציה אמיתית הם מדליפים מידע. חפשו `console.log` לפני שאתם מסיימים.
> * **משנים חמישה דברים בבת אחת.** אז אתם לא יודעים איזה שינוי תיקן (או שבר) את התוכנית. שנו דבר אחד בכל הרצה.
> * **סומכים על הזיכרון.** "המשתנה הזה בטוח 5." הדפיסו אותו. הבאג נמצא בדרך כלל בדיוק במקום שהייתם בטוחים שהוא לא יכול להיות בו.

> **תורכם:** בשלוש פונקציות יש באג אחד בכל אחת. השתמשו בקריאות `console.log` מתויגות כדי לראות את הערכים, תקנו את `sum`, את `maxOf` ואת `formatPrice`, ואז הסירו את לוגי הדיבאגינג כך שיודפסו רק שלוש השורות הסופיות: `6`, `-2` ו-`$5.00`.
