כל מתכנת רואה שגיאות כל היום. ההבדל בין מתחיל למומחה הוא בעיקר שהמומחה **קורא את ההודעה**. בשיעור הזה תלמדו לקרוא שגיאה כמו דוח קצר: מה השתבש, איפה, ואיך לתפוס אותה כדי שהתוכנית לא תקרוס.

## האנטומיה של שגיאה

כש-JavaScript לא יכולה להמשיך, היא **זורקת שגיאה** (throws an error). אם שום דבר לא תופס אותה, התוכנית נעצרת ואתם רואים משהו כזה (ב-Chrome או ב-Node):

```text
TypeError: Cannot read properties of undefined (reading '0')
    at initials (main.js:3:28)
    at main.js:6:13
```

בטקסט הקטן הזה יש שלושה חלקים:

| חלק | דוגמה | מה הוא מספר לכם |
| --- | --- | --- |
| **שם** | `TypeError` | סוג הבעיה |
| **הודעה** | `Cannot read properties of undefined (reading '0')` | הפרטים |
| **Stack trace** | `at initials (main.js:3:28)` | איפה זה קרה, הקריאה החדשה ביותר ראשונה |

ה-stack trace הוא רשימה של הפונקציות שרצו ברגע שהשגיאה קרתה. השורה העליונה היא המקום שנכשל. השורות שמתחתיה מראות מי קרא לו, אחר כך מי קרא לזה, וכן הלאה. קראו אותו כמו שביל פירורים בחזרה אל הקוד שלכם. שני המספרים בסוף כל שורה הם השורה והעמודה.

## שמות השגיאה שתפגשו הכי הרבה

* `ReferenceError`: השתמשתם בשם שלא קיים (שגיאת כתיב, או משתנה שהוגדר במקום אחר). הודעה: `totalPrice is not defined`.
* `TypeError`: השתמשתם בערך בדרך שהטיפוס שלו לא מאפשר, כמו קריאת מאפיין של `undefined` או קריאה למספר כאילו הוא פונקציה. הודעות: `Cannot read properties of undefined (reading 'name')`, `count is not a function`.
* `RangeError`: מספר נמצא מחוץ למה שמותר, כמו `new Array(-1)` (‏`Invalid array length`) או רקורסיה אינסופית (‏`Maximum call stack size exceeded`).
* `SyntaxError`: הקוד אינו JavaScript תקין (חסרים סוגריים או מרכאות). הוא מתגלה לפני שמשהו רץ, ולכן אי אפשר לתפוס אותו עם `try/catch` באותו קובץ.

הנוסח המדויק של ההודעות משתנה קצת בין דפדפנים, לכן הסתמכו על ה**שם** ועל **הרעיון** של ההודעה.

## תפיסת שגיאה

`try/catch` מאפשר להריץ קוד מסוכן ולהחליט מה קורה אם הוא נכשל:

```js
try {
  console.log("before");
  undefinedFunction();      // throws a ReferenceError
  console.log("never printed");
} catch (error) {
  console.log(error.name);     // prints: ReferenceError
  console.log(error.message);  // prints: undefinedFunction is not defined
}
console.log("the program keeps going");
```

* הקוד שב-`try { }` רץ שורה אחר שורה עד שמשהו זורק שגיאה.
* JavaScript קופצת אל `catch (error) { }` ושמה את אובייקט השגיאה במשתנה `error` (אפשר לקרוא לו `e` או `err`).
* השורות שאחרי השורה שנכשלה בתוך `try` מדולגות.

## איך לקרוא שגיאה ברוגע

1. קראו קודם את ה**שם**: הוא מצמצם מאוד את הבעיה.
2. קראו את ה**הודעה** מילה אחר מילה. שמות של משתנים ושל מאפיינים מופיעים בה.
3. מצאו את שורת ה-stack הראשונה שמצביעה לתוך הקובץ **שלכם**, ועברו לשורה הזאת.
4. שאלו: איזה ערך הוא `undefined` או שגוי כאן, ומאיפה הוא הגיע?

> **שימו לב:**
> * **מתקנים את השורה הלא נכונה.** שורת השגיאה היא המקום שבו התוכנית *שמה לב* לבעיה, לא תמיד המקום שבו היא *התחילה*. אם `user.name` נכשל, ייתכן שהטעות האמיתית היא ש-`user` מעולם לא הוגדר קודם.
> * **מתעלמים מ-`reading '0'`.** ב-`Cannot read properties of undefined (reading '0')` מה שבתוך המרכאות הוא המאפיין שניסיתם לקרוא. זה אומר לכם איזה ביטוי נכשל: `something[0]` כש-`something` הוא undefined.
> * **בלוקי catch ריקים.** `catch (e) {}` מסתיר את השגיאה והופך באגים לבלתי נראים. לפחות הדפיסו את `error.message`.
> * **גודל האותיות משנה.** `firstName` ו-`firstname` הם מאפיינים שונים. שם שגוי נותן `undefined` ולא שגיאה, עד שמשתמשים ב-`undefined` הזה.

> **תורכם:** שני חלקים. (1) השלימו את `tryIt(label, fn)`: קראו ל-`fn()` בתוך `try`; הדפיסו `label: ok` כשזה עובד, או `label: ` ואחריו `error.name` כשנזרקת שגיאה. (2) הפונקציה `initials` קורסת: קראו את השגיאה שהיא גורמת, גלו אילו שמות מאפיינים שגויים ותקנו אותם כך שיודפס `GH`.
